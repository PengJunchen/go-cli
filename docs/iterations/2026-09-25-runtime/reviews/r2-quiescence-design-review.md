## Initial findings

1. **Carry the proof through the actual single prepared invocation.** The proposal adds completion methods to `PreparedInvocation`, but the production path currently hides that object: `MiddlewareToolRegistry.Get` returns a proxy whose `Execute` calls `prepareToolCall` and dispatches internally (`internal/tools/prepared_proxy.go:114-125`); core's `executeSingleToolRegistered` calls the returned `ToolDefinition.Execute` (`internal/core/parallel_tools.go:193-205`). Core therefore cannot read the exact invocation's identity, effects, normalized digests, or completion receipt by adding methods to `PreparedInvocation` alone.

   Specify one durable dispatch path where core calls `ToolCallPreparer.PrepareToolCall` exactly once, derives the intent from that returned invocation, reserves it, then dispatches that same instance. Streaming must use that same instance's `DispatchStreaming`; do not prepare once for the intent and then call the `Get` proxy, which would prepare and approve a different invocation. The non-durable compatibility path may retain proxies, but it must continue to pass through the final dispatch fence. Add executable acceptance cases for one preparation/approval and one executor entry per action, intent identity/digests matching that invocation, and the streaming path using the same prepared call.

   Completion must also be registered with the run owner before the tool worker is released. Today core registers `PendingExecutionError.ExecutionDone()` only for returned errors (`internal/core/parallel_tools.go:170-188`); a queued scheduler can return on `ctx.Done()` while its exact accepted job is still executing (`internal/tools/prepared_registry.go:574-598`). The handoff should require the core path to retain the invocation's completion channel for that action and keep the owner claim pending until it closes. A queue cancellation must not be recorded as a join; only that job's result after its handler returns closes the receipt. If the durable receipt has already been written as `unknown`, later completion may resolve quarantine but must not rewrite the receipt or replay the action.

2. **Bind sink and identities atomically, and define their trusted sources.** The proposed `WithRunCommitBinding` creates a second context key beside `WithRunCommitSink`. This permits a context to pair sink A with binding B, and replacing/masking a child sink can leave an inherited binding behind. Use one private context value and one binding operation containing `{sink, binding}`. Preserve `WithRunCommitSink` compatibility by writing that same key while clearing the binding; passing `nil` must continue to mask inherited durable state. The runtime owner should overwrite/add its own generation in that same value, not accept a caller-selected generation.

   The field sources should be stated precisely: `SessionID` comes from the locked `PreparedSession.View()`; `WorkspaceID` is a versioned stable digest made from the selected workspace root after `Abs`, `Clean`, and successful `EvalSymlinks`; `OwnerGeneration` is generated by the runtime owner. `WorkspaceQuarantineIndex.EnsureWorkspace(ctx, workspaceID)` only validates and initializes the supplied string; it does not canonicalize a path or return a trusted ID (`internal/session/workspace_index.go:165-179`). Canonicalization failure must error rather than fall back to `.` or another workspace. State that this digest is application identity, not an OS sandbox or proof against later workspace rename. Add tests for missing binding blocking before provider/dispatch, a child sink replacement clearing the parent binding, and canonicalization failure refusing durable dispatch.

3. **Keep proof kinds closed and action-scoped; do not create a generic resource inventory.** The three proposed cases map to real source seams—final synchronous prepared pipeline return, one accepted mutation job's completed result, and a locally owned process group whose leader/readers joined and group is absent. Keeping these as a small closed enum is reasonable. Remove or concretely define “validate every listed resource receipt”: the document introduces no receipt-list type, and a generic per-resource manifest would exceed the observed one-job/one-process-group cases. An invocation may issue a proof only for the owned resource set its sealed executor can fully join; wrappers or tools with untracked work, unsupported containment, or unknown effects issue none and remain unresolved. `ExecutionIdentity` remains optional supporting metadata and never supplies the completion proof by itself.

   Recovery acceptance should link the proof row to the complete original action occurrence and the exact prepared invocation snapshot. It must accept a synchronous no-resource executor without an identity, reject identity-only rows, and refuse any proof for a different invocation or registration generation. The implementation should append a proof-bearing execution row only after its completion channel closes; the existing row validator currently requires identity for `local_resources_quiescent` (`internal/session/durable_recovery.go:514-518`), while `ExecutionIdentity.Validate` explicitly checks shape only (`internal/core/execution_identity.go:42-67`).

## Confirmed boundaries

- `ExecutionIdentity` is not evidence of termination, and a row with identity alone must never resolve quarantine.
- Bash may prove only its owned local process-group scope after leader/readers join and positive group absence. A detached/escaped process outside the supported group remains outside the proof; do not claim general process-tree containment.
- Remote Bash, MCP/lost-response work, and unknown/config-controlled executors cannot use local transport or caller return as remote terminal proof. Unknown outcomes stay quarantined and are never retried by this resolution path.
- The child-run section correctly says this handoff does not approve durable delegation and requires durable mode to reject subagent launch until the independent child session/sink and marker semantics receive a later review. Keep this rejection explicit; do not add a parent-marker bypass or delegation fact in this slice.
