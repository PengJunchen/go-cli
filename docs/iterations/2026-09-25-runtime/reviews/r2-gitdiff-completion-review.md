The production Assembly creates `DefaultGitTool`, wraps its `UnifiedDiffGenerator` in `GitDiffGenerator`, and configures the default file-mutation queue (`internal/cli/assemble.go:839-911,1147-1155`). `DefaultGitTool.Diff` uses the managed local-command path for both `rev-parse` and `git diff`; its diff args disable external diff/textconv and its runner retains leader, pipe-reader, and process-group evidence. A normally joined ordinary Git failure can therefore use the existing unified fallback. `GitDiffGenerator` checks for cancellation and typed pending/unknown/containment errors before fallback. `WriteTool` and `EditFileTool` surface these unresolved errors before backup and file mutation.

The trusted registry grants `CompletionQueuedJobJoined` only to concrete Write/Edit definitions configured with the exact `GitDiffGenerator` → `DefaultGitTool` → `UnifiedDiffGenerator` pipeline, and only on Darwin/Linux. Other injected diff or Git implementations do not receive this proof. Prepared mutation dispatch uses the captured `DefaultFileMutationQueue`; it attaches the job signal on enqueue. The worker publishes the pending error to the caller, then waits on the same nested `PendingExecutionError.ExecutionDone()` channel before closing the job signal. Nil nested channels and containment failures invalidate the queue proof. For forced pipe close, local reader join does not become containment proof: the returned outcome remains unknown; the outer queue signal can close after the local job exits while `Proof()` stays empty. No fabricated permanently-open process channel is used on this GitDiff path.

`DefaultFileMutationQueue` applies the same nested-`ExecutionDone` wait on its legacy non-prepared `Enqueue` path. This preserves same-path FIFO while a returned pending resource remains active. It also means synchronous `Close()` waits for `workerWG` and can block until that nested channel closes; `Close` has no caller context. This is a truthful join boundary, but lifecycle owners must call it in a way that can report pending to their waiters rather than bypassing the worker. The `gitDiffCombinedOutput` buffer is unbounded; the previous `CombinedOutput` path was also unbounded, so this is a follow-up limit rather than a regression in this slice.

## Limits

Unsupported OS behavior and full Assembly/R2 durable recovery remain outside this review.
