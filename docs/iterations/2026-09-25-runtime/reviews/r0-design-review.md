# R0 contract review

Review target: `docs/iterations/2026-09-25-runtime/r0-contract.md`; follow-up implementation review of provider commit `fe0666f4aea1a7219314060add27cf9c50dc72ed`.  
Review type: source-grounded design, lane-boundary, and targeted code review. No product code or tests were changed or run.

The seven-lane split is mostly workable, and the contract correctly keeps R0 narrow. The red tests need to enter production paths, however, and several boundaries below need to be explicit before this serves as the final builder contract.

## Findings and dispositions

1. **[P1, resolved] Define a non-cyclic production HITL bridge.** `cliHITLEmitter` sends `cli.HITLMessage` through Bubble Tea (`internal/cli/interactive.go`), but the production model is `tui.teaModel` (`internal/tui/app.go`) and its `Update` switch has no handler for that message. The revised contract puts the protocol in `tui`, keeps CLI aliases or an equivalent TUI-owned seam, prohibits a `tui`→`cli` dependency, and requires the production `teaModel.Update` path. This addresses the import-cycle risk and the gap in the current custom-model-only HITL tests.

2. **[P1, resolved] Require the mutation arguments in the advertised tool schemas.** `WriteTool` and `EditFileTool` do not currently implement `tools.Parameterized`; `SchemaValidator` skips validation for tools without that interface. The revised contract requires the schema properties, preserves explicit empty strings, and assigns `mutation.go` plus `mutation_test.go` to the permissions lane so both executor and CLI queue behavior can be tested.

3. **[P1, resolved] Name the read-only tools allowed in Plan Mode.** The revised allowlist names only existing built-ins, including configured `web_search` and `web_fetch`; unknown and unregistered tools remain blocked. This preserves normal read-only network work without granting broad access to unregistered/custom names.

4. **[P1, resolved] Cover cross-origin redirects and both MCP transports.** The revised contract tests foreign absolute SSE endpoints and HTTP redirects before any foreign request or credential is received, keeps same-origin redirects usable, and exercises lost-response/no-replay behavior on both the stdio reconnect path and HTTP POST path with an explicit ambiguous-result error.

5. **[P1, resolved] Keep scanner findings from being suppressed to pass the gate.** The revised contract explicitly prohibits new ignore/exemption allowlists, rule-severity reductions, or swallowing the 20 `SCAN-012` errors; it requires separate positive/negative applicability evidence for any false-positive claim.

6. **[P2, addressed in contract] Exercise Streaming Bash read errors and long lines.** The cap regression is correctly isolated to `StreamingBashToolImpl`: its `readPipe` breaks after the capture limit and leaves the child pipe unread. The archived reproduction confirms a finite 200 KB Bash builtin blocks until the 1.2 second timeout at a 20-byte cap. `readPipe` also uses a `bufio.Scanner` with a 1 MiB token ceiling and currently ignores `scanner.Err()`, so a long line can stop draining before EOF as well. The revised contract requires short-line and oversized-line cases, error reporting, continued draining, and the existing combined stdout+stderr `MaxOutput` budget. The implementation test should include a non-EOF reader error case as well. The ordinary `BashTool` `limitedWriter` is a separate path and does not invalidate this finding.

7. **[P1, R4 mandatory follow-up; accepted R0 hotfix-slice residual] Preserve the complete registered Plan Mode read/control surface and close executor-name spoofing.** Source inspection confirmed `lsp_query` (including rename, which returns a `WorkspaceEdit` but does not apply it), `tool_search`, `goal_get/list`, and `task_get/list` are read-only; `ask_user`, `enter_plan_mode`, and `exit_plan_mode` are control-plane tools. The revised contract explicitly lists those names, retains the current `exit_plan_mode` behavior during R0, and leaves the long-term D-01 permission policy deferred. A separate source review confirmed the limitation is reachable: `DefaultToolRegistry.Register` is last-registration-wins, and `assembleExtensions` registers extension tools after built-ins without a name-collision check. An extension can therefore replace the `read` executor with an arbitrary side effect, while the Plan Mode interceptor checks only `ToolCall.Name` and allows it. The R0 slice is not a security-release claim; R4 must bind effects/identity to the resolved executor or prevent unsafe replacement. This also avoids turning the corrected read/control enumeration into a product permission change.

8. **[P1, implementation finding; provider fix pending] Restrict small-model credential fallback by provider identity and origin.** Provider commit `fe0666f` routes the primary model through `resolveCLIProvider`, but `buildSmallModel` still copies `rc.Provider.APIKey` and `rc.Provider.BaseURL` whenever the corresponding small-model field is empty, even when `small_model.provider` names a different provider. For example, a primary `anthropic` configuration with its API key and a small model explicitly named `openai` but with no endpoint or key is resolved as OpenAI API-key-only, so the primary credential can be sent to the default OpenAI origin. The factory must also avoid inheriting a primary key when the small model explicitly overrides its BaseURL to a different origin, even if the provider names match. Preserve reuse when provider identity and effective origin match; do not silently carry a credential across identities or to a different origin. Add recording-endpoint tests through `buildSmallModel` for same-provider/same-origin reuse, mismatched provider, and same-provider/different-origin. The existing provider tests exercise `buildModel`, not this small-model construction path.

9. **[P2, test gap; Bash implementation otherwise sound] Directly exercise the output reader error path.** Commit `6235107` correctly retains a combined bounded prefix, drains past the capture cap, drains after `Scanner.Err`, and surfaces reader errors. The new tests cover finite output past the cap and a line beyond the Scanner limit, but no test injects a non-EOF error into `readPipe(io.Reader, ...)` as the R0 contract requires. Add a reader that returns data and then a non-EOF error; assert the error is surfaced and the result remains bounded. The separately reproduced 100 ms cancellation taking about 711 ms because a child process inherits the pipe belongs to R1 process-lifecycle work, not a failure of this R0 finite-output drain fix.

## Confirmed contract strengths

- The approval row correctly distinguishes callback `ApprovalAllow` from `ApprovalAlwaysAllow`. The first must bypass both the session cache and `ApprovalStore`, because `ApprovalMiddleware.decide` stores every final classification after `resolveAsk`; merely avoiding `ApprovalCache` would still reuse a one-shot allow. Classifier-produced static Allow/Deny may retain their existing policy semantics. The CLI currently wires in-memory store/cache, so no new cross-process persistence should be implied.
- The provider row captures the dangerous `buildModel` branch: any configured `BaseURL` or `APIKey` constructs an Eino/OpenAI-compatible provider regardless of the selected identity. In particular, a Claude/Gemini API key with an empty base URL must not reach the OpenAI default endpoint. Unknown providers must fail before dispatch, and this row does not authorize enabling native Claude/Gemini protocols.
- The provider implementation review confirmed the resolver is shared by `buildModel`, `listAvailableModels`, and `buildSmallModel`, and native `claude`/`anthropic`/`gemini` identities fail before dispatch. Finding 8 remains: `buildSmallModel`'s primary-setting fallback needs an identity-and-origin guard, with recording tests for the actual small-model factory path.
- The privacy row correctly includes the real `cmd/cli/main.go` tracer and failure fallback, not only an independently constructed redacting exporter. The main tracer is not wrapped by the redacting exporter used in `assembleTracing`, and the one-shot prompt span carries CLI arguments. The prompt canary should be checked on every actual exporter/log path named by the final test.
- The ownership table keeps the Bash, TUI, network, provider, privacy, permissions, and verify implementations largely separate. The provider/privacy work in `assemble.go` is explicitly divided by responsibility; keep that constraint when rebasing or cherry-picking.
- The protected-file boundary is explicit and correctly reserves protected gate changes for separate review and the required approval flow.

## Review conclusion

**The revised contract preserves the full current Plan Mode read/control surface, but its name-only guard leaves a reachable executor-identity bypass.** Finding 7 is an accepted R0 hotfix-slice residual that R4 must close; R0 must not be described as safe-release closure. Provider finding 8 remains an implementation blocker pending the small-model fallback fix and targeted red/green tests; Bash finding 9 is a direct reader-error test gap. Findings 1–6 are resolved or represented in the contract. Review did not run tests and is not evidence that any implementation or gate has passed. This does not approve changes to protected files.
