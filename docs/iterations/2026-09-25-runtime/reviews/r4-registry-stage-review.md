# R4 registry metadata and stages seam review

Reviewed snapshot: `f9329b7794eb2aeb59116af037208b22663fd9d4` (parent `a78775a655b8c7717cb723506089b031ef0a98f8`). Scope is the five-file delta in `internal/tools/{deferred.go,middleware_registry.go,registry.go,registry_test.go,trusted_registry.go}`.

Decision: **accept this bounded metadata/stages seam**. I found no blocking TOCTOU or fence-splitting issue in the current Default → Deferred adapter → nested Middleware path. This does not complete R4: `PrepareToolCall`, protected `Get`/`List` proxies, and actual prepared dispatch are still under construction and remain separate gates.

## Review findings

- **The built-in registry stack shares one fence and pipeline state.** `DefaultToolRegistry` owns one fence and one prepared pipeline state. `DeferredToolRegistryAdapter` and each `MiddlewareToolRegistry` forward those same objects from their inner provider rather than allocating local fences/state. The nested-wrapper regression checks pointer identity and sets policy/stages through the outer wrapper, then reads the resulting snapshot from the base registry (`trusted_registry.go:140-151`; `deferred.go:241-276`; `middleware_registry.go:52-108`; `registry_test.go:227-296`).
- **Ordinary registration cannot mint trusted effects.** `Register` always calls the private registration boundary with `unknownTrustedEffects()`. Only the explicit `TrustedControlRegistrar` path labels the source `builtin_control` and grants the fixed `EffectControl`; there is no public generic effect-set registration or effect-upgrade setter. The test registers the same name through both paths and verifies ordinary registration stays `unknown` while the explicit path records `control` (`registry.go:52-54`; `trusted_registry.go:22-35,153-157`; `registry_test.go:227-256`). The registrar is a deliberate capability for first-party assembly and must not be handed to project extensions.
- **Identity, schema, definition, pipeline, and generation are captured consistently against registration and stage writers.** Registration publishes the tool map and metadata under `DispatchFence.Publish(Registry, ...)`; per-name generation is advanced in that same publication. `toolRegistrationSnapshot` uses the fence read lock while taking the registry and pipeline snapshots, so a registration or stage/policy publication cannot interleave and pair a new definition with an old generation (or vice versa). Replacement tests verify the captured definition, schema snapshot, per-name generation, global registry generation, and fresh executor fingerprint (`trusted_registry.go:153-239`; `registry_test.go:194-225`). The snapshot intentionally pins the original definition instance; this relies on the R4 contract that definitions/configuration remain immutable after registration. Raw `Get`/`List` exposure is still present and is not claimed closed by this metadata-only slice; the later proxy work must keep those returned values from bypassing prepared dispatch.
- **Policy and stages changes invalidate through the intended domains without an effect-upgrade input.** `SetPreparedToolPolicy`, including clearing it with `nil`, publishes through the shared fence's Approval domain. `SetPreparedToolStages` publishes through Registry and copies caller-owned slices before storing them. `PreparedToolStages` contains preparers, execution wrappers, and a mutation queue, but no effect or identity field; the policy decision can allow/deny and return generations but cannot replace trusted metadata. The tests assert the correct domain increments and that the outer wrapper's stored stages are visible at the base (`middleware_registry.go:73-101`; `trusted_registry.go:44-75,98-132,529-545`; `registry_test.go:258-299`). These checks establish version changes, not end-to-end stale invocation rejection; that requires the not-yet-implemented preparer/dispatch path.

The definition pointer remains available to the original registering caller and through current legacy `Get`/`List` methods. This slice records a schema/effect/identity snapshot but cannot freeze arbitrary Go object internals. Treat immutable-after-register definitions as a required registration invariant; later protected-proxy and prepared-call review must verify replacement goes through the fenced registry path and does not re-discover or mutate the executor after preparation.
