# R7 CLI invocation owner for pending Assembly close

Status: accepted implementation contract for the bounded R7 invocation-owner slice. It carries existing Assembly completion into the command invocation owner and retains the invocation log through the existing AsyncExporter owner; it does not revise Assembly shutdown order, tracing exporter semantics, or R7 acceptance.

## Problem and source evidence

At `17ab7b76ef0b7636abff1e5a055de7acf6f6bb31`, Assembly already has a single close owner. `AgentAssembly.Close(ctx)` delegates to it, and a waiter can receive `ErrAssemblyClosePending` while the owner keeps running (`internal/cli/assemble.go:257-268`, `internal/cli/assembly_lifecycle.go:58-151,316-322`). The Assembly owner closes shared run admission before starting its resource sequence, then signals its private `done` only after `closeResources` completes (`assembly_lifecycle.go:58-195,330-338`). A callback that ignores its context can therefore keep this owner pending; an unknown-completion result also deliberately leaves `done` open.

Command wrappers preserve an error chain: prompt, REPL, and serve join the result of `closeAssemblyForCommand` into their command result (`internal/cli/prompt.go:171`, `repl_session.go:136`, `serve_cmd.go:259`), and `ExecutionError.Unwrap` retains that chain (`internal/cli/cli.go:56-73`). But `cmd/cli.runCLI` maps the error to an `int` (`main.go:186-200`), so `run` cannot observe the Assembly owner's completion channel. It then unconditionally ends the root span, calls `tracer.Flush`, shuts down the exporter, and returns (`main.go:97-118`); a deferred `logFile.Close` runs on return (`main.go:64`).

That order is unsafe while Assembly close is pending. `Tracer.Flush` is currently a compatibility no-op (`internal/tracing/span.go:116`). Span `End` exports synchronously (`span.go:265-282`), while `AsyncExporter.ExportSpan` rejects and counts spans after shutdown admission closes (`internal/tracing/async.go:146-169`). A late Assembly producer can therefore emit a span or log after the root exporter or invocation log file has been closed. The R7 shutdown handoff already requires Assembly completion before ending the root span and shutting the invocation-owned exporter. This design carries that actual completion fact across the `runCLI` boundary.

The prior Assembly-close review also records that its reviewed commit was not accepted overall and that its probes did not prove every producer path. This proposal makes no claim that the historical review accepted full Assembly shutdown; it relies only on the current source's single close owner and requires the exact close `done` signal before invocation finalization. The design follows the dependency order and non-cooperative callback boundary in `r7-assembly-close-handoff.md` and the root-exporter contract in `r7-tracing-shutdown-handoff.md`.

## Narrow ownership change

Keep the Assembly's existing `done` as the only completion source. In `internal/cli/assembly_lifecycle.go`, have `pending()` return a private `assemblyClosePendingError` carrying `o.done`:

```go
type assemblyClosePendingError struct {
    reason string
    cause  error
    done   <-chan struct{}
}

func (e *assemblyClosePendingError) Done() <-chan struct{} { return e.done }
func (e *assemblyClosePendingError) Unwrap() error {
    return errors.Join(ErrAssemblyClosePending, e.cause)
}
```

Its `Error()` remains a stable, safe pending classification. The concrete error stays private; it does not expose the close owner or grant a new close/cancel capability. The read-only `Done()` channel is exactly `o.done`, stable across waiters. The sentinel remains discoverable with `errors.Is`. Terminal success and ordinary terminal cleanup errors keep their existing return behavior. Do not add an Assembly registry, generic producer interface, or second done channel.

Add a narrow extractor in `internal/cli`, for example `AssemblyCloseCompletions(err error) ([]<-chan struct{}, bool)`. It walks the wrapped/joined error tree and collects channels only from the private `*assemblyClosePendingError` concrete type. It ignores unrelated errors that happen to implement `Done()`, including an earlier `errors.Join` child with an already-closed channel. `ok` is true only when at least one actual Assembly pending error was found and every such error has a non-nil `o.done`; no match or an invalid channel is unknown completion. Deduplicate identical channels. Do not use `errors.As` to an arbitrary `interface{ Done() <-chan struct{} }` in `cmd/cli`.

Change `cmd/cli.runCLI` to return a small result containing its exit code and original error, instead of only `int`. It must keep the wrapped error intact. For the Assembly-pending case, do not print `err.Error()` or nested callback text; let `run` emit one stable status after it knows whether its bounded wait completed. `run` checks the Assembly pending sentinel, then calls `cli.AssemblyCloseCompletions(err)`. If there is no valid concrete Assembly completion channel, take the safe pending path and do not finalize. If there are multiple actual Assembly pending errors in a joined chain, the invocation owner waits for all returned channels; it must not pick the first `Done`-shaped error. Other command errors keep their current exit-code mapping.

Add one private invocation finalizer owner in `cmd/cli/main.go`. It owns the root span, tracer/exporter, invocation log writer, previous global logger, stderr, and an aggregate barrier for every actual Assembly `Done` channel. It exposes `initialDone` for the first bounded exporter-finalizer result and `Done()` for completion of all required owners and log cleanup; a `sync.Once` starts its one lifecycle. It waits for all Assembly channels before ending the root span. After the root span ends, it runs the existing bounded exporter finalizer. If that reporter says `OwnerFinished == false`, the owner keeps the logger and file, then calls `ShutdownWithReport(context.Background())` again on that same reporter. Only a positive `OwnerFinished` result permits log close and logger restore. When Assembly completion is already available, the caller joins this finalization inline, preserving synchronous ordinary completion.

Transfer logger/file cleanup ownership to this object on the pending path. Guard the current `run` defers with an ownership flag: after transfer, `run` must not restore `slog.Default` or close the file. Keep the invocation logger installed while the owner is waiting, so late producer logs continue to the invocation's log file instead of being routed to a previous logger. When finalization eventually runs, close the file, then restore the previous logger only if `slog.Default() == invocationLogger`; an old owner must not overwrite a newer logger. The CLI remains a single-invocation process: this identity check protects against clobbering a newer default but does not make nested or concurrent `run` calls safe, because a newer run may have captured an older invocation logger as its own previous logger. The owner must not use the canceled signal context as its lifetime context.

## Bounded wait and actual process behavior

Use an unexported `runWithInvocationWaitBudget(..., producerWaitBudget time.Duration)` seam; production `run` supplies a fixed 20-second budget, while tests use short durations. This budget applies only to waiting for every actual Assembly completion channel. Do not add an environment variable or config setting. If a producer channel remains open, write only a stable diagnostic such as `error: invocation shutdown remains pending; trace and log finalization was deferred`, return nonzero, and do not end the root span, shut down the exporter, close the log, or restore the invocation logger. The invocation owner remains attached to the actual producer channels while the process remains alive. Recheck all channels when the timer fires.

If every producer channel closes within budget, the owner ends the root span and performs the existing bounded exporter finalizer. The caller joins the first attempt, so the maximum cooperative wait is producer budget plus the existing exporter wait budget. If the exporter attempt reports pending, return nonzero after that bounded attempt while the owner rejoins the same reporter with `context.Background()`. `initialDone` records the first bounded result; the owner's full `Done()` stays open, and its logger/file remain open until `OwnerFinished` is true. This second wait does not extend the process caller's bound.

The producer wait budget limits only this invocation waiter. It must not cancel Assembly close, mark any producer `done` closed, reopen run admission, or run root/exporter/log cleanup while a producer remains. Recheck all producer channels after the timer wins to avoid reporting pending when completion has already become observable. A context-cancellation test must prove that the Assembly close waiter can return the typed pending error while the shared close owner stays live; the invocation owner then observes those same channels under its own fixed wait budget.

The actual executable's `main` calls `os.Exit(run(...))`. If `run` returns while Assembly `Done` is still open, `os.Exit` terminates all goroutines, including the retained invocation owner. There is no in-process design that can both return from `main` promptly and guarantee a non-cooperative callback later completes its trace/log finalization. Therefore the real CLI policy is: bounded wait, safe pending diagnostic, nonzero exit, no application-level root/exporter/log close, and no claim that the producer became quiescent. The operating system will reclaim process resources at exit, and pending trace/log data may be incomplete. Do not silently wait forever and do not describe a background goroutine as surviving `os.Exit`. A caller that embeds `run` without exiting can observe the owner's `Done`; tests use that to prove late completion ordering.

## Required ordering and invariants

1. Assembly's existing close owner closes admission synchronously, then waits for real in-flight work and performs its established serial resource close. An invocation waiter timeout never reopens admission or converts timeout into completion.
2. `assemblyClosePendingError.Done()` is the Assembly owner's actual `done`, not a timer, context, run-slot idle approximation, or proxy goroutine exit. `AssemblyCloseCompletions` extracts only this private type and returns every actual pending Assembly channel in the wrapped/joined error tree. Each closes only on the existing `finish` path after `closeResources` returns. If an owner encounters unknown completion and leaves its `done` open, invocation finalization waits for it.
3. Invocation close order is: observe every Assembly channel → set final command exit attributes/status → end root span → run `tracer.Flush` (currently a no-op) → call the bounded async exporter shutdown/finalizer → if pending, rejoin that reporter until `OwnerFinished` → close the invocation log file → restore the previous global logger. No root end or exporter shutdown occurs while an Assembly channel is open; no log close occurs while an Assembly producer or exporter callback is unconfirmed.
4. The AsyncExporter remains the trace queue owner. Its existing close owner drains accepted spans, waits for the active sink callback, then shuts down the sink. This proposal adds no exporter queue, tracing completion API, or flush abstraction. Exporter pending is reported by the existing finalizer; it is a nonzero result and is not evidence that a callback stopped. The invocation owner retains the log and rejoins the same reporter instead of treating a waiter timeout as callback completion.
5. A late Assembly callback may emit child spans and `slog` records while `Done` is open. They retain the invocation tracer/logger. Once `Done` closes, no Assembly-owned producer is allowed to emit; root end is then the final span submission before exporter shutdown.
6. The boundary covers the production CLI's Assembly-owned path. It cannot cover code that retains and uses a bare model/tracer/logger outside Assembly ownership, a producer with no completion contract, or an in-process callback that never returns. Those cases remain pending; no timeout can prove them stopped.

## Executable acceptance tests

Write the focused regressions before changing the lifecycle code. Do not run broad verification as part of this design slice.

1. In `internal/cli`, add a gated close-owner regression. Start a real Assembly close with a callback held on a channel; call `Close` with an already-canceled or short waiter context. Assert `errors.Is(err, ErrAssemblyClosePending)`, `errors.As` to the private pending capability, `Done()` is the same channel across a second waiter and remains open, and the close admission fence stays closed. A new run claim must fail closed while the callback is held. Release it and assert that the same channel closes only after the serial resource owner finishes; repeated close does not invoke the callback twice.
2. In `internal/cli`, add an adversarial extractor regression with `errors.Join(fakeDoneError{Done: alreadyClosed}, realAssemblyPending)`. Assert `AssemblyCloseCompletions` returns the actual Assembly owner's open `o.done`, ignores the earlier unrelated channel, and does not report completion until the actual close owner finishes. Include two actual private pending errors in a joined tree and verify both channels are returned (deduplicated if identical), with a nil actual `done` causing `ok == false`.
3. In `cmd/cli`, exercise the invocation owner with an open producer barrier. Use a short test wait budget. Before releasing the producer, assert bounded nonzero return, a stable pending diagnostic, open owner `Done`, open log file, no root `End`, and no exporter shutdown. After release, assert the owner finishes and the late child span/log precede root end, exporter shutdown, log close, and guarded logger restore. Also verify a barrier with two actual Assembly channels remains open until both close.
4. Use a real `tracing.AsyncExporter` with a gated sink callback. In one case, have a late Assembly producer end a child span before closing its producer channel; verify the child and root are delivered, `RejectedAfterClose == 0`, and sink shutdown follows producer completion and root export. In a separate case, let the producer join while the sink callback remains blocked. Assert `initialDone` closes after the bounded reporter result, full owner `Done` remains open, the callback can still write through the open invocation log, and only callback release plus `OwnerFinished` permits log close and logger restore.
5. Exercise the main-package wait boundary with a forced pending producer barrier. Assert return code 1, the stable pending diagnostic, no root/exporter application finalization, and a still-installed invocation logger. This proves the caller reports incomplete shutdown; it does not claim a goroutine survives the subsequent `os.Exit`.
6. Keep the existing `TestTracingFinalizerWaitsDespiteCanceledSignalContext`, Assembly owner tests, and `TestAssemblyUsesInvocationTracerWithoutOwningExporter` as neighboring regression gates. The new tests add the missing cross-boundary ordering; they do not replace exporter accounting tests or claim full R7 lifecycle acceptance.

## Trace and log containment evidence

The containment assertion is about timing, not guaranteed durable delivery. `localSpan.End` submits synchronously to the configured `TraceExporter`; the CLI runtime wraps its built-in JSONL/stdout sink in `AsyncExporter`. Closing that exporter before Assembly `Done` changes subsequent submissions into counted `RejectedAfterClose` failures. The barrier test therefore proves the necessary ordering by observing zero post-close rejections and delivery of the gated child span plus root span. Existing AsyncExporter report fields still distinguish accepted/delivered/pending and do not claim durable storage merely because the sink callback returned.

The invocation log file is a separate resource from the JSONL trace file. Keep it installed through every Assembly completion channel because Assembly producers and span-export error reporting may use `slog`. If the bounded exporter call reports pending, keep the file open through the callback's actual completion too; the callback itself may call `slog` after the initial waiter returns. Only `OwnerFinished` permits application log close. A late write after application log close is forbidden by the barrier test. If Assembly or exporter completion is not observed before `os.Exit`, the process reports pending and skips application-level root/exporter/log finalization.

## Non-cooperative producer boundary

If an extension or other in-process producer ignores cancellation and blocks, `AgentAssembly.Close` can return a typed pending error to its waiter while the Assembly owner and its channel remain open. The invocation owner keeps root span, exporter, logger, and file alive while the process remains alive. On eventual callback return, Assembly close may continue once and close its channel; invocation finalization then runs exactly once. An AsyncExporter callback can independently remain pending after all Assembly producers joined; the invocation owner keeps the log open and rejoins the same close owner. If either callback never returns, its real completion never arrives and no close order can complete. A caller deadline is not permission to advance teardown. In the actual CLI, bounded waits return nonzero and `main` exits; process termination stops any remaining callback and forfeits final delivery, but is reported as pending rather than quiescent.

This is deliberately a single invocation owner around an existing Assembly owner. It adds no general goroutine registry, no producer counter, no new admission gate, no retry of Assembly cleanup, and no tracing flush framework.
