# R4 shipped-extra built-in schemas implementation handoff

Contract census snapshot: `575fc5f746f702256a9b5d46150b955951a71066` on `codex/runtime-stabilization`. The default-schema change `fa7c969` is an ancestor of that snapshot. Implementation baseline: isolated branch `codex/r4-extra-tool-schemas-impl`, based on `468aa6cc3cc598bd1253219cff723e5693cd106f` (which includes the accepted WebSearch source chain and review). This document records the implemented schema slice and its evidence; it does not claim fresh review or R4 acceptance.

The implementation adds `Parameters()` to the 15 fixed shipped extras that lacked it at the census snapshot. `git_pr_create` remains unchanged; the fixed extra set now has 16 schema-bearing tools. No executor behavior, prepared validator, approval policy, or native Claude provider code is changed.

## Scope and assembly census

`AssembleAgent` builds the real production registry in this order: default tools, extensions, prepared approval/resilience wrappers, SubAgent, extra first-party tools, then the LoopAgent (`internal/cli/assemble.go:336-376`). `assembleTools` registers the seven default file/shell tools and 17 Git tools, then configured custom, MCP, LSP, remote Bash, and skill tools (`internal/cli/assemble.go:832-966`; `internal/tools/builtins.go:82-184`). All seven default tools expose schemas at this snapshot: Read, Bash, Grep, Find, and Ls were added in `fa7c969`; Write and Edit already had them. Their field matrix and validation findings are recorded in [the accepted default schema review](reviews/r4-default-tool-schemas-review.md). The 17 Git tools also implement `Parameterized`; `git_pr_create` is registered from `assembleExtraTools` and already has a schema.

The fixed extra set is 16 concrete definitions: six ordinary registrations (`todo_write`, `task_create`, `task_update`, `goal_create`, `goal_update`, `git_pr_create`), eight trusted controls (`task_get`, `task_list`, `goal_list`, `goal_get`, `ask_user`, `enter_plan_mode`, `exit_plan_mode`, `tool_search`), and two trusted network reads (`web_fetch`, `web_search`) (`internal/cli/assemble.go:1323-1389`). At the census snapshot, only `git_pr_create` implemented `tools.Parameterized`; the other 15 did not. Their executor contracts are inventoried below. Configured custom/MCP/LSP/remote/skill and extension registrations are conditional or externally defined, so they are not substitutes for schemas on these fixed shipped tools and are outside this bounded gap.

## Executor contracts at the initial census snapshot

“Required” below means the concrete executor's existing precondition. It does not imply JSON Schema can encode non-empty strings: the prepared validator supports presence, types, enum, numeric minimum/maximum, arrays, nested objects, and `additionalProperties`, but not `minLength`, conditional schemas, or `default` (`internal/tools/prepared_registry.go:198-340,388-470`). Executor defaults remain runtime behavior; JSON Schema `default` would not apply a value.

At the census snapshot these `Execute` methods ignored unrecognized keys unless noted. The implemented closed object schemas reject those keys on the prepared model-call path before policy, while a direct raw-executor call may still ignore them. Root accepted this narrower prepared/model contract; tests preserve and record the boundary.

`git_pr_create` is the one fixed extra with an existing schema. It declares required string `title`, `base`, `head`, optional string `body`, and `additionalProperties: false` (`internal/tools/git_pr_create.go:35-57`). Its executor rejects blank required values after trimming, uses a string body if present, and otherwise ignores unknown fields (`internal/tools/git_pr_create.go:60-104`). Do not add them based on the tool name or outside descriptions.

## Implemented schema shape

Each missing tool now implements `Parameters() any` on its existing concrete type; no new `ToolDefinition` method or interface redesign was needed. Every schema is a closed root object using only keywords understood by the prepared validator. Required fields follow executor preconditions; no `minLength`, URL format, schema defaults, task-status enum, or priority enum was invented. `task_list` and `goal_list` use empty closed objects.

Implemented groups:

1. **Network reads and search control:** `web_search`, `web_fetch`, and `tool_search` expose string fields. `tool_search.category` uses the source categories plus `""` as an explicit no-filter sentinel; this preserves the executor's behavior when a caller supplies an empty category while still documenting accepted input. WebSearch provider/auth/redirect behavior comes from the accepted independent WebSearch chain; this schema change does not alter it. `web_fetch` URL safety remains runtime validation.
2. **Task and goal stores:** `task_create/update/get/list`, `goal_create/update/get/list` use the exact string fields consumed by source. Task status and priority remain unconstrained strings. `goal_update.status` advertises the six canonical lowercase values; raw execution continues accepting case and surrounding-space aliases.
3. **Action and UI controls:** `todo_write` has required `action` enum and optional `id`, `content`, `status`, and `priority` union fields. `ask_user.options` is an array of strings. The plan-mode tools each expose one optional string, with execution and policy semantics unchanged.
4. **Assembly/Loop handoff:** tests check all 16 fixed extras (including existing `git_pr_create`) through actual Assembly protected registry definitions and a real Loop model-definition capture. `tool_search` retains `TopToolsProvider` and ranked subset behavior.

## Dispatch path and accepted parity boundary

The handoff through dispatch already exists. `assembleApproval` wraps the deferred registry in `MiddlewareToolRegistry` and installs a shared prepared policy (`internal/cli/assemble.go:1064-1165`); `assembleLoopAgent` gives that same `s.tr` to Loop and enables tool filtering at threshold 30 (`internal/cli/assemble.go:1393-1483`). Registration snapshots a schema when the definition is registered; `newProtectedToolDefinition` reconstructs the `Parameterized` capability from that immutable snapshot (`internal/tools/trusted_registry.go:352-380`, `internal/tools/prepared_proxy.go:21-79`). `MiddlewareToolRegistry.Get/List` return those protected proxies (`internal/tools/middleware_registry.go:166-199`). Loop's `buildToolDefinitions` calls `List`, copies `Parameters()` into `llm.ToolDefinition.Parameters`, and caches by registry version (`internal/core/loop.go:295-339`); `defsToLLMTools` does the same for filtered definitions (`internal/core/loop.go:1511-1523`). At invocation, `prepareToolCall` validates the captured schema before the prepared policy is asked (`internal/tools/prepared_registry.go:46-133`). No second schema channel or proxy redesign is indicated.

The accepted design decision is that the public model/prepared contract may be narrower than direct calls to `Execute`. Several raw executors ignore unknown keys or wrong-typed optional values; closed typed schemas reject them in the prepared path. Required-string blankness cannot be expressed by this validator, so a present-but-blank value passes schema validation and is rejected by the existing executor after policy. The implementation leaves that order and raw behavior unchanged and tests it explicitly. Exact bidirectional parity would require separate executor behavior changes and is out of scope.

`todo_write` has action-dependent requirements (`content` for `add`, `id` plus `status` for `update`, `id` for `remove`) that its current validator vocabulary cannot encode. The implemented schema requires only `action` and declares all action fields optional; the executor remains the conditional validator. Making prepared schema rejection match those conditional failures before policy would require a separately reviewed expansion of validator vocabulary (for example `oneOf` or `if/then`) and is outside this slice.

`goal_update.status` documents canonical lower-case enum values while direct execution keeps its case/space aliases. `tool_search.category` declares canonical lower-case categories and the empty no-filter sentinel; direct execution continues trimming and lowercasing aliases. The accepted default-schema review documents the same model-contract boundary for Find/Ls enums. `ask_user.options` is `array<string>`; raw execution still drops non-string members, while prepared calls reject them before policy. These differences are tests and documented contract boundaries, not executor changes.

### Separate native Anthropic provider-contract gap

The source audit found `encodeClaudeRequest` does not serialize `GenerationOptions.Tools`, and its `claudeRequest` has no tools field. Native Claude conversion also does not preserve assistant tool-call / `tool_result` history, and non-streaming native tool-use response handling is absent. The new Claude decoder test covers streamed inbound `tool_use` only. Consequently, full Anthropic schema request conversion and tool-call round-trip acceptance remain open as a separate R3 provider-contract P1; do not interpret this schema slice or its mixed-provider test as closing that gap. `internal/llm/native.go` was intentionally not modified here. Sampling support for Claude `temperature`/`stop` is also a separate provider capability question, not part of this slice.

This scoped schema result does not close R4. Required broader phase evidence remains the contract and gates listed in `r4-remaining-source-contract.md`, plus fresh independent review of this implementation.
