# R7 Runtime Capability Disposition

**Snapshot:** integrated source baseline `2beba957225ebbe3ccfe94fd133934fb601ad8df` (R6 production commit `84e9281` is an ancestor). This is a source and wiring audit, not an implementation approval or phase closure. Test names below are evidence locations only; this audit did not execute tests.

The table separates APIs that exist from behavior reachable through the default CLI/Assembly. A library test or constructor alone does not establish runtime wiring or protocol support.

## Disposition labels

- **Current-active**: connected to the default CLI/Assembly on a compatible configuration and build.
- **Metadata-only**: descriptive or schema metadata; it does not grant permissions or wire a runtime capability.
- **Unwired**: an API/helper or lower-level primitive exists, but no production Assembly/runtime path delivers the capability described in that row at this baseline.
- **Fail-closed**: the runtime deliberately rejects the requested transport or exporter before using it.
- **Unavailable-environment**: the path requires a compatible build tag, platform, or toolchain; otherwise the build stub rejects it or the test cannot exercise it.
- **Proposed-decision**: a design/handoff candidate only; source does not implement it and no R7 decision or phase closure is implied.

| Verified project `.so` capture size | [`project_sources.go`](../../../internal/config/project_sources.go#L25) keeps a 16 MiB aggregate source ceiling. | Changed native plugin binary reload | R6 content-addresses verified bytes and tests reuse of the same materialization path for an identical-byte regrant ([`TestProjectExtensionNativeTrustRegrantUsesStableModulePath`](../../../internal/cli/extension_project_native_test.go#L28)). The Go [`plugin` package contract](https://pkg.go.dev/plugin) says a plugin initializes once, cannot be closed, and `plugin.Open` of an already-open path returns the cached module. Changed bytes at the same path therefore cannot replace the loaded module. A different content path may load another module, but does not unload or replace the existing one; default Assembly has no changed-module swap path, and no source path unloads a plugin or tests changed-byte live replacement. | **Unwired** for in-process changed-module replacement: the native loader exists, but Assembly has no live-reload/swap path. The only tested case is identical-byte regrant reuse. Process restart is an inference about reliable adoption, not an accepted R7 decision. |
| Project extension hook/middleware live revoke | Assembly attaches project extension hook registrations and middleware after plugin initialization ([`assembleExtensions`](../../../internal/cli/assemble.go#L1119)). R6's trust binding matrix explicitly excludes these callbacks and leaves them uncovered ([R6 boundary](r6-trust-dispatch-revocation-design.md#L123)); the generation binding is applied to project extension-provided tools, not to hooks/middleware. | **Current-active but live generation revocation is uncovered**. Do not extend the R6 prepared-tool revocation guarantee to extension hooks or middleware. |
| Extension `ConfigProvider` | The [`extension.ConfigProvider` contract](../../../internal/extension/extension.go#L26) is stored in the `Assembly`'s exposed [`core.DefaultRegistry`](../../../internal/cli/assemble.go#L252), whose replaceable [`ConfigProvider` slot](../../../internal/core/registry.go#L251) is initialized to [`core.DefaultConfigProvider`](../../../internal/core/registry.go#L86); its `Load` and `Watch` return `errConfigUnsupported` ([`Load`](../../../internal/core/stubs.go#L211), [`Watch`](../../../internal/core/stubs.go#L217)). A search of non-test production code finds no caller of either registry accessor, so the default CLI flow does not load or watch an extension config source. It is distinct from `llm.ModelProvider`. | **Unwired** as a default runtime config source; the exposed API slot does not establish a configured consumer. |
| EventBridge | [`EventBridge`](../../../internal/extension/bridge.go#L19) is a bounded helper with a 64-event output buffer, FIFO forwarding, cancellation, and dropped-after-read accounting. [`TestEventBridgeCancelAfterReadReportsDropped`](../../../internal/extension/bridge_test.go#L149) covers that helper. A production-source search finds no Assembly/EventStream/trace consumer. | **Unwired**. This helper does not establish Assembly event delivery or tracing integration. |
| Trace runtime: JSONL/stdout/none | CLI [`newTracing`](../../../cmd/cli/main.go#L525) calls [`BuildTracingRuntime`](../../../internal/tracing/runtime.go#L49). The runtime accepts empty/default, `jsonl`, `stdout`, or `none`; disabled tracing and `none` create no runtime artifacts. Enabled sinks are wrapped for redaction and async export. Assembly reuses the invocation tracer from context ([`assembleTracing`](../../../internal/cli/assemble.go#L907)); it does not construct another exporter. Tests cover supported names, disabled/none, JSONL identity, stdout, and rejection ([`runtime_test.go`](../../../internal/tracing/runtime_test.go#L17)). | **Current-active** for JSONL/stdout; **current-active no-op** for `none` or disabled tracing. The default empty exporter name selects JSONL. |
| Trace OTLP/Kafka constructors | OTLP emits a simplified `{"spans":[...]}` JSON-over-HTTP payload ([`exporter_otlp.go`](../../../internal/tracing/exporter_otlp.go#L38)); Kafka uses a length-prefixed JSON/TCP frame ([`exporter_kafka.go`](../../../internal/tracing/exporter_kafka.go#L21)). Runtime/config validation rejects names outside its supported whitelist before side effects; exporter unit tests use fake HTTP/TCP peers and do not show OTLP/Kafka wire-protocol conformance. | **Fail-closed / unsupported by default runtime**. Constructors and focused tests are not evidence of compatible OTLP collector or Kafka broker integration. |

## R7 boundary and evidence limits

The [extension tool-projection handoff](r7-extension-tool-projection-handoff.md#L3) and [`SkillLoadReport` design](../2026-09-25-runtime/r7-lifecycle-design.md#L100) are candidates only. Neither is an implemented behavior or an accepted phase decision. This snapshot does not close R7: the existing ledger still has R7-DES-01 pending, BLD-01/BLD-02 in progress, and REV-01 pending ([DES-01](../2026-09-25-runtime/execution-tasks.json#L1543), [BLD-01](../2026-09-25-runtime/execution-tasks.json#L1594), [BLD-02](../2026-09-25-runtime/execution-tasks.json#L1634), [REV-01](../2026-09-25-runtime/execution-tasks.json#L1676)). The ledger and phase state were not modified.

Evidence in this document is limited to the source baseline, production call paths, and named tests. No tests, build, race run, E2E, protocol interoperability test, or live runtime check was performed for this audit. The local toolchain and platform above describe only the audit environment; they do not prove CI or release-platform coverage.
