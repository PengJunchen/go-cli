# R2 CLI production RunCommitSink wiring handoff

Status: source audit plus docs-only design follow-up; no product code or tests changed. Audited source base: `812a70e551188801c21e904a8ff55cf6515b0693` (`codex/r2-cli-production-wiring`); implementation handoff fixed at `2b8101ed5cf9105bc639dfcc41f2474b394c1a59`; independent design review: [`r2-cli-production-wiring-design-review.md`](reviews/r2-cli-production-wiring-design-review.md) at `e58bb2f2e81d9adebdf85ef238ad8b0c12238331`. This document updates the source-state portion of [the earlier CLI session handoff](r2-cli-session-handoff.md); that approved handoff and the R2 contract, local-quiescence proof contract, core consumer, and session adapter remain authoritative except for the explicitly scoped first-slice fork deferral below. Assembly shutdown must use the `AgentAssembly.Close(ctx)` owner from the existing [Assembly close handoff](r7-assembly-close-handoff.md), not create another close framework.

## Source conclusion and activation rule

The production prompt and interactive commands do not yet install a durable session sink. `durableSessionManager` and `durableCLISession` are real, tested helpers, but their only callsites are helper tests. The current prompt/REPL/serve paths never call `newDurableCLISession` or `bindRun`, and no assembly field owns a durable session.

`SessionConfig.StorePath` has an empty zero value and is not itself an `enable` switch. `AssembleAgent` defaults `enableSession` to false and opens a legacy `JSONLSessionStore` only when both `enableSession` and a nonempty `StorePath` are present (`internal/cli/assemble.go:261-277,305-307,512,1584-1593`). The interactive command always passes `WithSessionPersistence(true)` (`internal/cli/repl_session.go:264-279`), so a configured path currently selects the legacy writer. Prompt adds that option only for `--fork` (`internal/cli/prompt.go:147-159`); an ordinary prompt currently ignores a configured store path.

For the R2 production wiring, preserve that existing enable boundary rather than adding a parallel `--durable-session` mode:

- When `Session.StorePath` is configured and the command enables session persistence, use the durable manager and the actual seven-method session RunCommit sink. The interactive command therefore starts a new physical session by default when it has a configured store path. Prompt must treat a configured `Session.StorePath` as persistence enabled and start a new physical session by default; this intentionally changes its current ordinary-prompt behavior, which does not persist today.
- `Session.StorePath` empty, or an explicitly disabled persistence option, remains the non-durable path. No durable manager or sink is bound there.
- `--resume-session <physical-id>` is an explicit durable selection and always requires an exact ID. It never means “latest.” The selected branch defaults to the exact active branch in that physical session. The current manager rejects a different requested branch with `ErrPreparedSessionBranchSelectionUnsupported`; do not expose a branch switch until the prepared-session API can select it durably.
- The old boolean `--resume` cannot choose a physical file or branch. With a configured durable directory it must return a usage error directing the user to `--resume-session <physical-id>`. Legacy v0/single-file reads, if retained, belong to a separately explicit compatibility/import path and must not be presented as a durable ledger or used as fallback after a durable prepare error.

This activation rule has two compatibility consequences that need explicit tests and release notes: configured interactive persistence moves from best-effort legacy JSONL writes to durable RunCommit rows with fail-closed errors; configured prompt persistence begins creating a new durable physical session where ordinary prompt previously wrote nothing. A configured path ending in `.jsonl` is not silently converted: `JSONLSessionStore` accepts both file and directory modes, while `DurableJSONLSessionPreparer` expects a session directory. Durable preparation must reject incompatible paths, never reinterpret or migrate an old file in place.

## Minimal wiring sequence

1. **Resolve mode before constructing the runtime.** Parse exact resume selection and the existing session enablement. Validate that a configured durable `StorePath` is a directory and reject an old file path, ambiguous `--resume`, unsupported branch selection, and unsupported durable fork before creating a provider call path. Do not automatically fall back to the legacy store if durable setup fails. Surface the generated/selected physical ID distinctly from the logical `SessionConfig.ID` so the user can resume it; do not derive it from the display label, path, timestamp, or contents.
2. **Prepare once and transfer ownership.** Call `newDurableCLISession(ctx, StorePath, displayLabel, exactPhysicalID, activeBranchID)` before publishing the Agent. It already derives a canonical workspace identity, ensures the workspace index, and calls `PrepareNew` or exact `PrepareResume`. Read one `snapshotSelected()` and verify the physical ID and active branch. Pass the prepared durable session to `AgentAssembly` through one narrow option/field; Assembly adopts the manager on success and includes `requestClose` in its existing `Close(ctx)` owner. If assembly fails before ownership transfers, the command closes the helper and joins that close error with the assembly error. No caller and Assembly may both own independent base-close paths.
3. **Seed from the canonical view.** Initialize `Agent` history from `snapshot.PublishedView.Messages`. For REPL navigation, build with `session.NewDefaultSessionTreeBuilder().BuildFromSnapshot(ctx, snapshot)`. The tree is navigation only; do not reconstruct model history from `DurableEntries`, events, or the old JSONL store. After an acknowledged terminal checkpoint and a joined/non-pending run, read one new prepared snapshot, update Agent history from its `PublishedView`, and rebuild the navigation tree before the next slash command or user turn. Do not refresh from an unacknowledged terminal or from an open assistant group.
4. **Bind exactly one lease to each run.** Immediately before `Harness.Submit` or `TurnRunner.RunTurn`, call the selected helper's `bindRun` with that run's context. Pass the returned context unchanged to the entrypoint and do not call `PrepareToolCall` or any sink method from the CLI. Core owns the optional `RunCommitRunLease` return obligation at both entrypoints: capture it before any possible early return, release it on every pre-owner rejection after local claim/wrapper/stream cleanup, and transfer it exactly once to the `runOwner` at the synchronous accepted-run boundary. `runOwner.run` reuses a transferred lease token instead of adopting/wrapping the same sink lease again; direct owner tests/callers without an entrypoint token retain the existing context-based adoption path. Once accepted, only the owner releases after callbacks/workers/resources join and terminal/late-proof policy completes, including a `cleanup_pending` return. A pre-owner `CloseRunCommit` panic joins `ErrRunCommitLeaseClosePanicked` with the original rejection, without inventing a RunID or unknown run. The helper binds the actual session adapter, its `WorkspaceQuarantineIndex`, physical session ID, and workspace ID atomically. Core remains responsible for RunID/OwnerGeneration, `CommitInput` before provider entry, canonical assistant/intent sync, `BeginDispatchBatch` returning `CommittedNow` before dispatch, canonical receipt ordering, proof-gated resolution, and terminal acknowledgement. Session adapter uses real `AppendAndSync` row IDs for evidence. CLI must not invent row IDs, release a per-run lease, or infer proof from normal return.
5. **Keep one transcript writer.** With a durable session attached, never also create/use `JSONLSessionStore` for that same path. In REPL, do not initialize `PendingSessionWrites` or its flush ticker, do not call legacy `persistSession` transcript enqueue/flush/save, and do not make final legacy session saves. Preserve memory extraction only after the canonical Agent history is refreshed. Non-durable and explicitly selected legacy-compatibility paths retain their current writer separately.
6. **Close through the complete wrapper.** Use the Assembly's existing single-flight `Close(ctx)` from the Assembly-close lane, not `Cleanup` as a substitute. Its established close sequence fences and drains run owners before requesting durable manager close; manager close rejects new leases and waits for the owner-returned leases before calling `PreparedSession.Close`. A `cleanup_pending` result, status-only quarantine, canceled caller, or failed terminal sync does not release a live lease or close a live handle. Commands return errors.Join of run/output/input/server and Assembly-close failures; no `defer Cleanup()` may erase them. Assembly close must report manager close errors and remain joinable after a caller deadline.

In prompt, if the event consumer fails to write output, retain the first writer error but continue draining the event stream and wait for `stream.Result()` so the accepted run can finish its terminal/cleanup path before close. In the REPL, a `RunTurn` that returns cleanup-pending or unknown stops further input/turns; it is not permission to start another run or close a still-leased session. Normal known error/cancel outcomes with a synced terminal may refresh the canonical snapshot, but they are not reported as successful runs.

## Failure and recovery behavior

- **Prepare, identity, binding, or recovery failure:** return a typed error before provider/tool dispatch. Never drop the sink, create a replacement session, select the newest file, or use a logical session label as physical identity. If a run lease was acquired and the core entrypoint rejects before owner adoption, core releases that lease after local claim/wrapper cleanup; if that release panics, join `ErrRunCommitLeaseClosePanicked` with the original rejection. No RunID or unknown run outcome is fabricated for a pre-owner rejection, and the manager remains truthfully pending if the lease callback did not complete.
- **Known denial or index fence:** preserve canonical transcript receipt order. A denial does not dispatch. A `BeginDispatchBatch` denial/error stops before the executor; it is not repaired by a legacy write or by continuing the suffix.
- **Unknown tool outcome or no positive completion proof:** preserve the receipt/outcome and unresolved workspace marker; stop suffix/provider work and do not claim durable success. `Done`/local join is not proof by itself. Default `Write`/`Edit` using the wrapped external `GitDiffGenerator` remain outside the inline-proof trust set; an invocation that returns no recognized proof must stay quarantined. The attested concrete core EventStream path may be used for streaming only through the same prepared invocation and captured synchronous sink; custom/unattested sinks remain unsupported. Do not turn these proof limits into CLI-side inference.
- **`cleanup_pending` / owner still live:** do not release the lease from a caller defer, begin a later REPL turn, or close the selected physical handle. Keep the Assembly/session manager reachable and let the existing owner continue until callback, workers, and known resources join. A bounded waiter may return pending; it is not a stop signal.
- **Persistence/sync failure (poisoned writer):** return the sink failure and withhold successful acknowledgement. Once the core owner has actually joined and returned its lease, call the manager's `reopenPoisoned` path before the next durable run. It closes and `PrepareResume`s only the same physical ID against the same workspace recovery authority. If exact recovery fails, leave the session unavailable/quarantined and return that error; never create a new session as repair.
- **Unknown outcome with healthy local writer:** this is distinct from a poisoned writer. Do not mark the writer poisoned solely because outcome is unknown, and do not clear a global marker merely because local resources joined. Preserve quarantine and let exact recovery/index validation decide whether any later operation is admissible. Never replay the original action.
- **Compaction projection boundary:** the current durable core consumer fails closed with `ErrRunCommitCompactionProjectionUnavailable` before invoking the compactor when a durable compaction projection is unavailable. CLI wiring must surface this terminal error; it must not continue through legacy compaction or acknowledge an empty projection. Actual durable compaction projection remains outside this CLI handoff.
- **Child/ACP isolation:** the current durable child path returns typed `ErrRunCommitChildUnsupported` before provider work when there is no independent physical session factory. Do not mask context values, bind one server-wide session, or use matching child prompt text as identity.

## Independent review follow-up: pre-owner lease return and bounded fork deferral

This docs-only revision closes the P1 lease-ownership gap and resolves the P2 fork-scope conflict from the independent review at `e58bb2f2e81d9adebdf85ef238ad8b0c12238331`. It does not change product code, close the R2 feature/plan gate, or waive the R7 Assembly-close prerequisite.

### One core-owned lease handoff across both entrypoints

The CLI binds the selected durable sink/lease in the run context and passes that context unchanged to `Harness.Submit` or `TurnRunner.RunTurn`. It does not close a per-run lease itself, including when an entrypoint returns a rejection. Core owns a narrow, unexported pre-owner lease guard shared by both entrypoints; the existing optional `core.RunCommitRunLease` remains the only external capability, with no new exported transfer API.

Each entrypoint captures the optional lease before any early return. Until the accepted-run handoff is established, its rejection path owns return of that lease. A deferred pre-owner release runs after ordinary entrypoint cleanup by LIFO ordering, so stream/span/context, wrapper registration, and claimed run-slot cleanup finish first. This covers a nil TurnRunner loop, failed claim, wrapper registration/status failure, and Harness stream setup failure. If no owner adopts the lease, return it exactly once.

Transfer is synchronous and unambiguous: `Harness.Submit` attaches the captured lease to its `runOwner` after wrapper status succeeds and before marking transfer/starting `h.run`; `EinoTurnRunner.RunTurn` attaches it after wrapper status succeeds and before calling `owner.run`. The accepted path disarms the entrypoint rejection guard, and the owner releases only after callback, workers, resources, terminal bookkeeping, and eligible late-proof drain have completed. A returned `cleanup_pending` snapshot does not move ownership back to the caller. `runOwner.run` must reuse a lease token already transferred by an entrypoint instead of adopting the same sink capability a second time. Direct `runOwner.run` use without an entrypoint transfer remains supported by its current context lookup/adoption behavior.

Use one internal once-guard for exactly-once close if needed to share the release result across the rejection and owner paths; do not infer adoption from `Result`, `Outcome`, arbitrary error identity, or `ExecutionState`. The pre-owner release path uses the existing `closeRunCommitLease` panic containment and maps a panic to `ErrRunCommitLeaseClosePanicked`, joined with the original rejection. A rejection before owner start has no run identity: do not invent a RunID or mark a nonexistent run unknown. If a user-provided lease close panics, its manager borrow may remain live; preserve that manager-level pending condition for Assembly close rather than claiming the lease was returned. A release callback is not permitted to perform fallible durable work or close the prepared session.

### First CLI wiring slice explicitly defers fork and slash mutation

For this bounded production-wiring slice, durable prompt `--fork <entry-id>` returns a typed unsupported error before calling `newDurableCLISession`; it must not initialize the workspace index, prepare/create a physical session, acquire a run lease, change history, or enter the provider. In durable REPL mode, `/resume`, `/switch`, `/fork`, and `/clone` return a typed unsupported error before tree/history/branch/session writes; `/tree` and `/branches` remain read-only views of the selected canonical snapshot. The non-durable compatibility path may retain its current behavior.

This explicitly supersedes the earlier R2 CLI handoff's requirement to deliver a durable prompt fork in this first wiring slice. It does **not** complete durable fork/branch functionality or close the full R2 feature/plan gate. A separate follow-up must define and implement a distinct durable target physical session/branch seeded from the exact source snapshot and persisted before provider work; resuming the source and changing in-memory history is not a fork. Exact `--resume-session <physical-id>` remains the only durable physical-session selection, and the current manager's unsupported alternate branch remains fail-closed.

### Required follow-up regressions

- Core entrypoint table tests cover pre-owner rejection at nil-loop, run-slot claim, wrapper-registration, wrapper-status, and stream-setup boundaries. Assert zero provider calls, original rejection preserved, all claim/wrapper/stream cleanup occurs before lease return, and `CloseRunCommit` is attempted exactly once.
- A lease that panics during a pre-owner return yields `errors.Is(err, core.ErrRunCommitLeaseClosePanicked)` and preserves the original rejection cause. Assert no invented RunID/outcome and that Assembly/manager close still reports the held borrow as pending if release did not complete.
- Accepted `Harness.Submit` and `TurnRunner.RunTurn` each transfer once. Hold callback/resource completion so an early `cleanup_pending` return leaves the lease open; after actual join and terminal policy, the owner closes it exactly once. Keep direct `runOwner.run` tests working without an entrypoint transfer token.
- Durable prompt `--fork` is rejected before `newDurableCLISession`, so neither workspace-index initialization nor session creation occurs, and before provider entry. Durable REPL `/resume`, `/switch`, `/fork`, and `/clone` are rejected before mutating tree, Agent history, branch state, or disk; read-only `/tree` and `/branches` continue to use the canonical view.

These are later implementation acceptance requirements, not tests claimed by this design-only revision. The real command/Assembly integration remains gated on the accepted R7 `AgentAssembly.Close(ctx)` owner.
