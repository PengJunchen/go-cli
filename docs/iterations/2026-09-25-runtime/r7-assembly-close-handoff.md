# R7 Assembly close and shared admission handoff

Status: bounded design-only handoff. The Assembly/R2 source baseline is `009f31c`; the independent R3/R7 lifecycle review rechecked the guard and selector findings at `a8717d0` on `codex/runtime-stabilization`. This defines the Assembly shutdown prerequisite needed by R3 model switching; it does not implement shutdown or close R2/R3/R7 phase gates.

## Minimal shutdown contract

1. `AgentAssembly.Close(ctx)` is single-flight and idempotent. The first call immediately closes admission on the exact guard shared by Harness and TurnRunner. The close request remains in force if the caller context is already canceled or expires. Calls made after the fence receive the stable typed closed-admission error; a run claim that linearized before the fence remains owned until its actual R1 release.
2. Add one narrow close-capability on `DefaultRunSlotGuard`: `CloseAdmission() <-chan struct{}` atomically closes admission against `ClaimRun` and returns the same stable idle channel on every call. The guard also owns one closed-notification channel used internally by blocked `ClaimRun` calls; fencing closes it so waiters wake promptly and fail without waiting for the current claim to release. The idle channel closes only when admission is closed and there is no current claim. If the guard was idle at the fence, it closes immediately; otherwise only the real `Release` transition can close it. Repeated fence calls neither replace nor reopen either signal.
3. Linearize claim acceptance/publication and release/availability under the same guard mutex or equivalent single atomic state transition. Prefer a small mutex plus wait notification that removes the current semaphore reservation-before-publication window. A `ClaimRun` either publishes `current` before the close fence and remains active until real `Release`, or observes closed admission and returns the typed error without becoming current. A blocked claimant waits on availability notification, stable closed notification, and its own context; after any wake it rechecks the closed bit under the guard lock before publishing. `Release` makes `current = nil` and slot availability visible as one transition; idle must not close in an intermediate state. If the semaphore is retained, idle closes only after the accepted current claim is cleared and its semaphore token is returned. Do not add a second reservation registry or complex counter framework. If retaining the semaphore requires reservation accounting to preserve these semantics, prefer removing that internal reservation instead.
4. A caller deadline is a waiter deadline only. Timeout returns a typed `cleanup_pending` error/report; it does not cancel the R1 owner, clear its claim, release an R2 lease, or run model/session cleanup while the owner may still use those resources. The same close owner remains reachable and continues from the same phase. A later `Close` joins that owner; it does not start a duplicate close sequence.
5. After the closed fence and R1 idle signal, Assembly close must acquire the **same R3 selector mutation gate** before releasing any resolver/provider dependencies. While holding it, seal selector mutation and detach the Loop model, retaining selected-model disposer handles for the later model-cleanup phase. This prevents a post-fence builder from starting and waits for a builder already in progress; that builder's later run-slot claim fails closed, its candidate is disposed once, and only then can the gate transfer to close. Do not clean selected models during this early seal if the resource order requires session/event cleanup first.
6. Use this dependency order; it is based on the live producers and owners above, not a restriction on what trusted extension code may retain: **at close initiation, close the shared run-admission fence and stop/cancel hot-reload request sources; wait for the R1 owner and resources to become idle; seal the selector through its same mutation gate and retain model disposer handles; join any active hot-reload reconnect/register callbacks and run extension shutdown serially; then close the durable session and event/memory resources; dispose the selected and small models; finish Assembly spans; finally let the root invocation end its root span and shut down its exporter.** The first fence/cancellation steps prevent new work. R1 drain keeps the resources used by an admitted run alive; gate acquisition then joins or rejects candidate construction before its resolver/provider dependencies are released. Extension and reconnect callbacks are joined before their possible dependencies are closed; even though Extension.Init does not receive a session handle, the extension is trusted in-process code and may own other references. EventBridge is not currently assembled; if introduced, join its forwarder before closing the destination bus. The R2 owner has synced its terminal outcome (or recorded unknown/error), returned its per-run lease, and released the guard before physical session close. Selector seal detaches the Loop model but does not close model resources until the designated model-cleanup phase. |
7. Record resource disposers immediately at acquisition, not at a late final-cleanup append. Each resource has one owner and an observable terminal state. Close results aggregate terminal errors in one `ShutdownReport`; only a confirmed completion is marked closed. Setup failures join the original error with cleanup errors/pending status instead of discarding the cleanup result.

### Uncooperative close callbacks

The public caller context must not be passed as the lifetime context for the close owner. A single Assembly-owned serial close executor owns the operation and its resource handles; callers only wait for its result with their own contexts. A callback that ignores context cannot be forcibly interrupted. If it blocks past a caller deadline, `Close(ctx)` returns `cleanup_pending`, while the same executor retains the callback stack, the current resource, and all later dependencies; it must not advance or claim shutdown complete. When the callback eventually returns, that owner records its result and continues once. If it never returns, the truthful process result is pending/nonzero; no implementation can claim the callback stopped merely because the caller stopped waiting.

The first `AgentAssembly.Close` call creates the single close owner and records one absolute cooperative deadline from that instant. The first slice may reuse `tracing.DefaultAsyncExporterShutdownWaitBudget` (currently 20 seconds: the existing 10-second drain plus 10-second callback budget) as its initial Assembly budget; this is reuse of a default, not evidence that all Assembly callbacks finish within 20 seconds. Do not reset the deadline per phase or callback, and do not derive the owner deadline from the caller's waiter deadline. The caller's context only decides how long that caller waits. Even if that context is already canceled, the call must still close admission and start/join the owner; it must not skip cleanup.

For context-aware resource shutdown, pass a close-owner callback context with that one deadline. The callback's close request must synchronously close its own admission/start its own operation even when the deadline has expired; the context bounds cooperative work and waiting, not whether the close request is made. If a callback is contextless `func()`, invoke it once, serially, on the close owner itself. Never put it in a detached goroutine merely to make the caller return: until it truly returns, retain its stack, resource handle, and all later dependencies, and let callers receive a typed pending report. A deadline cannot interrupt such a callback.

When an asynchronous manager can return before its callback actually stops, wait on that manager's operation-specific completion signal and retrieve its stored result (for example, a narrow PluginManager `WaitShutdown(ctx)` over the exact shutdown operation). Do not infer operation state from error text or a sentinel that user callbacks can themselves return. If the shared deadline expires while the callback is still active, the close owner remains responsible and waits for the exact completion signal; waiters may return `cleanup_pending`, but teardown must not advance past that callback. After it returns, the owner may continue serial cleanup while retaining the original deadline for cooperative operations. A resource whose close request reports pending must stay owned until its `Wait` seam confirms stopped; absent such a seam, the source must remain pending rather than be marked closed. Do not start a second callback attempt on a later `Close` call.

## Minimal source ownership and API delta

- `internal/core/run_slot.go`: implement the R7-assigned `RunAdmissionCloser.CloseAdmission() <-chan struct{}` on the existing default guard. Add one stable internal closed-notification channel to wake blocked claims and one stable idle channel returned by every `CloseAdmission` call. Linearize admission/current publication and release/availability under one guard mutex or equivalent transition: a pre-fence claim remains until actual `Release`, post-fence claims fail immediately, and idle cannot signal before real release. Prefer removing the semaphore reservation gap over adding reservation counters. Keep `RunOwner`, `RunClaim`, worker accounting, and R1 status semantics unchanged. This guard admission change can be the first independently implemented slice; it does not depend on R2 durable CLI wiring and does not create a second registry.
- `internal/cli/assemble.go`: add `AgentAssembly.Close(ctx) error` and a private single-flight close owner/report; preserve `Cleanup func()` as a deprecated compatibility wrapper. Change the Assembly-owned cleanup registration from raw `func()` to the smallest typed step needed to propagate error/pending and exactly-once state. Ensure initial and switched primary model cleanup have one selector owner. Keep the configured small model as a distinct owned resource.
- `internal/cli/durable_session_manager.go` / prompt / REPL: once R2 wiring lands, Assembly close calls the manager's close request only after shared guard quiescence and reports `PreparedSession.Close` errors. `CloseRunCommit` remains run-owner-only lease release.
- `internal/extension` and `internal/cli/assemble.go`: provide an exact `PluginManager` shutdown-operation wait/result seam; split close-owner callback context from each caller's waiter context. Stop hot-reload admission immediately, then join the active reconnect loop and registration callback before closing registries or downstream resources. Do not hold selector/assembly state mutexes across plugin callbacks. Keep EventBridge out of current Assembly ownership; if wired later, cancel and join its `Wait` before closing its destination.
- `internal/llm/model_selector.go`: implement the accepted R3 mutation gate before the resolver/builder, held through build, shared run-slot claim, publication, callback, and retirement. After shared admission drains, selector close takes that same gate, seals mutation and detaches the Loop model while retaining its cleanup handles for the later model phase. A busy/closed selector returns typed errors. Selector/model resources are reported closed only after their actual cleanup callbacks return.
- `internal/cli/prompt.go`, `repl_session.go`, `serve_cmd.go`: call `Close` explicitly with a bounded shutdown waiter and combine its error with command/HTTP shutdown errors. A defer may be used only to guarantee a fallback attempt, not to suppress the returned error.
- `cmd/cli/main.go`: preserve the existing single exporter owner. After the command has closed Assembly and ended the root span, run the existing bounded exporter finalizer and keep any close/finalizer failure nonzero.

No new general Runtime, independent admission gate, goroutine registry, or arbitrary-model reference counter is required. The guarantee is limited to the Assembly's shared Harness/TurnRunner path. Direct `LoopAgent.Run`, a retained bare `BaseChatModel`, or a caller-provided model reference outside Assembly remains that caller's quiescence responsibility.

## Gates and explicit limits

R1 supplies the truthful run-owner/quiescence primitive; the first implementation slice may add only the closed-admission fence, waiter wakeup, and stable idle signal to that same guard. R2 still gates production session/sink/lease wiring. R3 resolver/catalog behavior, pre-builder mutation gate, and selector resource ownership are prerequisites to the model close step. R7 extension shutdown/error aggregation, hot-reload join, and root tracer/exporter ownership remain in their assigned slices. None of these interfaces proves that a non-cooperative callback can be stopped; it can only keep ownership truthful, bound callers, preserve dependencies, and return a pending/nonzero result.
