# R3 model switch and Loop lifetime handoff

Status: design-only follow-up for the approved R3 provider/catalog contracts. The initial selector findings were verified at integration tip `463354450a3015ecc516734de4a3fbb52b654379`; the R2 lease status below was rechecked at `009f31c` on `codex/runtime-stabilization`. This document does not authorize implementation, complete R3, or enable a protocol. R3 implementation remains gated by production R2 session/owner wiring and `R2-REV-01`.

## Minimal contract recommended for the CLI path

Use one serialized model-mutation operation in the existing selector/assembly path, plus the already-shared `RunSlotGuard`; do not hold the selector state mutex across builders, cleanup callbacks, or notifications, and do not add a general model/runtime registry.

1. Resolve and build the candidate from the existing immutable resolver and full `ModelSpec` before entering the publication section. Keep its cleanup locally owned until commit succeeds. Preserve the current provider/protocol/origin and credential checks.
2. Try to acquire a separate selector mutation gate; do not queue callers behind it. If another switch/close owns it, dispose of the candidate and return a typed busy error. After acquiring it, claim the same `RunSlotGuard` used by Harness and TurnRunner using the caller context. If claim fails or the context is canceled before publication, clean up the uncommitted candidate outside state locks and leave the active selector/Loop unchanged. The run owner continues to hold the slot while R1 workers/resources remain; the core R2 lease implementation now releases its borrow before the slot, but production CLI wiring is still pending. Current Harness/TurnRunner admission uses a 200 ms claim timeout, so a run arriving during the short switch transaction may fail as busy; it must make no provider call against a half-published model.
3. Under the selector state mutex, perform one short publication of the current `ModelSpec`, model, generation, and cleanup ownership. Release that mutex before updating the Loop or running any cleanup. While the operation gate and run-slot claim remain held, update the Loop's model through the existing `SetModel` seam, then clean up the retired model. Only then release the run-slot claim and operation gate. Thus no assembled CLI run can snapshot or call the retired model during the selector/Loop publication gap, and a slow old cleanup cannot let another switch callback overtake it. Read-only selector queries from a callback remain safe because the state mutex is not held.
4. Give the selector an idempotent closed state. Assembly close first closes shared run admission and waits for the existing R1 owner to release the slot; only then does selector close acquire the mutation gate, mark the selector closed, clear the Loop model, and close each model-owned cleanup exactly once. A switch that finishes building after admission closes must dispose of its candidate and return a typed closed error without publishing. Register one selector close with `assembleState` cleanup; transfer primary cleanup ownership into the selector so a model generation has one cleanup owner. Keep the independently configured small-model cleanup separate. The bounded close behavior and exact owner-retention contract are in [`r7-assembly-close-handoff.md`](r7-assembly-close-handoff.md).
5. Limit this guarantee to models acquired through the assembled CLI's Harness/TurnRunner path and its shared run guard. Direct external `LoopAgent.Run` calls or retained naked `BaseChatModel` pointers bypass that fence; their callers must provide their own quiescence/lifetime coordination. Do not add a global refcount to make arbitrary uncontracted model references appear safe.

The mutation gate orders publication, callback, and cleanup as a single transaction. The accepted semantics is **successful publication order**: whichever operation successfully acquires the mutation gate and shared run slot later commits later. No invocation generation or last-invoked-wins rule is needed. Concurrent or nested mutation attempts return a typed busy error; read-only callback queries remain allowed because the selector state mutex is not held across callbacks.

The current callback is the assembly's in-memory `LoopAgent.SetModel` update. While the operation gate is held, callback read-only queries are allowed. Nested and concurrent mutations are rejected with the same explicit busy error; do not add an implicit queue or goroutine-reentry detector.

## Close and bounded shutdown boundary

`AgentAssembly.Cleanup` currently has type `func()` and `assembleState.runCleanup` invokes cleanup closures synchronously. Root selected bounded, context-aware Assembly close: close shared admission immediately, wait for the already admitted R1 owner and its resources, then clean resources. A caller deadline bounds only that caller's wait; it must not cancel the owner, release the run claim, or close a model while an owner may still use it. The full close owner/retention contract is specified in [`r7-assembly-close-handoff.md`](r7-assembly-close-handoff.md). R2's core lease is implemented at `009f31c`, but CLI sink/lease wiring is still an R2 gate and must not be claimed complete here.

## RED-first acceptance

Add focused tests before implementation. Use fake models with gated `Stream`/cleanup callbacks and the production shared run-slot wiring; do not test only selector helper state.

- `TestModelSwitchCallbackCannotPublishOutOfOrder`: first switch blocks in a retired-model cleanup; start a second switch. Assert the second returns the typed busy error and cannot publish/callback. After the first finishes, retry the second and assert the successful publication order leaves selector identity and Loop model on the same generation. Each callback performs `CurrentModelSpec`/`PrimaryModelName` reads to prove no state mutex is held.
- `TestModelSwitchWaitsForRunOwnerQuiescence`: a real `LoopAgent.RunCanonical` starts with model A and blocks inside its stream; a switch to B must not clean A, update the Loop, or admit another run until the current RunOwner releases the shared slot. Then assert the first run used A, the next run uses B, and A's cleanup ran exactly once. Repeat with a registered worker/resource that holds the R1 owner after the Loop callback returns; the switch must remain fenced until that resource joins. After R2 integration, add a sink `RunCommitRunLease` fixture and prove switch admission also waits for its release.
- `TestSwitchCanceledAtAdmissionPreservesCurrentModel`: occupy the run slot, build a candidate with an observable cleanup, cancel the switch context while it waits, and assert candidate cleanup exactly once with no selector/Loop publication.
- `TestSelectorCloseClosesAdmissionAndOwnsAllCleanups`: close an idle assembly after zero or multiple switches; assert initial/current/intermediate cleanup counts are exactly once, the Loop cannot call a model after close, repeated close is harmless, and subsequent switch fails with the typed closed error. Race close against a blocked builder; once it returns, the uncommitted candidate is disposed and never published.
- `TestModelSelectorReadQueryDuringPublish`: callback queries the selector while a switch is publishing and completes under a bounded timeout; a nested `SwitchModel*` from that callback returns the typed busy error without deadlocking. This prevents moving the state lock over callbacks as a false fix.
- `TestAssemblyCleanupIncludesFinalSwitchedModel`: assemble with a local HTTP model fixture, switch once, then invoke the real bounded `AgentAssembly.Close(ctx)`; verify the active switched client/cleanup is released once and no switch can reopen the selector.

Run exact tests in their owning packages, then race the concurrency/lifetime cases:

```bash
rtk env GOMAXPROCS=2 go test -p 2 -race -count=1 ./internal/llm -run '^(TestModelSwitchCallbackCannotPublishOutOfOrder|TestSwitchCanceledAtAdmissionPreservesCurrentModel|TestSelectorCloseClosesAdmissionAndOwnsAllCleanups|TestModelSelectorReadQueryDuringPublish)$'
rtk env GOMAXPROCS=2 go test -p 2 -race -count=1 ./internal/core -run '^TestModelSwitchWaitsForRunOwnerQuiescence$'
rtk env GOMAXPROCS=2 go test -p 2 -race -count=1 ./internal/cli -run '^TestAssemblyCleanupIncludesFinalSwitchedModel$'
```

For the A/B ordering and close-versus-builder tests, repeat the named tests with `-count=20`. Verify the test names with `rtk go test -list` before recording them. Do not run full R3/R2 acceptance from this design slice. The first RED should reproduce selector B + Loop A after A's cleanup is released, a switch completing while a run still calls A, and a post-close switch retaining a newly built cleanup. A passing selector-only test is not evidence of safe production admission or Assembly cleanup.

## Root decisions fixed for implementation

1. Successful publication order wins; no last-invoked-wins generation.
2. A non-blocking mutation gate returns typed busy/closed errors for concurrent or nested mutation; read-only callback queries remain supported.
3. Assembly close is bounded and context-aware. A waiter timeout returns pending while the close owner and cleanup responsibility remain alive; it never closes a model or dependency while an R1 owner still holds the shared slot.
4. The guarantee covers the Assembly's shared Harness/TurnRunner path only. Direct `LoopAgent` calls and retained naked model references require caller-owned quiescence.

R2 production run-lease wiring, R1 admission/quiescence, and R3 resolver/provider identity remain independent gates. This design does not authorize native protocol enablement, retry changes, cost accounting, cycler/subagent resolver work, or a new global model-runtime framework.
