The highest-priority implementation handoff is the extension Hook boundary. `HookEvent` is documented as immutable, but the production bridge passes `core.Submission`, `core.Result`, and the original `error` directly in `Data`; hook registration owner identity is discarded, and an arbitrary unbounded `HookResult.Reason` is copied into a returned error (`internal/cli/extension_bridge.go:25-73`, `internal/cli/assemble.go:1084-1088`). This leaves mutable runtime state and raw diagnostic content visible to extension code. The planned `TestHookEventDataIsImmutable` is absent; existing adapter tests cover pass/block behavior only. The accepted design already specifies the bounded remedy: extension-owned, deep-copied value DTOs, owner-preserving `HookRegistration`, and errors that do not interpolate arbitrary reason text ([remaining design:87-91,100-111](../2026-09-29-runtime/r7-remaining-design.md#L87)).
