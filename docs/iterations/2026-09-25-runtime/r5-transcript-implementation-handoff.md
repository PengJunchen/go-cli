# R5 transcript / R8 viewport implementation handoff

Status: implementation handoff for root review; no source, ledger, or test changes are included. Source inspection is pinned to detached, read-only commit `a44b19de3e75ec176bae5fdc1b4d1f1ea6543195`. Existing R5/R8 design and review documents remain the product contract. This handoff records their remaining default-path wiring and ownership; it does not mark R5 or R8 complete.

The R5 design and contract reviews already define message identity, compaction, tool occurrences, interactions, status truth, and the R5/R8 boundary. The accepted R5 PTY slice covers terminal input ownership; the accepted R8 cells slice covers safe cell-width/ANSI helpers. Neither acceptance establishes a canonical durable transcript, general viewport, full-history search, or a completed default CLI journey. At this source baseline R5 builder work is partial and R8 builder work is partial.

## Current default path and authority gaps

The default local interactive path is `REPLSession.Run → start → setupAgent → setupSlashContext → setupEditors → readInput → executeTurn`. `readInput` obtains and trims one line through `DefaultLineEditor.ReadLine`. `executeTurn` calls `setupTurn`, starts `TurnRunner.RunTurn` in a goroutine, opens a new `BubbleteaApp` for that turn, waits for the app and runner, then calls `persistSession`.

`setupTurn` creates a bounded `EventStream` with `DiscardOldest` and attaches it to `TurnRunner`. `runAgentGoroutine` submits the user text, then emits a generic `done` event containing `Result.Message` and closes the stream. `renderTUI` connects `BridgeEvents` to a fresh Bubble Tea model; it passes `assembly.SessionID` as display metadata plus callbacks, but supplies no restored transcript, physical session ID, active branch, EntryID, or run-status handle. The app therefore sees this turn's events only. In non-TTY mode the final result is also printed after the app exits.

After the UI closes, `persistSession` makes new IDs and queues only a user row and, when non-empty, one final assistant row through the legacy JSONL store. It logs flush/save errors and continues. It does not persist the canonical tool receipt sequence and runs after the UI has already rendered. `setupSlashContext` independently calls `BuildFromStore`; legacy assembly can independently read `FilePath()` through `loadSessionHistory` and ignores that read error. The legacy tree builder chooses a latest timestamp leaf and tolerates skipped rows. These are not durable-session snapshot semantics.

| Fact | Current source / gap |
|---|---|
| Exact selected physical session and active branch | R2 `PreparedSessionSnapshot` exposes `SessionID`, `ActiveBranchID`, `ActiveLeafEntryID`, `MaxSeq`, `DurableEntries`, and `PublishedView`. The default REPL still uses `assembly.SessionID` and the legacy store. It must receive identity from the prepared handle. |
| Model-history transcript and source mapping | `PublishedView.Messages` is the model-history projection; `SourceEntryIDs` maps each message position to its actual durable source EntryID. The full snapshot may contain newer journal rows while the published view still withholds an open tool-call group. Use the view for transcript messages; use journal rows only for validated metadata. |
| Navigational tree | `BuildFromSnapshot` already validates one coherent snapshot and restores its exact leaf. The tree supports navigation and current-leaf bookkeeping. It is not a transcript, recovery replay source, or replacement for `PublishedView`. |
| Run identity and cleanup state | Core already has owner-generated `RunID`, `RunStatusHandle`, and `Result{RunID, Outcome, ExecutionState, StatusHandle}`. `TurnRunner` associates the owner status handle with the stream, but the REPL does not pass it into the TUI. `RunID` is absent from `core.AgentEvent` and the TUI bridge DTO. |
| Tool occurrence identity and payload | Core canonical run commits carry `RunID`, assistant transcript ordinal, and `ToolCallID`; persisted action rows may additionally carry `ActionID`. Current `BridgeEvents` copies only the event's standalone `ToolCallID`; it drops `ToolCalls`, `Usage`, and other canonical payload. TUI status/result lookup falls back to the most recent tool call, and `ToolCallID` alone can repeat in a later assistant group. |
| Saved acknowledgement | `RunCommitSink.CommitTerminal` is the durable terminal sync boundary; its current API returns errors, not a UI row map. A post-terminal `Snapshot()` on the same prepared handle can provide the exact published source IDs. Until that reconciliation, streamed rows are provisional. Never derive EntryIDs or ActionIDs in TUI. |
| Viewport / search | `AccordionModel` stores the full event-built slice and selection index. Main Up/Down moves accordion selection; it does not scroll transcript. `RenderView` keeps the last lines when given a height, with no durable EntryID anchor. There is no general transcript search API. |
| Full-history read cost | `PreparedSession.Snapshot()` clones the complete durable session; there is no paginated transcript-window or indexed search interface at this baseline. Passing the complete history to a virtualized TUI would still duplicate unbounded history in memory. |

The `done` event currently carries the final answer as status content. A streamed complete `message` is skipped after incremental rendering, but `done` is separately mapped to status and can render the same text again. Completion status is not answer content: `done` must update run status only. A stream gap is also not recoverable by replaying observed events; `GapCount` must remain visible until a same-handle durable snapshot reconciles history. `TurnRunner.RunTurn` can return while its owner is still `cleanup_pending`; the result retains a live `StatusHandle`, but the current app exits when its per-turn event stream closes. The UI lifecycle must keep the status visible and observe later snapshots within R1's bounded cleanup contract, rather than equating stream closure or runner return with quiescence.

The local path is the target here. The optional remote ACP adapter is a different event source and cannot be presented as having this local durable-session projection unless it receives the same reviewed identity/commit contracts.

## Minimal target seam

1. Prepare or resume one physical durable session before the Assembly publishes a runnable agent. Capture its coherent startup snapshot once and derive Agent history, the navigation tree, and the initial transcript input from that same snapshot. Do not call `loadSessionHistory`, `BuildFromStore`, or open a second JSONL writer for this configured durable path. A run's `SessionRunCommitSink` still captures its own coherent run-start view, as required by R2.
2. Seed `AgentImpl` history from `snapshot.PublishedView.Messages`. Build the slash/navigation tree with `BuildFromSnapshot(snapshot)` only. After a successful terminal refresh, refresh that existing navigation projection from the same updated snapshot so its cursor follows the exact durable active leaf; do not append UI-created rows or choose a leaf by timestamp. Show the active physical session and branch identity from the snapshot; the selected branch is display/recovery context, not a new branch-browser or branch-switching feature.
3. For every turn, acquire a lease on that same prepared handle, construct the R2 `SessionRunCommitSink`, and invoke `TurnRunner.RunTurn` with `core.WithRunCommit` and the exact physical session/workspace binding. Preserve run-owner lease ownership: return a pre-owner construction/claim failure's borrow exactly once; once handed to the owner, REPL must not close that lease itself. Do not replace the prepared session between turns.
4. Give `BubbleteaApp` a value-only initial transcript snapshot and an explicit refresh/update path. A small CLI-to-TUI DTO should carry durable `EntryID`, selected `SessionID`/`BranchID`, canonical `core.AgentMessage`, and optional exact run/assistant-ordinal/tool-call/action metadata. Iterate `PublishedView.Messages` paired positionally with `SourceEntryIDs`; join to `DurableEntries` by that exact source ID for row type and validated identity metadata. Never reconstruct message history by replaying physical journal order. Keep journal-only intent/execution/checkpoint rows out of transcript messages.
5. Render EventStream data as a provisional overlay. Preserve the available `ToolCalls`, stdout/stderr stream, error flag, usage, and event-gap state. Do not use event timestamps, rendered text, position, or `ToolCallID` alone as a durable key. Exact live per-call grouping needs the R1 run/event correlation seam for `RunID + assistant/group transcript ordinal + ToolCallID`; if the seam is absent, show an uncorrelated provisional event or explicit limitation instead of guessing. After terminal commit, snapshot the same prepared handle, replace matching provisional rows using returned durable source identities, and refresh the navigation tree from that snapshot. Keep observing the retained status handle when cleanup continues past `RunTurn`; show “complete · saved” only when R1 outcome is success, execution is quiescent, and R2 terminal sync succeeded.
6. Keep typed durable compaction rows distinct from any provider-history summary message. The row type and EntryID come from its durable record, not `Message.Role`; the summary projection is untrusted model context, not a new user prompt. A source tree cursor may include journal/checkpoint entries that do not appear as transcript rows.
7. R8's viewport consumes keyed rows and exposes a bounded visible window plus overscan/cache. Use durable EntryID as the stable scroll anchor once a row is published. Search may cover only the loaded window and must say so until R2 provides paginated full-history reads/search; do not copy an entire session into the TUI to simulate virtualization. Full-history search is unavailable until that read contract exists.

The existing `core.RunCommitSink` methods acknowledge durable operations with `error` only. Final snapshot reconciliation supplies actual EntryIDs after terminal sync, but it cannot give the live TUI a per-action EntryID/ActionID immediately after each receipt. If R5 requires a saved badge before terminal completion, R2/R1 must add a narrow typed post-commit observation that carries the actual persisted identity; the TUI must not calculate stable sink IDs from inputs. This does not require a second persistence writer or an event-sourced reconstruction path.

## Dependency order and independent TDD

**Can start independently:**

- Pure TUI row/viewport primitives with caller-supplied stable keys: anchor preservation, bounded visible range/overscan, focus and selection preservation through append/resize, and a window-limited search result. Tests can use synthetic immutable rows; no R2 feature or product capability is implied.
- TUI presentation rules that do not mint authority: a `done` event never creates answer text; provisional/durable labels remain separate; event gap renders as incomplete; existing safe cell helpers remain the only width/clipping primitives.
- CLI projection unit tests over hand-built `SessionView`/snapshot DTOs: exact positional source-ID mapping, metadata joins by EntryID, typed compaction, branch isolation, repeated ToolCallID across distinct run/assistant ordinals, and refusal to infer from timestamps or output text.

**Requires R2/Assembly wiring first:**

- Real startup hydration and restart/resume from one `PreparedSession`; strict error propagation on prepare/snapshot/tree failure; selected physical identity and active branch in status.
- Canonical run binding and no legacy second-write after the turn; same-handle final snapshot refresh and reconciliation of provisional rows. The existing `durableSessionManager` and session run-commit adapter are present at a44 but are not connected to default REPL/Assembly.
- Per-action durable badges/ActionID links if shown before terminal sync; the current error-only sink interface does not return those mappings.
- Bounded memory and full-history viewport search. R2 must expose a same-handle paginated read/search contract, or R8 must state the narrower loaded-window behavior. `Snapshot()` is a complete snapshot, not a page.

R5 owns the durable transcript handoff, live provisional overlay, run/interaction status, and default CLI acceptance. R8 owns generic viewport, search over whatever source R2 supports, Unicode/cell-safe long rendering, performance, resize behavior, and the platform matrix. R5 approval-detail scrolling and existing R8 cell helpers do not satisfy the general viewport requirement. No new task, memory, web, or branch actions are part of either slice.

## Acceptance and verification handoff

Add meaningful tests before implementation. Test the production bridge/model and the real prepared-session path, not only a reducer assembled from invented display state.

1. **Projection tests:** `TestTUITranscriptRestoresSelectedBranch` (active selection only; no new branch action), `TestTranscriptProjectionUsesPublishedSourceIDs`, `TestTranscriptProjectionKeepsCompactionTyped`, `TestTranscriptOccurrenceIdentityScopesRepeatedToolCallID`, `TestTranscriptOpenJournalDoesNotReplacePublishedView`, and `TestTurnDoneDoesNotDuplicateAssistantText`. Use a real `PreparedSession` for end-to-end hydration and terminal refresh; compare every visible durable row and ID to `Snapshot().PublishedView`/`SourceEntryIDs` plus its exact durable metadata. Cover empty history, corrupt/mismatched source mapping, repeated ToolCallID across two assistant groups, interrupted/unknown outcome, an open journal newer than the published view, and tool payloads containing nested JSON args.
2. **Runtime/UI tests:** `TestTUIEventProjectionPreservesToolArgs`, `TestTUIEventGapMarksProvisionalViewIncomplete`, and run-state tests exercise the actual bridge and status handle. Assert the bridge never supplies a fabricated run/entry/action ID, `done` changes status only, terminal-sync failure cannot render saved/success, and a same-handle snapshot replaces rather than duplicates provisional rows.
3. **Viewport tests:** verify 10,000 uniquely keyed rows, duplicate text with distinct EntryIDs, anchor stability on append/resize, focus/selection retention, bounded materialized rows/cache, and loaded-window search semantics. Include CJK, combining marks, emoji/ZWJ, SGR, safe OSC-8, and control-sequence payloads. Measure rendering over increasing history sizes and streamed chunks; no full prior-transcript repaint/copy per token. Full-history search must be tested only if the R2 reader/index is available.
4. **Default CLI PTY journey:** run the actual local CLI child process with temporary config/session/workspace-index roots and a deterministic local fake provider. Submit a prompt, observe a tool call with args/output and terminal receipt, complete the turn, exit, reopen the exact physical session, and confirm the displayed rows and IDs equal the prepared snapshot without a second user/assistant write or duplicate final text. Inject terminal sync failure and event loss; assert explicit error/incomplete state and no saved-success claim. Keep HOME/XDG/config paths isolated so user config is not read or changed. Exercise live resize at 60/80/120/200 columns, including a long stream and approval/HITL modal; assert raw terminal mode is restored. This complements the already accepted line-editor PTY slice.
5. **Test command discipline:** first verify planned test names exist, then run targeted suites; zero matched tests is not evidence. Suggested sequence after implementation:

   ```sh
   rtk go test -list 'Test(TUITranscript|TranscriptProjection|TranscriptOccurrence|TranscriptOpenJournal|TurnDone|TUIEvent|TranscriptViewport)' ./internal/tui ./internal/cli ./internal/session ./internal/core
   rtk go test ./internal/tui ./internal/cli ./internal/session ./internal/core -run 'Test(TUITranscript|TranscriptProjection|TranscriptOccurrence|TranscriptOpenJournal|TurnDone|TUIEvent|TranscriptViewport)' -count=1
   rtk go test -race ./internal/tui ./internal/cli ./internal/session ./internal/core
   ```

   The PTY journey must run against the default CLI entrypoint in its own subprocess test and retain raw input/output plus exit/terminal-restoration evidence. It is not replaced by `TestRawMode_PTY_RoundTrip` or library-only `BubbleteaApp` tests. Root owns any broader integrated repository verification.

Passing this handoff's tests would close only the reviewed R5 transcript and R8 viewport slices they exercise. It would not by itself close all R5 interactions, R8 cross-platform/accessibility gates, CLI feature parity, or overall R2/runtime release.
