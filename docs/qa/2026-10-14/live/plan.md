# Dot / Magpie / 本机 Codex 真实验收计划

日期：2026-10-14。起始源码 `e0493e5`，该提交已推送到远端 develop；上轮模拟验收保留在父目录，本目录只记录真实上游调用。

三个 GPT 6 Luna Max 子代理分工：Magpie 安装及真实上游验证；Dot PTY 多轮执行与截图；独立工具、PPT、压缩及证据审查。主代理负责场景规划、逐轮多角度审查、问题合并修复、全量回归及远端推送。

## 验收场景

| 场景 | 可执行验证 | 证据 |
| --- | --- | --- |
| 安装、启动和账号接入 | 官方发行校验、真实 loopback listener、健康响应、已登录 Codex discovery、实际推理成功；原有 Codex 配置哈希保持一致 | 版本/SHA、响应 ID、真实 token 用量及 Magpie provider/model 路由 |
| Dot 流式多轮对话 | 真实 binary、PTY 与 Magpie 请求；每轮输入及输出关联，回复含当轮随机事实 | 请求响应元数据、原始 PTY、当前终端 viewport 截图 |
| 多种工具 | read / ls / grep / write / edit / bash，工具回执与调用 ID 一致、真实文件和命令副作用正确 | 请求里的 tool receipt、traces、文件字节与哈希 |
| 审批拒绝与允许 | 先拒绝写入或 Bash，文件保持不存在；下一轮批准后产生对应副作用 | 审批界面、按键记录、拒绝回执、实际副作用 |
| PPT 生成与下一轮修改 | 模型实际调用工具生成 editable PPTX，随后新对话修改；检查 OOXML、页数、内容、修改 nonce、实际渲染 | 工具代码及执行、v1/v2 文件、独立检查和渲染截图 |
| 长任务与补充指令 | 真正启动的 Bash 运行中提交 follow-up，生产 queue ACK 和后续模型请求对应；完成副作用与回复正确 | 实际启动文件、事件/请求、运行中与完成截图 |
| 取消与继续 | 实际 Esc 取消后无延迟副作用或自动续请求，新输入可正常完成 | PTY、请求计数、延迟文件检查 |
| 上下文压缩 | 真实多轮累积内容触发生产 compaction；不伪造历史、替换响应或手动删上下文；压缩后仍能回答早期关键事实及最新指令 | compaction 日志、前后上下文/真实请求、记忆断言及截图 |

## 每轮闭环

1. 保存输入、源码版本、隔离配置、实际 provider/model、请求与终端关联。
2. 从协议、界面、工具副作用、审批、会话/上下文、资源生命周期及产物质量核对结果。
3. 问题分为产品缺陷、网关/依赖问题、测试装置问题及模型未遵循要求；保留失败证据。
4. 先复现再修复，分配明确文件归属；独立审查后整合，并复跑受影响案例。
5. 所有场景通过后运行适用的全量门禁，再提交并推送；未通过或未测项目不记为通过。

## 真实性与执行边界

- Magpie 使用本机已有 Codex 登录，Dot 在独立 HOME/cwd/config 中只连接本机网关。认证材料不输出、截图或提交。
- 如需观察请求，代理只能透明转发真实网关响应，不生成或替换模型回复。模型目录不能代替已完成推理的可用性证据。
- 截图注明 native app / real PTY rendered by xterm.js / PPT render 的实际来源。
- 可为测试配置较小上下文预算以合理触发生产压缩，记录确切设置，不把该压力设置称为默认真实窗口。
- PPT 必须由 Dot 发出的真实工具调用生成，审查代理只准备输入和验证脚本，不能代作产物。
- 如测试关闭 OS sandbox，明确记录；工具审批与 OS 隔离分别验收。保护 Makefile、CI、lint 规则及 infra 规划文件。
