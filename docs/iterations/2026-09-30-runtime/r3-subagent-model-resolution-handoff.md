# R3 SubAgent model-resolution handoff

Status: narrow builder-candidate handoff for R3-BLD-01, checked against `develop` at `87346654853082d95381a2b449c91324284d9b0b`. This records a bounded model-resolution gap; it does not change the protected task ledger, close R3, enable a provider protocol, or introduce a credential policy. Independent R3 review remains a separate gate.

## Source finding

`internal/cli/assemble.go:1431-1435` builds the CLI SubAgent factory with `llm.NewProviderRegistry()` instead of the `cliModelResolver` already built for the Assembly. `internal/core/real_subagent_runner.go:87-100` uses `ProviderRegistry.GetModel` whenever `SubAgentConfig.Model` is non-empty. A fresh registry contains only its default Eino provider (`internal/llm/registry.go:37-55`); it does not carry the Assembly's provider snapshot or scoped `config.AuthChain`.

The Assembly resolver owns one immutable provider snapshot and its scoped credential chain (`internal/cli/assemble.go:1742-1764`). `buildPrimary` and `buildInteractive` resolve through that snapshot; `build` obtains an exact `CredentialRef`, resolves the candidate, and calls `ResolvedModel.Build` (`internal/cli/assemble.go:2007-2062,2115-2130`; `internal/llm/model_resolver.go:132-168`). This is the existing path that binds provider, protocol, origin, and credential before constructing a guarded adapter.

The real runner's creation seams cannot supply the execution context: `DefaultSubAgentFactory.Create` explicitly ignores its `context.Context`, and `SubAgentRunnerFactory` accepts only `SubAgentConfig` (`internal/core/factory.go:52-60`; `internal/core/subagent.go:74-77`). The durable-parent rejection instead runs at the beginning of `realSubAgentRunner.Run(ctx)` (`internal/core/real_subagent_runner.go:49-55`), and `ResolvedModel.Build` can return a non-nil cleanup together with an error (`internal/llm/model_resolver.go:125-133`). Therefore the runner should capture the builder as a dependency at construction, invoke it only inside `Run` after the durable and depth guards with that run's context, and own the returned cleanup until the run has drained the child result.

The empty-override path already inherits the Assembly model. The gap is the non-empty override: the CLI child resolves it outside the Assembly's provider/auth authority. Current assembled SubAgent tests cover parent-model use, child approval, Plan transition, and stale prepared-tool replacement (`internal/cli/r4_subagent_prepared_policy_test.go`), but do not cover a child model override through the Assembly resolver and its credential scope.

## Bounded contract

1. Preserve `SubagentTask.Model` / `SubAgentConfig.Model` as the optional model-name override. A trimmed empty value inherits the exact parent `s.model` pointer and does not rebuild it. For the current CLI path, a non-empty value names a model on the Assembly's resolved primary provider, matching the existing same-provider `DefaultModelSelector.SwitchModel` behavior. Do not infer another provider from a bare string or add `provider/model` parsing in this slice; cross-provider child overrides need a separately reviewed identity contract.
2. Add an additive resolver-builder seam that is stored on the `realSubAgentRunner`, for example `type SubAgentModelBuilder func(context.Context, string) (llm.BaseChatModel, func(), error)` and `NewRealSubAgentFactoryWithModelBuilder(parentModel, builder, tools, opts...)`. The factory may capture the builder as a dependency when it creates the runner, but must not resolve or build a model there: `DefaultSubAgentFactory.Create` discards its context, and `SubAgentRunnerFactory` has no context parameter. In `assembleSubAgent`, provide a closure that calls `s.modelResolver.buildPrimary(ctx, s.rc, s.providerName, modelName)` and returns its model and cleanup. Do not pass raw keys, construct another provider registry, or add a second credential lookup path.
3. After `realSubAgentRunner.Run(ctx)` rejects a bound durable parent (and after its recursion-depth guard), trim and validate a non-empty override and call the stored builder with that Run's cancellable context, before constructing or dispatching the child LoopAgent. Fail closed if the builder is missing, returns an error, or returns no model. Use a typed unavailable error for a missing builder. Never fall back to the parent model, default Eino provider, or legacy registry path after an override-resolution failure in the builder-enabled CLI factory. If the builder returns both cleanup and an error, retain and defer that cleanup immediately, as `ResolvedModel.Build` can return cleanup alongside an error. Otherwise preserve the returned cleanup and run it exactly once from `Run` after the child stream and result have finished, including error and cancellation paths; this keeps cleanup owned by the Run that owns and drains the child work.
4. The resolved model must remain a resolver-issued guarded candidate through the existing model middleware chain and the child's `LoopAgent`. The Loop must continue to derive candidate identity and metadata from that same candidate for `CandidateProposal`, `PreparedRequestPlan`, and `OperationDispatchAuthority`; do not unwrap it to a raw provider adapter or create a second dispatch authority. Keep `s.tr` as the child's tool source so prepared approval, Plan, registration-generation, and frozen-invocation checks remain shared with the parent Assembly.
5. A resolver/build failure may retain its typed cause for internal classification, but its rendered `SubagentResult.Error`, tool result, event, log, or trace must not expose an API key, auth-file content, endpoint query, or raw provider body. Add or use a typed safe presentation wrapper whose `Error()` is generic and whose `Unwrap()` preserves internal classification; do not assume the model-response sanitizer covers failures before streaming, and do not store credential material in SubAgent task/config state.
6. Preserve the durable-run boundary unchanged. `DefaultSubagentDispatcher.Dispatch`, `realSubAgentRunner.Run`, and the Core durable child check continue to reject a child under a bound durable parent with `ErrRunCommitChildUnsupported`, before model resolution, child creation, or provider dispatch. This handoff does not add child session or run-commit support.

This is an R3 provider-resolution slice only. It does not change retry/failover policy, candidate selection policy, sampling precedence, native protocol support, the prepared tool policy, or R2 durable-session semantics.
