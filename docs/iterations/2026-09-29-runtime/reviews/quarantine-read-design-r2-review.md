## Why the corrections close the earlier review

- **The whitelist and root ownership now match the code.** `assemble.go` passes `WithRegisteredPathWhitelist` only when `Sandbox.AllowedPaths` is nonempty ([`assemble.go`](/Users/pengjunchen/Documents/github/go-cli/internal/cli/assemble.go:963)); default tool registration only attaches that whitelist to readers in the same nonempty case ([`builtins.go`](/Users/pengjunchen/Documents/github/go-cli/internal/tools/builtins.go:104)). `PathWhitelist` treats an empty list as unrestricted ([`bash_sandbox.go`](/Users/pengjunchen/Documents/github/go-cli/internal/tools/bash_sandbox.go:83)). The design now says this state cannot earn a quarantine exception, explicitly adds `assemble.go` as an owner, and requires the canonical workspace root to come from the same durable-manager capture as its ID. That capture currently canonicalizes and hashes the root but discards the path ([`durable_session_manager.go`](/Users/pengjunchen/Documents/github/go-cli/internal/cli/durable_session_manager.go:64)); the proposed runtime option and root-to-binding flow close that gap without a second `Getwd`.

- **The exception is limited to readers with existing joined completion evidence.** Current trusted registration assigns `CompletionInlinePipelineJoined` to concrete `ReadTool` and `LSTool`, while `GrepTool` and `FindTool` do not receive it ([`trusted_registry.go`](/Users/pengjunchen/Documents/github/go-cli/internal/tools/trusted_registry.go:293)). The design now authorizes only `ReadTool`/`LSTool` and explicitly leaves Grep/Find on ordinary fail-closed quarantine behavior. It asks for no optional completion feature for those tools.

- **Proof authority and no-intent receipts stay separate.** The proof is opaque, issued only from the real private `*preparedInvocation`, and binds its captured identity, effects, schema and argument digests, call ID, generation fence and actual whitelist roots. The index rederives `WorkspaceID` from the runtime canonical root; root and proof remain runtime-only and are removed before persisted comparison or encoding (design lines 15, 19-21). No public identity/effect DTO or scope fingerprint alone grants the exception. Separately, the session sink validates no-intent receipts before writing rows or entering the index and rejects overlap between receipt and intent call IDs ([`run_commit.go`](/Users/pengjunchen/Documents/github/go-cli/internal/session/run_commit.go:171)). Its validator requires `ActionID == ""`, `DispatchStateNotDispatched`, an exact matching assistant tool call, and only `error` or `interrupted` outcomes; `unknown` is rejected ([receipt validator](/Users/pengjunchen/Documents/github/go-cli/internal/session/run_commit.go:1350)). The sink constructs index actions from `Intents`, not `KnownReceipts` ([dispatch construction](/Users/pengjunchen/Documents/github/go-cli/internal/session/run_commit.go:320)). The revised design correctly allows a valid denial alongside an independent safe-read intent while denying any proof borrowing or marker/resolution effect from that receipt. Its acceptance criteria test both the malformed/unknown case and the legitimate known-error case before executors run.

- **The replay, resolution, and generation boundaries remain sound.** Under its workspace lock, `BeginDispatchBatch` syncs the open journal before using its locked snapshot, treats `AlreadyExists` as no permit, and only appends a new marker after the unresolved-marker gate ([`workspace_index.go`](/Users/pengjunchen/Documents/github/go-cli/internal/session/workspace_index.go:238)). The proposed proof check is per prepared action and must finish its generation snapshot before index append/sync; the final prepared dispatch commit remains the execution linearization point ([fence snapshot](/Users/pengjunchen/Documents/github/go-cli/internal/tools/prepared.go:97), [final dispatch commit](/Users/pengjunchen/Documents/github/go-cli/internal/tools/prepared.go:773)). Existing session paths acquire session ownership before index operations; recovery applies validated resolutions and inspects markers from that session-owned load path ([`durable_jsonl.go`](/Users/pengjunchen/Documents/github/go-cli/internal/session/durable_jsonl.go:163)). The index does not call into or open a session, so the proposed short fence snapshot under the index lock does not introduce a reverse lock path. A generation change after index commit still fails the final prepared commit and proceeds through the existing no-dispatch resolution path.

- **Historical unknowns remain distinct from new actions.** The design permits an unchanged complete historical `unknown` receipt to remain in a fresh below-budget provider request, while an `unknown` no-intent receipt in the current action batch fails session validation. The read exception never changes an older receipt or mutation marker. The recovery and failure criteria retain exact-action resolution, sync-failure closed behavior, and the rule that `AlreadyExists` cannot authorize replay.

No further design correction is needed for this handoff. Keep the implementation bounded to proof issuance for the attested `ReadTool`/`LSTool` path; do not expand it to Grep/Find in this change. No tests were run because this review checks the design and existing integration boundaries only.
