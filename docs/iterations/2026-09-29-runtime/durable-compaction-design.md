## 当前源码与边界

当前 RunCommitSink 已含 CommitCompaction；CompactionProjection 有 ExpectedHistoryRevision/Through/Summary，RunTerminal 有 Projections（internal/core/run_commit.go:120-132,270-292）。SessionView.Validate 保证 Messages 与 SourceEntryIDs 一对一、revision/source ID 唯一；SessionRunCommitSink 从 prepared snapshot 捕获 immutable `baseView`，随后按真实 SourceEntryID 或当前 run TranscriptIndex 映射 cursor 并 AppendAndSync marker（internal/session/durable_contract.go:18-60; internal/session/run_commit.go:49-95,853-918）。restore 在完整 source boundary 后派生 user-role summary 与 canonical suffix（internal/session/derive.go:230-280,368-390）。

当前 core 尚未把这些 seam 接起来：RunCanonical 的 terminal defer 以 nil projection list 调 CommitTerminal（internal/core/loop.go:372-435）；runCommitConsumer 没有 CommitCompaction 调用入口；durable consumer 下 Loop 会把实际 compactor 换成 unavailableRunCommitCompactor，触发时返回 ErrRunCommitCompactionProjectionUnavailable（internal/core/loop.go:907-920, internal/core/run_commit_consumer.go:20,867-872）。这条路径当前 fail closed，是已核实能力缺口。不能根据 session sink 单测声称 durable compaction 已接通。

Compaction 的组边界与摘要角色已有独立接受的内存层实现，不在本设计重写：groupTurnItems 校验 call/result ID 组；SummaryCompactor 保留真实系统消息，产生 RoleUser + IsCompaction 摘要；Loop 与 session restore 都用 UntrustedSummaryContext 包装派生摘要（internal/compaction/tool_groups.go:19-83, internal/compaction/summary.go:198-220, internal/core/loop.go:1091-1107, internal/session/derive.go:368-390）。旧 summary-system-role P1 已修复，不重新打开。

当前仍有必须封住的 handoff 缺口：

1. Loop 在工具处理后才调用 midTurnCompactor.CompactIfNeeded，首个 provider request 没有 preflight（internal/core/loop.go:905-925）。必须在每个 main-model request 前 compact eligibility/preflight。
2. durable `PublishedView` 已带 Revision/Messages/SourceEntryIDs，但 `session.EntriesToAgentMessages` 只返回消息；Agent clone/Submission 虽保留 canonical `ReceiptOutcome`，没有 per-item source; SystemReminderInjector prepend 无 source mark；Loop 两次转换又丢 ReceiptOutcome 和所有 source，继续生成 `msg-N`（internal/session/durable_contract.go:18-60; internal/session/context.go:182-194; internal/core/agent.go:136-146; internal/core/agent_history.go:43-48; internal/core/system_reminder_middleware.go:94-103; internal/core/loop.go:531-548,1050-1136）。仅给 messagesToTurnItems 补 receipt 无法恢复更早已丢字段。
3. Compactor 只返回 `[]TurnItem`；SummaryCompactor 知道 `cut` 却不返回 source boundary；UnifiedCompactor 的 LastStrategy 是 shared mutable value，不是该调用的返回事实（internal/compaction/compactor.go:117-124; summary.go:159-230; unified.go:93-113,148-197; midturn.go:153-190）。durable core 不能据 items 长度、内容或新 IsCompaction marker 猜 projection。
4. Factory 支持 configured summary/model 注入，但 CLI assemble 的条件排除了 `strategy == "summary"`，使此 assembled path 可落到 no-op summarizer（internal/cli/assemble.go:1603-1614; internal/compaction/factory.go:47-65; internal/cli/assemble.go:2164-2177）。需要组装层 RED 并为实际 summary call 计独立 dispatch。

5. 还必须封住现存的 loop 外 compaction 入口。当前源码中 `AgentImpl.Run` 在 `RunCanonical` 后更新 history，再无条件调用 legacy `CompactionHook`（`internal/core/agent.go:162-170,199-230`）；CLI assemble 无条件安装该 hook（`internal/cli/assemble.go:419-422`），hook 直接调用 `Compactor.Compact` 并回写 Agent history，既不提交 `RunCommitSink.CommitCompaction`，也不进入 terminal projection list（`internal/cli/compaction_adapter.go:21-49`）。`AgentImpl.Compact` 也直接复制 history、执行 hook、替换 history（`internal/core/agent.go:280-299`）。因此 bound durable run 必须完全绕过 post-run hook，不能让它在 terminal commit 后再调用 strategy/summarizer 或改写 history；non-durable Agent 保留现有 hook 行为。`AgentImpl.Compact` 对通过 durable source snapshot 绑定的 history 必须在调用 hook/strategy、summarizer 或复制/改动 history 之前返回 typed `ErrDurableCompactionUnsupported`。durable request 的 per-request preflight 是唯一 compaction 入口；不增加手工 projection 路径或 ledger。当前根集成快照尚不能声称 `/compact` 已有 durable guard：slash handler 本身会调用 `Agent.Compact`（`internal/cli/slash_handlers.go:106-118`）；4de967c durable CLI candidate 在 slash dispatch 前用 `durableHistoryMutationUnsupported` 拒绝 `compact`（`internal/cli/slash.go:244-249`; `internal/cli/durable_cli_session.go:31-35`），集成时必须保留该 guard，不把 `/compact` 改路由到手工 durable projection。

## 唯一持久化事实与最小 API

不增加 event store、compaction ledger、session 表、第二份 transcript 或新的 RunCommitSink 方法。复用现有 `RunCommitSink.CommitCompaction` 与 `RunTerminal.Projections`。core 生成 typed projection 并调用 sink；session adapter 仍是唯一把原始坐标映射到真实 entry ID/TranscriptIndex 并写 JSONL/index 的层。

**Metadata contract — one per item, runtime-only:** 在 `internal/llm/llm.go` 定义通用 `RuntimeMetadata` 并同时由 `core.AgentMessage`、`llm.Message`、`compaction.TurnItem` 持有；carrier 字段都标 `json:"-"`。metadata 至少包含 `ReceiptOutcome` 和 `SourceRef`，其 SourceRef 是以下 tagged union，验证时必须且只能有对应 kind 所需的字段：

```go
type SourceKind uint8 // SourceNone, SourcePriorPublished, SourceRunTranscript, SourceRunSummary, SourceEphemeral, SourcePendingRunInput
type SourceRef struct {
    Kind SourceKind
    RunID string           // required for RunTranscript/RunSummary/PendingRunInput
    HistoryRevision string // required for PriorPublished; equals this run's baseView.Revision
    BranchID string        // required for PriorPublished
    SourceEntryID string   // required for PriorPublished; exact real marker/message row ID
    PriorOrdinal uint64    // required for PriorPublished; zero-based ordinal in this run-start PublishedView
    PriorSourceCount uint64 // required for RunTranscript/PendingRunInput; immutable count of baseView.SourceEntryIDs
    TranscriptIndex uint64 // required for RunTranscript; exact canonical index assigned by this run's transcript writer
    Through SourceThrough // required for RunSummary created in this run
}
type SourceThrough struct { PriorHistoryCount, TranscriptCount uint64 }
type RuntimeMetadata struct { Source SourceRef; ReceiptOutcome string }
```

`SourceRef` is a validated tagged union: the fields required by its `Kind` must be populated (zero is valid for ordinal/index/count), and every field not selected by that `Kind` must be zero/empty. `SourceRunTranscript` requires `{RunID, PriorSourceCount, TranscriptIndex}`; `SourcePendingRunInput` requires `{RunID, PriorSourceCount}` and forbids a transcript index until append; `SourceRunSummary` requires `{RunID, Through}`; `SourcePriorPublished` requires `{HistoryRevision, BranchID, SourceEntryID, PriorOrdinal}`; `SourceEphemeral` and `SourceNone` carry no durable coordinates. The `ReceiptOutcome` value uses the existing canonical receipt strings and is copied from persisted truth; runtime metadata does not create a second outcome state.

`PriorPublished` includes a summary restored from an earlier run as one ordinary prior source item: `SourceEntryID` is that compaction marker's real ID and `PriorOrdinal` is its position in the current run-start view. Clear any old run-local `Through` during hydration; only a `RunSummary` created during the current run carries this run's source-through cursor. `Ephemeral` has no cursor. `PendingRunInput` is allowed only until the canonical writer commits the current user input, then it becomes `RunTranscript` with the writer-assigned exact index. Both tags carry the same immutable `PriorSourceCount` captured from the sink's run-start `baseView.SourceEntryIDs`; it is not recomputed from the current (possibly compacted) Agent history. `None` is for non-durable history; durable compaction rejects source-bearing items with missing/invalid tags.

The session/core handoff is one typed API on the same run-bound sink, not another persistence abstraction:

```go
type RunCommitCompactionSource interface {
    CompactionSourceSnapshot() (CompactionSourceSnapshot, error)
}
type CompactionSourceSnapshot struct {
    Revision string
    BranchID string
    Messages []AgentMessage // immutable clone of the sink's captured baseView.Messages
    SourceEntryIDs []string // same baseView.SourceEntryIDs, one-to-one with Messages
}
```

`SessionRunCommitSink.CompactionSourceSnapshot` returns a defensive clone of its existing `baseView`. `AgentImpl`/durable CLI hydration uses this one snapshot to attach `{Revision, BranchID, SourceEntryID, PriorOrdinal}` to each message and preserve canonical `ReceiptOutcome`; `CloneAgentMessages` deep-copies the value metadata, and `Submission.History` carries it without parallel length-based arrays. The prompt and REPL call sites must hydrate from the snapshot returned by the same sink before invoking the Agent; never combine an independently loaded history with the sink's cursor snapshot. At Loop entry validate revision, branch, ordered source IDs, message/source uniqueness, and all tag shapes against that capability. A new durable turn rehydrates summaries from the latest PublishedView so an older summary becomes `PriorPublished` by its real marker ID; it never reuses a prior run's Through.

The core API on the Agent is `SetHistoryFromSourceSnapshot(snapshot CompactionSourceSnapshot) error`: it first runs `Validate`, stores the immutable `priorSourceCount := uint64(len(snapshot.SourceEntryIDs))` on `AgentImpl`, attaches per-item source metadata by the view's one-to-one positional mapping, validates each runtime receipt copy equals `AgentMessage.ReceiptOutcome`, then calls the same deep clone path used by `SetHistory`. `AgentImpl.Run` marks only the newly appended user input `PendingRunInput{RunID, PriorSourceCount: priorSourceCount}`. At canonical append, the core transcript writer copies that exact count and adds its assigned index as `RunTranscript{RunID, PriorSourceCount, TranscriptIndex}`; subsequent current-run rows use the same captured count and their own exact writer-assigned index. The sink validates and persists those exact transcript coordinates. No layer derives the prior count from the current `Agent.History` length or compacted item positions. Thus `Submission.History` contains the metadata through the complete Agent clone path; no future builder needs to invent a parallel indexing scheme.

`SystemReminderInjector` sets `Source.Kind=Ephemeral` on every injected AgentMessage. Loop marks its dynamic system prompt Ephemeral too. They can participate in the prompt/compactor but do not advance or enter durable source coordinates. Agent history clone, Submission construction, and every message conversion must preserve the value metadata. On existing canonical rows, `AgentMessage.ReceiptOutcome` remains the persisted truth; hydration copies it into RuntimeMetadata and validation rejects disagreement. `llm.Message.Runtime` and `compaction.TurnItem.Runtime` are `json:"-"`; provider encoders use explicit protocol DTOs and do not serialize these tags. `messagesToTurnItems` copies Runtime/ReceiptOutcome; `turnItemsToMessages` copies source tags back and applies `UntrustedSummaryContext` exactly once only to a newly produced user-role summary.

Compaction becomes a typed per-call API, not an output slice plus shared `LastStrategy` lookup:

```go
type NewProjection struct {
    Summary string        // exact unwrapped summary body in the new IsCompaction item
    Through SourceThrough // exact boundary computed from tagged input items at this call's cut
}
type CompactionResult struct {
    Items []TurnItem
    Strategy Strategy // exact winner for this invocation
    NewProjection *NewProjection // nil for Micro/Truncating/no new summary
}
```

Each strategy's `Compact` and `MidTurnCompact` return this result. `SummaryCompactor` computes `Through` from the exact `items[:cut]` it chose by validating and consuming their `SourceRef`s, then returns `Summary` equal to the resulting new IsCompaction item's `Content` (post clamp/placeholder policy but before untrusted wrapper). `UnifiedCompactor` returns the winning subcall's items/projection/strategy atomically; `LastStrategy` may remain telemetry only and never supplies projection facts. Micro-only placeholder and Truncating-only drop results have no NewProjection and are typed unsupported in durable mode.

Keep request-history integrity separate from compaction eligibility. `ValidateRunRequestIntegrity(items)` validates the runtime source tags and existing ToolCallID group structure before each main-model request; it rejects missing/open/malformed groups and missing/duplicate/reordered source refs, but permits a complete, closed historical `ReceiptOutcomeUnknown` group as unchanged context. This request gate is not action authority and never authorizes replay. Only a fresh user operation may pass such prior history to the main model; an unresolved unknown action created during the current operation still blocks retry/continuation under the operation/replay authority.

Only after request integrity passes and the current request is known to exceed the budget does the durable Loop call `ValidateCompactionEligible(items)`, before dispatching Micro, Summary, or Truncating and before any direct durable strategy entry or Summarizer call. It performs the same integrity checks, then rejects unknown receipts before any strategy can summarize, placeholder-rewrite, or drop them. Because the existing strategy API does not expose a stable planned cut before Unified can try Micro, the durable gate conservatively checks the complete candidate vector; it therefore rejects before the summarizer whenever an unknown group would be in the selected summary region, without adding a separate planner API. Known error/interrupted outcomes remain intact. A below-budget request does not call the compactor or summarizer and forwards a valid historical unknown group unchanged. Summary/Unified failure that degrades to Truncating still reports its exact strategy and any summary operation already performed.

At each real main-model request, the Loop order is: bind/validate the one run snapshot; commit and sync current input/steering/follow-up as canonical rows while stamping their exact writer-assigned `TranscriptIndex` and the captured `PriorSourceCount`; finish dynamic tool filtering; build prompt messages with source metadata; run `ValidateRunRequestIntegrity`; estimate request size. If it is within budget, send the unchanged source-backed history (including any complete historical unknown receipt) without invoking a compactor or summarizer. If over budget, run `ValidateCompactionEligible` before the compactor's first strategy; then validate the exact result and suffix; form `core.CompactionProjection{ExpectedHistoryRevision: snapshot.Revision, Through: result.NewProjection.Through, Summary: result.NewProjection.Summary}`; call `CommitCompaction` and await append/sync/refresh success; append the exact projection to the terminal projection list and only then use `result.Items` for the main request. Source/input sync failure prevents both summary and main calls. Summary generation may occur before CommitCompaction; if marker sync then fails, its separate Summary operation remains accounted but the next main-model dispatch is zero and no success terminal ack is written.

The persisted projection stores the raw summary body only as the existing compaction marker; it creates no ordinary user transcript/input row. After marker sync, the new PublishedView must be exactly one user-role untrusted summary plus the same source-backed suffix accepted by the live result. The live prompt and restore each apply `UntrustedSummaryContext` once; source-less dynamic prompt/reminder messages stay ephemeral and do not appear in either durable suffix or cursor.

The existing schema represents one new summary replacing a source prefix, followed by an unchanged source-backed suffix. A durable result is unsupported unless it has exactly one new IsCompaction summary matching `NewProjection.Summary`, its runtime `RunSummary.Through` matches that projection, and every source-backed suffix item after that boundary is unchanged from its exact input value and metadata. Verify suffix integrity independently by SourceRef key and deep value equality (including role/content/tool IDs/calls/receipt/content blocks); this check never selects or guesses the boundary. If Unified's Micro stage changed any item left in that suffix, return typed unsupported before CommitCompaction and before the next main-model request; do not restore original suffix for durable restore while sending a placeholder to the live model. Ephemeral system inputs are excluded from projection/suffix persistence. This keeps the live prompt and PublishedView projection aligned.

## Source provenance：包括同一 run 多次压缩

Cursor 永远在当前 run-start 坐标空间：`PriorHistoryCount` 是该 run 捕获的 PublishedView 前缀个数；`TranscriptCount` 是本 run canonical transcript 中从 TranscriptIndex 0 起被覆盖的前缀数。若 `TranscriptCount > 0`，`PriorHistoryCount` 必须等于 baseView 的全部 source 条数。每个 `SourceRef` 先验证 `{Revision, BranchID, SourceEntryID, PriorOrdinal}` 或精确 `TranscriptIndex`; sink 再仅用自己捕获的同一 `baseView.SourceEntryIDs` 和已同步的本 run transcript rows 计算真实 `CompactedThroughEntryID`。source gap、重复、错序、revision/branch mismatch、cursor 越界或非闭合 group 都 fail closed。任何内容比较只允许用于后述 suffix integrity check，不能发现/重建 source ID 或边界。

`SummaryCompactor` 的边界算法只读 tagged provenance：遍历其精确选中的 cut，忽略 `Ephemeral`，要求 prior item 的 ordinal 从 0 连续；RunSummary 可将 cursor 前进到其同 run 保存的 `Through`；run transcript index 必须等于当前 `TranscriptCount` 后递增。第一次进入 RunTranscript 时，`PriorHistoryCount` 取 core Agent 在 `SetHistoryFromSourceSnapshot` 时从 immutable `baseView.SourceEntryIDs` 捕获并复制到每个 run item 的 `PriorSourceCount`，并要求该值等于 sink 所持 baseView 的来源数；绝不从压缩后的 `len(items)` 或 `Agent.History` 得到 count。gap/重复/逆序/跨 run summary 都返回 typed unsupported，而非造 cursor。sink最终仍用其 baseView 与实际 durable transcript rows重新校验并落到真实 boundary ID。

同 run 多次压缩的具体规则：第一次 result 的新 summary 在其 runtime `SourceRef` 上保存当时 exact `Through`；被覆盖的后缀项继续带各自最初的真实 SourceEntryID 或 TranscriptIndex。第二次 SummaryCompactor 根据选中的第二个 typed cut 汇总其实际覆盖项的 `Through`；先携带 cut 中同 run `RunSummary.Through`，再按真实 source 顺序推进，不能从缩短后 `[]Message/[]TurnItem` 的位置/长度重编号。首次 summary 生成后、进入下一 durable run 时，它已由 session AppendAndSync 成一个真实 compaction marker；重新 PublishedView hydration 必须把它标为 `PriorPublished`，具体采用 marker `SourceEntryID` + 当前 prior ordinal，不得沿用旧 run cursor。

显式覆盖 reviewer 指出的 second-cut case：若第二次 typed result 在 suffix 保留了一个 `SourceKind=RunSummary` 的旧 synthetic summary，本版 `CompactionProjection` 无法让 marker projection 和 live suffix 表达无重复、无遗漏的 source prefix。core 将返回 `ErrDurableCompactionUnsupported`，不 CommitCompaction、不发下一 main-model request、不写 success terminal ack。RED 必须构造此 case；实现不得用 item 数量或 summary 内容尝试“修复”source range。上一 run 已持久化的 summary 是 `PriorPublished` 的真实 marker source，不触发这条 same-run synthetic suffix rejection。

terminal `CommitTerminal` 必须带与此前每次成功 `CommitCompaction` 完全相同且顺序一致的不可变 projection list。若 append 可能已 sync 但 sink 返回 error，不推测成功、不 dispatch main model、不写 success ack；遵守现有 sink stable-ID/idempotency 与 RunOwner policy，不新建 projection ledger。

**Fence the legacy and manual entrypoints:** the durable binding recorded by `AgentImpl.SetHistoryFromSourceSnapshot` is the discriminator for these guards. In a bound durable run, `AgentImpl.Run` skips its post-terminal `CompactionHook` completely; the per-request preflight above is the sole durable strategy/summarizer path. `AgentImpl.Compact` on bound durable history returns the typed unsupported error before hook invocation, strategy/summarizer calls, or history copy/mutation. Non-durable runs and direct non-durable `Compact` retain their legacy behavior. The durable CLI `/compact` command remains rejected before slash-handler dispatch by the 4de candidate guard; preserve that guard when integrating the candidate. Do not route the command through a second/manual call to `CommitCompaction` or any alternative projection path.

## Unknown 与 pending 输入

Closed tool groups still use the existing ToolCallID pairing algorithm. A complete prior-run `ReceiptOutcomeUnknown` with its terminal RoleTool row is structurally valid history: a new user operation below budget may send it unchanged to the main model, with zero summary calls and no automatic re-execution of the old action. It is not evidence that a current-operation action is safe to retry or continue after; same-operation unknown remains denied by operation/replay authority.

Unknown is not compaction-eligible. On an over-budget request, the compaction gate rejects it before Micro, Summary, Truncating, Unified strategy dispatch, or any Summarizer call; no placeholder, summary, or truncation may transform/drop it or make it look known. The gate is conservative across the entire candidate vector until a typed strategy plan can prove a smaller unaffected region. Missing receipts, open assistant groups, duplicate/mismatched receipts, and malformed source groups fail the request-integrity gate as well as compaction. Runtime `ReceiptOutcome` flows from `PublishedView.Messages` through Agent clone/Submission, `llm.Message.Runtime`, `TurnItem.ReceiptOutcome/Runtime`, and back after compaction; known error/interrupted outcomes retain their original value. Rejection preserves canonical transcript/journal and causes zero summarizer call, zero projection commit, and zero next main-model dispatch.

R2 quarantine's trusted scoped-read exception is a prerequisite for executing any read proposed from this fresh request: the action's read-only effect and enforced path scope must both be positively proven. Current `WorkspaceQuarantineIndex` denies all new actions while the unresolved marker is active (`internal/session/workspace_index.go:274-278`); this design does not claim that safe-read admission is already implemented. Until the R2/R4 scoped permit exists, the missing proof keeps reads denied, and mutations remain denied even after the permit is added. The fresh main-model request may still receive unchanged historical context below budget; it does not bypass tool admission.
