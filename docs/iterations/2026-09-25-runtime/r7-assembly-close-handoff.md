## Minimal shutdown contract

1. `AgentAssembly.Close(ctx)` is single-flight and idempotent. The first call immediately closes admission on the exact guard shared by Harness and TurnRunner. The close request remains in force if the caller context is already canceled or expires. Calls made after the fence receive the typed closed-admission error; a run claim that linearized before the fence remains owned by R1.
2. Add one narrow close-capability on `DefaultRunSlotGuard`: `CloseAdmission() <-chan struct{}` atomically closes admission against `ClaimRun` and returns the guard's stable idle signal. The channel closes when the current claim has been released (or immediately if the guard was idle). This reuses the existing R1 claim/release lifecycle and gives `Close(ctx)` a simple bounded wait; do not poll status or add another owner registry.
3. A caller deadline is a waiter deadline only. Timeout returns a typed `cleanup_pending` error/report; it does not cancel the R1 owner, clear its claim, release an R2 lease, or run model/session cleanup while the owner may still use those resources. The same close owner remains reachable and continues from the same phase. A later `Close` joins that owner; it does not start a duplicate close sequence.
4. Once the guard's idle signal closes, run the resource teardown in one documented dependency order: **durable session → extensions/skills → selected and small models → tracing**. The R2 owner has already synced its terminal outcome (or recorded unknown/error), returned its per-run lease, and released the guard before the manager closes the physical session. Extension shutdown must not write to a closed session; stop hot-reload/admission sources before invoking their owning extension shutdown. Keep event forwarding and tracing sinks alive while extensions can emit lifecycle events. Model selector close marks the selector closed, detaches the Loop model, and disposes each Assembly-owned generation once. Assembly ends its spans; the root invocation ends its root span and shuts down the exporter last.
5. Record resource disposers immediately at acquisition, not at a late final-cleanup append. Each resource has one owner and an observable terminal state. Close results aggregate terminal errors in one `ShutdownReport`; only a confirmed completion is marked closed. Setup failures join the original error with cleanup errors/pending status instead of discarding the cleanup result.

### Uncooperative close callbacks

The public caller context must not be passed as the lifetime context for the close owner. A single Assembly-owned serial close executor owns the operation and its resource handles; callers only wait for its result with their own contexts. A callback that ignores context cannot be forcibly interrupted. If it blocks past a caller deadline, `Close(ctx)` returns `cleanup_pending`, while the same executor retains the callback stack, the current resource, and all later dependencies; it must not advance or claim shutdown complete. When the callback eventually returns, that owner records its result and continues once. If it never returns, the truthful process result is pending/nonzero; no implementation can claim the callback stopped merely because the caller stopped waiting.

For cooperative close APIs, use one close-owner context/budget for the whole operation, not a fresh timeout per callback or a caller context that cancels the owner. Expiration may make a resource report pending, but the owner must keep that resource and its dependencies reachable until a completion signal proves the resource stopped. Do not create detached goroutines per callback or retry an in-flight callback from a later `Close` call.

## Minimal source ownership and API delta

- `internal/core/run_slot.go`: implement the R7-assigned `RunAdmissionCloser.CloseAdmission() <-chan struct{}` on the existing default guard. A claim must recheck the closed bit under the same mutex that publishes the active claim; a waiter racing the fence must wake and fail. Keep `RunOwner`, `RunClaim`, worker accounting, and R1 status semantics unchanged.
- `internal/cli/assemble.go`: add `AgentAssembly.Close(ctx) error` and a private single-flight close owner/report; preserve `Cleanup func()` as a deprecated compatibility wrapper. Change the Assembly-owned cleanup registration from raw `func()` to the smallest typed step needed to propagate error/pending and exactly-once state. Ensure initial and switched primary model cleanup have one selector owner. Keep the configured small model as a distinct owned resource.
- `internal/cli/durable_session_manager.go` / prompt / REPL: once R2 wiring lands, Assembly close calls the manager's close request only after shared guard quiescence and reports `PreparedSession.Close` errors. `CloseRunCommit` remains run-owner-only lease release.
- `internal/extension` and `internal/cli/assemble.go`: provide a real completion/error result for extension shutdown and stop reload sources before plugin shutdown. Do not hold selector/assembly state mutexes across plugin callbacks.
- `internal/llm/model_selector.go`: implement the accepted R3 mutation gate and selector close after shared admission drains; a busy/closed selector returns typed errors. Selector cleanup happens before model resources are reported closed.
- `internal/cli/prompt.go`, `repl_session.go`, `serve_cmd.go`: call `Close` explicitly with a bounded shutdown waiter and combine its error with command/HTTP shutdown errors. A defer may be used only to guarantee a fallback attempt, not to suppress the returned error.
- `cmd/cli/main.go`: preserve the existing single exporter owner. After the command has closed Assembly and ended the root span, run the existing bounded exporter finalizer and keep any close/finalizer failure nonzero.

No new general Runtime, independent admission gate, goroutine registry, or arbitrary-model reference counter is required. The guarantee is limited to the Assembly's shared Harness/TurnRunner path. Direct `LoopAgent.Run`, a retained bare `BaseChatModel`, or a caller-provided model reference outside Assembly remains that caller's quiescence responsibility.

## Gates and explicit limits

R1 supplies the truthful run-owner/quiescence primitive; this slice adds only the admission-close signal to the same guard. R2 still gates production session/sink/lease wiring. R3 resolver/catalog behavior, model mutation gate, and selector resource ownership are prerequisites to the model close step. R7 extension shutdown/error aggregation and root tracer/exporter ownership remain in their assigned slices. None of these interfaces proves that a non-cooperative callback can be stopped; it can only keep ownership truthful, bound callers, preserve dependencies, and return a pending/nonzero result.
