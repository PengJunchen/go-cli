# Durable compaction core and CLI hydration review

**Frozen design:** `docs/iterations/2026-09-29-runtime/durable-compaction-design.md`, blob `82f02f89b7ff2c7a4d6af1cc3eff4e168aac870f`.

**Target:** parent `25b88ba890f59be488e2ea5defbf09186baf873d`; core source `f3cac72f5b7771b76d5a718da22ea512b7fb0a12`; CLI/API source `a7adc76187d0ae6bacd123511b29ae1501b8b3b8`; reviewed HEAD/report `f1a6f992fac4cd4a0bc716e84d90054e0e1122a5`.

**Verdict: ACCEPT for the durable core plus prompt/REPL hydration slice.** The run-bound path preserves source coordinates through core compaction, syncs a typed summary projection before the next provider request, and rehydrates from the exact sink used by that run. This is not acceptance of all R3 design work; the follow-ups below remain open.

## Contract evidence

- `SourceRef.Validate` enforces the tagged-union field shapes, while `CompactionSourceSnapshot.Validate` enforces a one-to-one message/source-ID mapping. `validateDurableRequestSource` checks the captured revision, branch, real source ID, ordinal, run ID, source count, uniqueness, and complete prior-prefix coverage. `ValidateRunRequestIntegrity` rejects missing, duplicate, reordered, or malformed source refs and open tool groups. A closed historical `unknown` receipt can pass this ordinary-request gate; `ValidateCompactionEligible` rejects it before any over-budget strategy or summarizer runs.
- Durable compaction accepts only a typed summary winner with one matching run-local summary item and an advancing source cursor. The core resolves the cursor from tagged coordinates, rejects a retained source-backed prefix, and compares the ordered source-backed suffix by deep value equality, including receipt and content fields. The session sink maps the cursor through its captured `baseView.SourceEntryIDs` or committed transcript indices; it does not infer a boundary from message text. The repeated-text test uses distinct real source IDs and confirms the intended boundary.
- `LoopAgent` calls `commitCompaction` and waits for the sink result before dispatching the next model request. The real-sink test inspects the JSONL-backed session from inside the provider callback: the marker and exact boundary are already present, the PublishedView is the expected wrapped summary plus suffix, and reopening yields an identical view and source-ID list. A subsequent run hydrates the marker as `SourcePriorPublished` with the marker's actual entry ID and no prior run cursor.
- Summary framing is applied once in the live core conversion and once in the restored session projection, from the same raw stored summary. The loop's system prompt and injected reminders are tagged `SourceEphemeral`; core conversions preserve that tag, the summary compactor preserves system-role items in the live request, and source cursor calculation skips ephemeral items. Thus they remain in the live prompt without advancing the durable cursor or entering the restored suffix. This was confirmed by source inspection; the current real-sink test does not inject a reminder/system row.
- A second cut in one run keeps the original transcript coordinates in `TestDurableProjectionSecondCutKeepsOriginalTranscriptCoordinates`; a same-run synthetic summary left in the suffix is rejected. Bound Agents skip the legacy post-run hook, direct `Agent.Compact` returns `ErrDurableCompactionUnsupported` before copying or mutating history, and durable `/compact` is rejected before its handler. Prompt and REPL both call `bindRun`, hydrate through the returned sink, then execute with that same run context.

## Follow-ups

**P2 — legacy CLI conversion helpers still drop runtime metadata.** `internal/cli/interactive.go:104-127` omits `m.Runtime` when converting `AgentMessage` to `TurnItem`; `:131-160` omits `it.Runtime` on the reverse conversion. A minimal repro is to round-trip an `AgentMessage` carrying `SourcePriorPublished` through `turnItemsToMessages(messagesToTurnItems(...))` and assert its `Runtime` is unchanged; the assertion currently fails with a zero source ref. `field_mapping_test.go:18-60,64-110` checks tool calls, receipts, and other canonical fields but not runtime metadata. These helpers feed the legacy compaction hook and registry adapter. The supported durable prompt/REPL path currently bypasses them: hydration uses the bound sink, `AgentImpl.Run` skips the hook while bound, direct compact is guarded, and slash dispatch rejects `/compact`. No durable projection or reopen divergence is reachable through those built-in paths. Preserve metadata and add the round-trip test before reusing these adapters for durable history.

**P2 — configured `summary` assembly remains outside this slice.** In `internal/cli/assemble.go`, the small-model injection condition includes `unified` and `micro_first` but excludes explicit `summary`, even though the frozen design requires configured-summary RED coverage. `DefaultCompactorFactory.Create("summary")` can therefore construct a no-op summarizer; an over-budget durable request with that strategy fails closed before the main request. The default unified path is wired. This adjacent assembly change is still required before claiming the full frozen design.

The real-session integration covers one synced projection followed by reopen and a below-budget restored request. Repeated source coordinates and same-run summary rejection have unit coverage, but there is not yet a real-sink test that performs another compaction after reopen while retaining a closed unknown receipt and checking an ephemeral mandatory system/reminder row. The inspected source mapping and derivation paths support those cases; record this as missing integration coverage rather than evidence of a current data-loss defect.
