## Minimal shutdown contract

1. `AgentAssembly.Close(ctx)` is single-flight and idempotent. The first call immediately closes admission on the exact guard shared by Harness and TurnRunner. The close request remains in force if the caller context is already canceled or expires. Calls made after the fence receive the typed closed-admission error; a run claim that linearized before the fence remains owned by R1.
2. Add one narrow close-capability on `DefaultRunSlotGuard`: `CloseAdmission() <-chan struct{}` atomically closes admission against `ClaimRun` and returns the guard's stable idle signal. The channel closes when the current claim has been released (or immediately if the guard was idle). This reuses the existing R1 claim/release lifecycle and gives `Close(ctx)` a simple bounded wait; do not poll status or add another owner registry.
3. A caller deadline is a waiter deadline only. Timeout returns a typed `cleanup_pending` error/report; it does not cancel the R1 owner, clear its claim, release an R2 lease, or run model/session cleanup while the owner may still use those resources. The same close owner remains reachable and continues from the same phase. A later `Close` joins that owner; it does not start a duplicate close sequence.
4. Use this dependency order; it is based on the live producers and owners above, not a restriction on what trusted extension code may retain: **at close initiation, close the shared run-admission fence and stop/cancel hot-reload request sources; wait for the R1 owner and resources to become idle; join any active hot-reload reconnect/register callbacks and run extension shutdown serially; then close the durable session and event/memory resources; close the selected and small models; finish Assembly spans; finally let the root invocation end its root span and shut down its exporter.** The first fence/cancellation steps prevent new work. R1 drain keeps the resources used by an admitted run alive. Extension and reconnect callbacks are joined before their possible dependencies are closed; even though Extension.Init does not receive a session handle, the extension is trusted in-process code and may own other references. EventBridge is not currently assembled; if introduced, join its forwarder before closing the destination bus. The R2 owner has synced its terminal outcome (or recorded unknown/error), returned its per-run lease, and released the guard before physical session close. Selector close marks the selector closed, detaches the Loop model, and disposes each Assembly-owned generation once. |
5. Record resource disposers immediately at acquisition, not at a late final-cleanup append. Each resource has one owner and an observable terminal state. Close results aggregate terminal errors in one `ShutdownReport`; only a confirmed completion is marked closed. Setup failures join the original error with cleanup errors/pending status instead of discarding the cleanup result.

### Uncooperative close callbacks

The public caller context must not be passed as the lifetime context for the close owner. A single Assembly-owned serial close executor owns the operation and its resource handles; callers only wait for its result with their own contexts. A callback that ignores context cannot be forcibly interrupted. If it blocks past a caller deadline, `Close(ctx)` returns `cleanup_pending`, while the same executor retains the callback stack, the current resource, and all later dependencies; it must not advance or claim shutdown complete. When the callback eventually returns, that owner records its result and continues once. If it never returns, the truthful process result is pending/nonzero; no implementation can claim the callback stopped merely because the caller stopped waiting.

The first `AgentAssembly.Close` call creates the single close owner and records one absolute cooperative deadline from that instant. The first slice may reuse `tracing.DefaultAsyncExporterShutdownWaitBudget` (currently 20 seconds: the existing 10-second drain plus 10-second callback budget) as its initial Assembly budget; this is reuse of a default, not evidence that all Assembly callbacks finish within 20 seconds. Do not reset the deadline per phase or callback, and do not derive the owner deadline from the caller's waiter deadline. The caller's context only decides how long that caller waits. Even if that context is already canceled, the call must still close admission and start/join the owner; it must not skip cleanup.

For context-aware resource shutdown, pass a close-owner callback context with that one deadline. The callback's close request must synchronously close its own admission/start its own operation even when the deadline has expired; the context bounds cooperative work and waiting, not whether the close request is made. If a callback is contextless `func()`, invoke it once, serially, on the close owner itself. Never put it in a detached goroutine merely to make the caller return: until it truly returns, retain its stack, resource handle, and all later dependencies, and let callers receive a typed pending report. A deadline cannot interrupt such a callback.

When an asynchronous manager can return before its callback actually stops, wait on that manager's operation-specific completion signal and retrieve its stored result (for example, a narrow PluginManager `WaitShutdown(ctx)` over the exact shutdown operation). Do not infer operation state from error text or a sentinel that user callbacks can themselves return. If the shared deadline expires while the callback is still active, the close owner remains responsible and waits for the exact completion signal; waiters may return `cleanup_pending`, but teardown must not advance past that callback. After it returns, the owner may continue serial cleanup while retaining the original deadline for cooperative operations. A resource whose close request reports pending must stay owned until its `Wait` seam confirms stopped; absent such a seam, the source must remain pending rather than be marked closed. Do not start a second callback attempt on a later `Close` call.

## Minimal source ownership and API delta

- `internal/core/run_slot.go`: implement the R7-assigned `RunAdmissionCloser.CloseAdmission() <-chan struct{}` on the existing default guard. A claim must recheck the closed bit under the same mutex that publishes the active claim; a waiter racing the fence must wake and fail. Keep `RunOwner`, `RunClaim`, worker accounting, and R1 status semantics unchanged. This guard admission change can be the first independently implemented slice; it does not depend on R2 durable CLI wiring and does not create a second registry.
- `internal/cli/assemble.go`: add `AgentAssembly.Close(ctx) error` and a private single-flight close owner/report; preserve `Cleanup func()` as a deprecated compatibility wrapper. Change the Assembly-owned cleanup registration from raw `func()` to the smallest typed step needed to propagate error/pending and exactly-once state. Ensure initial and switched primary model cleanup have one selector owner. Keep the configured small model as a distinct owned resource.
- `internal/cli/durable_session_manager.go` / prompt / REPL: once R2 wiring lands, Assembly close calls the manager's close request only after shared guard quiescence and reports `PreparedSession.Close` errors. `CloseRunCommit` remains run-owner-only lease release.
- `internal/extension` and `internal/cli/assemble.go`: provide an exact `PluginManager` shutdown-operation wait/result seam; split close-owner callback context from each caller's waiter context. Stop hot-reload admission immediately, then join the active reconnect loop and registration callback before closing registries or downstream resources. Do not hold selector/assembly state mutexes across plugin callbacks. Keep EventBridge out of current Assembly ownership; if wired later, cancel and join its `Wait` before closing its destination.
- `internal/llm/model_selector.go`: implement the accepted R3 mutation gate and selector close after shared admission drains; a busy/closed selector returns typed errors. Selector cleanup happens before model resources are reported closed.
- `internal/cli/prompt.go`, `repl_session.go`, `serve_cmd.go`: call `Close` explicitly with a bounded shutdown waiter and combine its error with command/HTTP shutdown errors. A defer may be used only to guarantee a fallback attempt, not to suppress the returned error.
- `cmd/cli/main.go`: preserve the existing single exporter owner. After the command has closed Assembly and ended the root span, run the existing bounded exporter finalizer and keep any close/finalizer failure nonzero.

No new general Runtime, independent admission gate, goroutine registry, or arbitrary-model reference counter is required. The guarantee is limited to the Assembly's shared Harness/TurnRunner path. Direct `LoopAgent.Run`, a retained bare `BaseChatModel`, or a caller-provided model reference outside Assembly remains that caller's quiescence responsibility.

## Gates and explicit limits

R1 supplies the truthful run-owner/quiescence primitive; the first implementation slice may add only the admission-close signal to the same guard. R2 still gates production session/sink/lease wiring. R3 resolver/catalog behavior, model mutation gate, and selector resource ownership are prerequisites to the model close step. R7 extension shutdown/error aggregation, hot-reload join, and root tracer/exporter ownership remain in their assigned slices. None of these interfaces proves that a non-cooperative callback can be stopped; it can only keep ownership truthful, bound callers, preserve dependencies, and return a pending/nonzero result.
