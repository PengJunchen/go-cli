## Findings

### R3-CONS-01 — Provider flag could rebind the provider block's endpoint and key (P1, fixed)

At the initial snapshot, `newCLIModelResolver` copied `rc.Provider.BaseURL` and `APIKey` onto whichever provider name the CLI selected. Since `prompt.go` gives the CLI provider flag precedence, a `--provider` override could cause the configured provider's key to be registered under the override's provider/protocol/origin scope and sent as its Bearer credential. A generated-canary `httptest` probe through `resolveProviderName` → `AssembleAgent` → `Generate` reproduced a request to the configured server with the provider-block key under the override scope; the intended no-request/no-key assertion failed.

The fix at `assemble.go:1515-1521` attaches provider-block endpoint/key only when the effective configured provider and selected provider have the same normalized identity. The endpoint is retained on the assembly resolver and reused by same-provider model switches and listing at `1657-1665` and `1730-1740`. An unknown custom override without its own endpoint now fails with typed `ErrProviderEndpointRequired` (`1620-1632`). The new HTTP regression at `assembly_model_resolver_test.go:62-90` asserts zero requests, no canary in request/error, and the typed failure. A positive HTTP case at `93-117` confirms that equivalent canonical spelling (`" OPENAI "` and `"openai"`) still uses the configured endpoint/key.

Review also checked the defaulted-small-model path, which initially offered a second way to inherit the provider-block values after a provider override. `resolveSmallModelProviderSettings` now checks the configured provider identity before inheriting either value (`assemble.go:1791-1817`). The regression at `assembly_model_resolver_test.go:119-144` verifies that a config-provider endpoint/key does not enter an `openai` override's primary or small-model binding and that the override retains its own default origin. A temporary focused helper regression reproduced the inherited endpoint on `fc72` and passed at `2d78`; it was removed after the permanent test landed. No registered CLI aliases are declared in this builder; the positive alias-equivalence evidence here is case/whitespace canonicalization. `openai` and `eino` remain distinct credential identities as required.

Same-scope primary/small key conflicts disable only the optional small model rather than silently switching keys (`assemble.go:1585-1593`); the assembled regression at `assembly_model_resolver_test.go:206-250` verifies the primary still succeeds and neither key leaks. Same-provider sharing is limited to the same origin; explicit other-provider/origin and small-owned credentials are covered in `small_model_credentials_test.go` and the assembled HTTP cases. Provider-only legacy credentials remain inert: `AuthChain.ResolveCredential` uses only full-scope sources (`auth_chain.go:127-155`), and `TestAssembledResolverDoesNotUseUnscopedOpenAIEnvironmentCredential` verifies a legacy `OPENAI_API_KEY` alone cannot satisfy the scoped resolver.

### R3-CONS-02 — Sampling presence and precedence are still incomplete (P1 for full R3; not part of the identity fix)

The current loader and request path cannot distinguish “unset” from explicit zero. `defaultConfig()` sets both provider and model `MaxTokens` to 4096 (`internal/config/loader.go:281-300`), while `overlayValue` only copies non-zero numeric values (`:303-329` onward). `buildPrimary` copies only `rc.Model` scalar values and never resolves provider-level temperature/max-tokens (`internal/cli/assemble.go:1657-1665`); the `ModelRequest` still contains plain `float64`/`int` fields (`internal/llm/model_resolver.go`). Finally, `openAIRequest` uses `omitempty` on both numeric fields (`internal/llm/provider.go:541-547`), so explicit zero is omitted from the wire.

This was confirmed through the actual `config.NewLoader().Load` → `AssembleAgent` → `httptest` path. A YAML provider configuration with temperature `0.8` and `max_tokens: 512`, with model sampling unset, loaded as provider `(0.8, 512)` and model `(0, 4096)`; the captured request omitted temperature and sent `max_tokens: 4096`. A direct assembled request with model `(0, 0)` omitted both fields. The existing `TestAssembledModelConfigZeroSamplingDoesNotFallBackToProviderDefaults` at `assembly_model_resolver_test.go:323-348` only checks that the provider's non-zero values are absent; it does not prove explicit zeros reach the provider and currently passes despite omission.

The separate sampling-presence handoff (`r3-sampling-presence-handoff.md`, `1e5ca2a`) is sufficient to guide this narrow fix: preserve loaded-field presence, keep old non-zero programmatic compatibility, carry per-field presence through resolver/model config, and use optional wire fields so explicit zero is encoded while unset is not. The handoff additionally requires real Loader-to-HTTP tests. Do not mark sampling complete until that implementation and matrix pass.

### R3-CONS-03 — `/model` switch is wired; `/model` inventory is usually empty (P2, incomplete capability)

The assembled selector's switch builder and list callback share the assembly's `cliModelResolver` snapshot (`assemble.go:754-768`). `DefaultModelSelector.SwitchModel` returns before replacing the current model when building fails (`internal/llm/model_selector.go:121-155`); the assembled HTTP regression confirms a cancelled switch leaves the old model active and a successful switch sends the configured endpoint, credential, and new model name (`assembly_model_resolver_test.go:252-301`). Native Claude/Gemini IDs fail before endpoint dispatch (`newCLIModelResolver` at `assemble.go:1506-1513`; regression at `303-321`).

The list path does not yet provide a useful inventory for the CLI-built providers. `newCLICompatibleProvider` sets only provider name and optional base URL (`assemble.go:1613-1627`), so its `Models()` list is empty. `listAvailableModels` validates through the shared resolver and then returns only `registry.Get(providerName).Models()` (`1730-1747`). Although the optional `ModelsDevRegistry` is built for token metadata at `708-721`, the selector's `AvailableModels` callback does not call `ModelsForProvider`; the slash handler therefore prints only the current model when this list is empty (`internal/cli/slash_handlers.go:179-193`). This is a product capability gap, not an identity or credential-scope blocker. Add model discovery through the eventual shared resolver/catalog snapshot; do not add a second independent listing authority.

## Decision

Accept the fixed identity consumer slice for integration: primary provider bindings, small-model sharing/isolation, same-provider model switch construction, native fail-closed behavior, and legacy-unscoped-key isolation are source-grounded and pass the focused race selection at `59b5`. This acceptance does not close sampling presence or `/model` inventory, and it does not cover the remaining R3 consumers assigned to later slices.
