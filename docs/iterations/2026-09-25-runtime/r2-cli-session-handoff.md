# R2 CLI physical-session, resume, and run-lease handoff

Status: design handoff only; no product code or tests changed. Source snapshot: `b7ffe0bc6d4d7795fe54c058189e7699a038b1f1`. This handoff consumes the approved [R2 contract](r2-contract.md) and [session RunCommit adapter handoff](r2-session-run-commit-adapter-handoff.md), plus the fixed [core consumer handoff](r2-core-consumer-handoff.md) at `9bdef4a3bbe1d51f3b0289fea15f31004185288b`. The CLI integration and restart-safety acceptance are not implemented or complete.

## Decision

Use one durable physical session handle per selected CLI session, prepared once for that session's lifetime, and one borrowed lease per run. A prompt invocation that starts a new session prepares one physical file; an interactive session prepares one file and reuses that same handle and physical ID across every `TurnRunner.RunTurn`. A run lease is not a new `PreparedSession` and must never create a new file. Reuse the existing `SessionPreparer`/`PreparedSession`, `RunCommitSink`, `RunCommitBinding`, `Harness.Submit`, `TurnRunner.RunTurn`, and run-owner lifecycle. Do not add another run framework or treat event listeners as persistence. A durable session configured for a command is mandatory: failure to prepare, recover, append, sync, resolve, or close must be returned to the command path; it must never disable persistence and continue with a nil store.

`SessionConfig.ID` remains a logical/display label. It never selects a file or contributes to a path. A newly created physical session gets a fresh physical file and root; subsequent runs within that selected session, including later REPL turns, reuse it. Resume selects a physical ID first, then an exact branch/entry in that file. A file's persisted `ActiveBranchID` is an exact default branch selection; no filename timestamp, display label, “latest” session, or content match may choose a session or branch.

## Preparation, identity, and dispatch path

1. At the command boundary, resolve the configured session directory and capture one workspace-root value. The current config has no general-purpose workspace-root field: `Git.WorkDir` is Git-specific, `LSP.WorkspaceRoot` is LSP-specific, and `Sandbox.AllowedPaths` may contain multiple scopes. Do not use any of those as an implicit session identity. For the current CLI, use the invocation working directory captured with a successful `os.Getwd()` as the explicit workspace root; if a future general workspace-root setting is introduced, pass that selected value here. Canonicalize with `filepath.Abs`, `filepath.Clean`, and `filepath.EvalSymlinks`, in that order, and fail on every error. Never fall back to `"."`, a relative path, or an empty workspace ID.
2. Derive a domain-separated stable digest from the canonical absolute root (for example, `workspace-v1:` plus lowercase hex SHA-256 of `go-cli/workspace-quarantine/v1\x00` followed by the canonical path). Persist the digest, not the path. This ID is distinct from the physical session ID and from the display label. Use the R2-mandated index root `os.UserConfigDir()/go-cli/workspace-quarantine/`; index-root, lock, permissions, or sync failures are fatal for mutation. A fresh workspace must durably `EnsureWorkspace` before any action can be dispatched.
3. For a new selected session, call `PrepareNew(ctx, displayLabel)` once. It must return a unique path-safe physical ID, a locked file, and an empty root/view. For resume, require an exact `--resume-session` physical ID and call `PrepareResume(ctx, id)` once with the workspace index as its `RecoveryAuthority`. Recovery holds the session lock, validates rows, applies exact durable resolutions, inspects markers, and only then returns a usable view. Do not call `PrepareResume` again for a physical ID already held by this manager: that would reacquire the same file lock and can self-deadlock. A failed different-ID target preparation leaves the currently selected session untouched.
4. Resolve the branch from the prepared snapshot's exact `ActiveBranchID`, or validate the requested exact `--resume-branch` against that physical session before publishing it. Keep both the selected physical ID and branch in the manager; every run sink is constructed from this same prepared handle/snapshot. Where selecting a non-active branch requires an API not exposed by the current `PreparedSession`, add a narrow `SelectBranch`/`PrepareResumeBranch` operation to the prepared-session owner and persist that branch choice before publication. Until that operation exists, reject a non-active branch request before provider entry; do not claim an in-memory tree move changed the durable writer's parent.
5. Publish the fully prepared manager/view into `AgentAssembly` only after preparation and branch validation succeed. The current `AssembleAgent` creates models before its late `assembleSession`; durable preparation therefore belongs at the CLI boundary before `AssembleAgent` or in an early fail-returning assembly phase. Register cleanup immediately so assembly/model construction failure releases the prepared handle. On resume, the same `WorkspaceQuarantineIndex` instance/authority used for recovery is used by the run sink.
6. Before each prompt `Harness.Submit` or interactive `TurnRunner.RunTurn`, acquire an idempotent run lease from the selected session manager. Construct the run-scoped adapter around the same `PreparedSession` and index, then call `core.WithRunCommit(ctx, sink, core.RunCommitBinding{SessionID: physicalID, WorkspaceID: workspaceID})` once. The core `runOwner` remains the sole source of `RunID` and `OwnerGeneration`; callers do not invent either. `CommitInput` must sync before the first provider request. Terminal records, transcript, and compaction projections must sync before the CLI reports the run saved/complete.
7. The sink borrows the prepared writer; it must not call `PreparedSession.Close`. The core consumer handoff defines the optional `RunCommitRunLease { CloseRunCommit() }` capability outside the seven-method `RunCommitSink`. `CloseRunCommit` has no error result and only returns this run's borrow/reference count, exactly once, after the run owner has joined callback/workers and applied its terminal/late-proof policy; it does not write durable state or close the prepared handle. The session manager owns the base handle and is responsible for returning any final `PreparedSession.Close` error through the command/CLI shutdown result. Align the adapter seam with the session owner before implementation.

## Session-manager lifetime and branch switching

The manager owns the base `PreparedSession` handle. A run lease pins that handle and selected physical ID/branch while a sink may still write. The manager prepares one handle per selected physical session, not one per REPL turn. `RequestClose` (normal exit or a different-physical-session replacement) atomically prevents new leases. The manager calls `PreparedSession.Close()` exactly once only after the last run lease returns and returns that close error through the CLI shutdown result; the existing no-result `Assembly.Cleanup` path cannot silently swallow it. UI cancellation, a caller timing out, or a `cleanup_pending` result is not proof that the run stopped and cannot release a live lease.

The `PreparedCompletionSignal` handle is fixed by `PrepareToolCall`, but its `Done()` channel may remain nil until dispatch or queue acceptance attaches it. Register an owner-held placeholder for the full action occurrence and that same signal handle before dispatch. On dispatch return, error, or panic, the worker reads the final `Done()` and hands it to the existing run owner before decrementing the worker count; the owner atomically transfers the placeholder to resource observation or no-proof so there is no zero-worker/zero-resource gap. The observer only records readiness and wakes the owner; it never writes the sink. The Loop drains ready proof after receipt sync and before another action/provider request. After callback return, the owner may do a final drain only after workers/resources join and terminal sync succeeded. If the writer is poisoned, skip late resolution/index writes, retain the persistence error and unresolved quarantine, and release the run lease once local resources have joined; never hold it forever or report success. A non-nil completion signal that remains open follows the owner's existing `cleanup_pending`/quarantine policy. A nil final `Done()` is no proof: it leaves the global marker unresolved. The session manager must not independently infer quiescence or replay the tool/provider action.

On callback cancellation, use the core run owner's single cached cleanup context derived from `context.WithoutCancel(callbackCtx)` to retain the run binding and values, then apply the existing `cleanupTimeout` once. Remaining known receipts, proof resolutions, index updates, and terminal bookkeeping share that one deadline; do not create a fresh timeout per write. This context is only for durable bookkeeping, never provider requests or tool dispatch. Deadline or storage failure withholds success acknowledgement and leaves markers quarantined; cancellation bounds boundary checks but does not promise to interrupt a filesystem `Sync` already in progress.

For a session/branch selection request, compare exact physical ID and branch against the manager's current selection before acquiring any new handle. Same physical ID plus same branch is a no-op: keep the existing prepared handle and lock, with no `PrepareResume`. Same physical ID plus a different branch is an in-session branch switch: stop new leases, wait for the active run lease/resource owner to reach its safe boundary, durably select the branch through the already-locked `PreparedSession`, refresh its canonical snapshot, then accept runs again. Never call `PrepareResume` for that same ID while its handle remains open, and never retarget an already bound sink. For a different physical ID, prepare and recover the new target independently first; only after that succeeds should the manager close-request the old handle, reject new old-session leases, publish the new selected handle/view, and let existing old-session leases drain. A failed different-ID target leaves the old selection usable.

A poisoned writer is not reusable for another run. After the current owner releases its lease, reopen the same selected physical ID through `PrepareResume` and the same workspace recovery authority before allowing a subsequent run. If recovery fails or reports unverifiable evidence, leave the session unavailable and return a typed error; do not create a fresh physical session as a silent repair.

## Child runs and fail-closed errors

The current child submit path inherits the parent context and would otherwise inherit its sink/session binding. Until there is a child-session factory that prepares an independent physical session, owner generation, and sink on the same workspace index, durable mode must return a typed unsupported error before the child makes its first provider request. Masking or clearing context values is not a substitute for child-session isolation.

Every configured durable operation must propagate errors through `promptCmd.Run` / the REPL turn path and final CLI shutdown result: workspace-root canonicalization, user-config/index preparation, `PrepareNew`/`PrepareResume`, recovery authority, branch selection, lease acquisition, `CommitInput`, intents/receipts/resolutions, compaction, terminal sync, and final `PreparedSession.Close`. The current log-and-continue sites in `assembleSession`, `setupSlashContext`, `persistSession`, and REPL cleanup must not remain on the durable path. Already-streamed output may precede a later sync failure; the command then reports a persistence failure and does not claim the output was durably saved.

## Acceptance matrix for the implementation lane

These are required real-command/process checks, not claims about existing tests. Each run should use an isolated session directory, isolated standard user-config directory, a local fake provider, and a controlled real tool/process fixture; assert both exit/output and exact durable JSONL/index state.

| Scenario | Required observation |
|---|---|
| New prompt and interactive start | A new prompt session and a new interactive session each create a physical file with an empty root. Within one interactive session, several `RunTurn`s reuse the same physical ID/file and prepared handle; they do not create a file per turn. A separate session gets a different physical file. The fake provider's first-request hook can read the synced input row. `Session.ID` changes only the display label. |
| Exact resume, fork, and branch | Resume ID A reads only A; ID B reads only B; durable `--fork <entry>` requires an exact source physical ID and verifies the entry belongs to it. Same ID/same branch is a no-op; same ID/different branch reuses the existing lock and selects durably without self-resume. Different ID is prepared independently before swap. Missing/unknown IDs, invalid branch, mismatched fork source, and ambiguous old `--resume` fail before any provider request. Compaction summary appears once at its source boundary and the uncovered suffix/source IDs survive reopen. |
| Workspace identity | Same canonical directory reached through a symlink yields the same workspace digest; a different directory yields a different digest. `Getwd`, `Abs`, or `EvalSymlinks` failure returns an error and never uses `"."`. Index-root/lock/sync failure blocks mutation before tool entry. |
| Crash after input sync | Kill the actual CLI after the input durable boundary and before provider dispatch. Restart on the exact physical ID restores the input; provider request count for the crashed run is zero. |
| Crash before/after dispatch marker | Crash before the marker has no executor side effect and recovers only the validated never-dispatched receipt. Crash after a durable dispatch marker but before receipt yields an unknown outcome/quarantine; restart does not replay the provider/tool or duplicate a side effect. |
| Live child / `cleanup_pending` | Keep the real child process alive after parent interruption. A second process cannot start a conflicting mutation for that workspace. No PID-only signal, guessed stop, lease release, or replay is accepted. Once the exact proof arrives, resolution is synced once; a poisoned terminal writer instead keeps quarantine and returns a persistence error. |
| Lease, slash refresh, and replacement | Complete a terminal sync, then verify `/tree`/entry state refreshes from that same handle's canonical snapshot before the next slash or user input, without a duplicate persistence write. Hold an active run while requesting session switch/exit. The old manager rejects new leases, keeps its file lock until the run owner releases, and closes once afterward. Same-ID selection never reacquires its own lock. A failed different-ID preparation leaves the old session selected. A poisoned handle cannot serve the next run until recovery. |
| Backend failures and child call | Inject session/index append, file sync, directory sync, recovery, and close errors. The command returns a classified error and no later provider/action starts after the failed boundary; a final `PreparedSession.Close` failure is visible in CLI shutdown status and produces a failing process exit. A child attempt in durable mode reports typed unsupported before the child provider is called. |

Unit/race tests should cover the small manager state machine and adapter lifetime, but they do not replace the actual binary crash/restart matrix. Root's R2 restart-safety review remains an independent gate.

## Dependencies and completion status

This CLI handoff depends on the R2 core consumer safely calling the seven sink methods at canonical boundaries, proof ownership and late-drain policy, the session adapter and shared workspace index/recovery authority, and the approved R4 prepared executor fence. Exact compaction projection persistence also requires the typed R1/R3 projection seam. The relevant current contracts exist, but the actual CLI bindings, manager leases, process crash evidence, and restart acceptance do not. This document is a design handoff only; it does not declare R2 implementation, R2-REV-01, or any release gate complete.
