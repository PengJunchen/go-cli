# R3 model catalog and selector consumer review

Review target: `6fb6baf1ba35f8c7f99a77a36aa90a99615fd0a2` (`codex/runtime-r3-provider-catalog`), reviewed in a separate clean detached worktree. This review covers the configured static catalog, `/model` list/switch consumer, assembly resolver wiring, credential/sampling scoping relevant to selection, and runtime selector update. It does not cover retry/cycler, subagent, compaction, or the remaining R3 provider runtime work. No product source was changed.

## Verdict

**Approve this bounded catalog/selector slice. No confirmed blocker found.** The actual assembly path uses one immutable resolver for primary, small, catalog, and interactive switches. A scoped switch builds the requested provider/model identity from that resolver; failed resolution does not replace selector or LoopAgent state. Unknown compatible model IDs can be used as explicit requests but do not inherit model capability metadata. Native-disabled identities fail before credential lookup or HTTP dispatch.

This does not close R3. The handoff is accurately bounded: catalog membership is static resolver data plus the effective configured primary/small model identities, not external discovery or native protocol enablement.

## Confirmed contract behavior

- `internal/llm/model_catalog.go:8-52` derives membership from the immutable resolver provider snapshot, excludes disabled/non-OpenAI-compatible/native providers, de-duplicates by canonical provider ID and exact model ID, preserves cross-provider duplicates, and sorts deterministically. `internal/cli/assemble.go:1592-1639` adds the final effective primary model and configured small-model request to the provider definitions before publishing the resolver snapshot.
- Listing consumes `ModelSpec` from the shared resolver and compares the full provider/model pair for the current marker (`internal/cli/assemble.go:801-820`, `internal/cli/slash_handlers.go:180-205`). The no-argument handler does not query models.dev for catalog membership; `TestModelHandlerCatalogListingDoesNotQueryExternalMetadataRegistry` verifies no lookup/list/refresh calls. When enabled, models.dev refresh is an assembly-time metadata operation (`assemble.go:755-768`), not a listing-time way to add identities.
- `/model --provider <id> -- <model-id>` validates the separator, joins model-ID tokens without splitting on `/`, and returns the resolver error without falling back to another provider. Bare `/model <id>` remains scoped to the selector's current provider (`internal/cli/slash_handlers.go:234-259`). Composite marker and malformed-flag regressions are in `internal/cli/model_selector_catalog_test.go:13-93`.
- Provider switches do not carry a previous `CredentialRef` or key. CLI construction binds configured credentials to canonical provider/protocol/origin scopes (`internal/cli/assemble.go:1673-1720`); resolver validation occurs before scoped credential lookup and rejects disabled native identity first (`internal/llm/model_resolver.go:187-237`). Same-scope primary/small key conflicts disable the small model and keep both canary keys out of errors/request bodies (`internal/cli/assembly_model_resolver_test.go:233-277`). Cross-origin small-model tests separately prove the small key is not sent to the primary origin and the primary key is not sent to the small origin (`internal/cli/small_model_credentials_test.go:170-209`).
- Interactive switches for the configured primary provider use primary sampling; selecting a different provider uses only sampling associated with that target identity or the generic fallback. A model configured for both primary and small roles is deduplicated by provider/model identity and interactive use follows the primary path (`internal/cli/assemble.go:1784-1799, 1820-1851, 1877-1893`; `assembly_model_catalog_test.go:105-240`). Small-only sampling does not leak to an interactive cross-provider request.
- `SwitchModelSpec` clears caller-provided metadata, invokes the builder first, and commits selector identity only on success; the success callback is called after replacement and is the only path that updates `LoopAgent` (`internal/llm/model_selector.go:167-205`; `internal/cli/assemble.go:808-820`). `LoopAgent.Run` snapshots the selected model when starting a run, so successful updates affect subsequent runs (`internal/core/loop.go:364-404`).
- Unlisted compatible model IDs remain usable only as explicit requests. `resolveModelSpec` returns `Known=false` with empty `ModelInfo` for an identity absent from static definitions (`internal/llm/model_resolver.go:287-297`); the CLI build path returns zero metadata for such a resolved model (`internal/cli/assemble.go:1854-1874`). This does not infer native protocol, context limits, or other capability from the identifier.

## Independent integration probe

A disposable, uncommitted test exercised the actual `AssembleAgent → /model` slash handler → `LoopAgent.Run → httptest` path. With primary and small configured to the same slash-bearing model ID under different provider identities, the explicit target switch sent the request only to the target endpoint with its target Bearer key and intact `vendor/shared-model` ID; primary received zero requests and target-only sampling was absent. A subsequent bare unknown slash-bearing ID remained on the current target provider and was sent intact. An unsupported-provider switch returned a readable error and left both the selector's model pointer and composite current identity unchanged. The two successful post-switch calls went through `LoopAgent.Run`, confirming that the assembly callback updates the live runtime model, not only the selector display.

The disposable test passed under race and was removed after verification. Existing permanent regressions cover the constituent catalog, slash, scope, sampling, native-gate, and failed-switch paths, but there is not yet one checked-in test combining real slash parsing, `AssembleAgent`, a failed switch, and a subsequent `LoopAgent.Run`. I recommend adding that as a non-blocking integration regression when the next CLI integration-test slice is touched.
