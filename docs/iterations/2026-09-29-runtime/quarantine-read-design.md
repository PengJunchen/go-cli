# R2/R4 safe-read quarantine admission

**Status:** minimal design for the remaining R2 safe-read admission gap. Design only; no product code or test result is claimed.

## Decision

Keep `WorkspaceQuarantineIndex` as the sole cross-session admission authority. The exception applies to actual prepared actions (`RunIntentBatch.Intents` / `WorkspaceDispatchBatch.Actions`): while a workspace has any unresolved dispatch marker, admit a batch only if every action has a fresh, runtime-only proof from its actual prepared builtin reader, each proof matches that exact action, and the executor enforces a whitelist wholly inside the quarantined workspace. Any write, unknown, composite, stale, mixed, or mismatched prepared action rejects the whole batch. No tool name, context flag, persisted identity/effect DTO, or scope fingerprint alone grants admission.

`KnownReceipts` are validated no-intent pre-dispatch denials, not actions. A valid non-unknown denial may coexist with a scoped read intent; it cannot lend a proof, cause an executor call, or resolve an older marker. The existing consumer/session validation must reject malformed or unexpected `unknown` no-intent receipts before index admission. Keep this check there; do not add a second index batch authority or send denials to the index as actions.

The existing once-only dispatch contract stays intact: persist the session intent, then append and sync the global dispatch marker while holding the workspace lock, then release the lock and dispatch. `WorkspaceDispatchAlreadyExists` remains an observation only and never grants replay. A marker sync error returns before executor entry, even if the record may later be recovered from disk.

## Proof and scope binding

`PreparedInvocation` already freezes the captured registration identity, effects, schema/normalized-argument digests, executor, and registry/policy fence generation. Add an opaque `tools.ScopedWorkspaceReadProof` with private fields and runtime-only serialization. The only issuer is `tools.ScopedWorkspaceReadProofFor(invocation, canonicalRoot) (proof, ok)`, which type-checks the package's real `*preparedInvocation`; there is no constructor from caller fields or `TrustedToolIdentitySnapshot`. The proof binds that invocation's identity, effect set, schema digest, argument digest, call ID, fence snapshot, and private whitelist roots. Its validator has the narrow shape `MatchesAction(identity, effects, schemaDigest, argumentDigest, callID, canonicalRoot) bool`; it rechecks those exact captured values and the current generation before index admission. Normal `Dispatch` keeps its final generation fence and one-use state.

Initially issue a proof only for concrete `RegistrationSourceBuiltin` `ReadTool` and `LSTool`, the scoped readers whose trusted registration already captures `CompletionInlinePipelineJoined` and whose prepared completion can resolve their own durable marker. Require exactly the positively known local `workspace_read` effect, a valid nonempty `PathWhitelist`, and the same captured whitelist used by the executor. A same-name custom definition, unscoped/invalid whitelist, unknown or composite effect, or unreviewed execution wrapper gets no proof. `GrepTool` and `FindTool` keep ordinary tool behavior but are excluded from quarantine admission in this phase; do not add proof minting or completion semantics for them without a separate review.

The path relation must be checked from actual roots, never inferred from `ScopeFingerprint`. Resolve the invocation CWD once in the durable manager to an absolute, cleaned, symlink-canonical root; return that root and `WorkspaceID` from the same capture. `WorkspaceID` remains the domain-separated hash of that root. Carry the canonical root only in the runtime run binding/batch; centralize the existing hash operation in a small `session.WorkspaceIDForCanonicalRoot` helper so the index can rederive and compare it. The proof retains the canonical roots from the executor's private `PathWhitelist`; require every root to be equal to or nested under the captured canonical workspace root and require its private scope fingerprint to equal the captured identity's scope. Configured sandbox paths remain the executor's whitelist; they do not replace the canonical root or determine `WorkspaceID`. Keep existing symlink checks; do not claim an OS sandbox or atomic protection from concurrent symlink replacement. Do not persist the canonical path or proof.

Runtime fields are limited to `core.RunCommitBinding.CanonicalWorkspaceRoot`, `core.RunIntentBatch.CanonicalWorkspaceRoot`, `core.ActionIntent.ScopedReadProof`, `session.WorkspaceDispatchBatch.CanonicalWorkspaceRoot`, and `session.WorkspaceDispatchAction.ScopedReadProof`; all are `json:"-"`. The consumer fills the batch root from its captured binding and proof from the same `PreparedInvocation` used for dispatch. The index validates each action before admission, then erases these transient fields before persisted payload comparison/encoding.

`internal/cli/assemble.go` already passes `WithRegisteredPathWhitelist` when `Sandbox.AllowedPaths` is nonempty; the default empty list leaves `PathWhitelist` unrestricted and therefore cannot mint a proof. Add a runtime-only `WithRegisteredCanonicalWorkspaceRoot(root)` registration option populated by assembly from the same durable-manager capture that derived `WorkspaceID`; do not call `Getwd` a second time. This pins the expected root for proof issuance. Preserve `Sandbox.AllowedPaths` as the enforced whitelist: each nonempty canonical path root must be within the captured workspace root. A configured path list is not a substitute for the captured root, and an empty/unrestricted whitelist stays fail-closed for quarantine admission.

## Minimal owners and flow

| Owner | Narrow change |
|---|---|
| `internal/tools/prepared.go`, `trusted_registry.go`, `builtins.go` | Opaque proof type/issuer; retain actual canonical whitelist roots with the prepared registration snapshot; issue only for attested `ReadTool`/`LSTool` and current generation. |
| `internal/cli/durable_session_manager.go`, `durable_cli_session.go`, `assemble.go` | Capture canonical CWD and `WorkspaceID` together; pass that root through `WithRegisteredCanonicalWorkspaceRoot` to default readers and into the runtime lease/binding, while preserving configured sandbox paths as the executor whitelist. |
| `internal/core/run_commit.go`, `run_commit_consumer.go` | Add runtime-only root to `RunIntentBatch`; attach the invocation-derived proof to each `ActionIntent`. Leave durable identity/effect facts and original dispatch fence unchanged. |
| `internal/session/run_commit.go` | Match each proof to its exact `ActionIntent` fields and root hash, then pass runtime-only admission data with the corresponding `WorkspaceDispatchAction`. |
| `internal/session/workspace_index.go` | Under the existing workspace lock, validate the complete new batch and each proof before relaxing the unresolved-marker gate; append+sync the ordinary global marker in the same critical section. Strip runtime proof/root before durable encoding and idempotent payload comparison. |

The session sink keeps its current order: append+sync session intent under the prepared session ownership, then call the index. The index re-syncs and reads current marker state, performs proof and prepared-action checks, appends+syncs the global marker, then returns. Proof generation/revalidation takes only a short snapshot of the captured dispatch-fence generation; release that fence lock before index append+sync. If generation changes afterward, the final prepared dispatch fence remains the execution linearization point and prevents the executor call. Neither session nor index lock crosses tool execution; the index never calls back into or opens the session. Failure at either sync yields zero executor calls. Resolution continues to require the existing exact action reference and validated execution evidence.

When a batch reaches an unresolved workspace, permit its prepared actions only if every action has a valid matching proof. Thus one safe reader cannot lend permission to a write, unknown/composite action, or another reader with a different scope. A valid non-unknown `KnownReceipt` may accompany the read intent because it is already validated as `not_dispatched`, has no `ActionID`, and is not an action; it never grants or resolves anything. The session/index check is per exact action reference plus captured identity/digests/scope; a prior marker for the same occurrence, `AlreadyExists`, or a replayed proof never grants a second execution.

A successful read receipt is not a resolution proof for the older mutation and cannot clear that marker. The existing inline completion evidence may resolve only the read's own marker through its exact durable resolution path; assert that the older mutation marker remains unresolved. Reads do not change old `unknown` receipts or synthesize `CompletionProof`.

## Acceptance criteria (RED before implementation)

- `TestWorkspaceIndexAllowsTrustedReadOnlyDuringQuarantine`: create a real unresolved mutation marker, prepare a scoped builtin `ReadTool` or `LSTool` under the same captured canonical root, and observe one dispatch permit and exactly one executor call. Its own read marker may resolve; the older mutation marker stays unresolved. A duplicate marker attempt yields no second permit.
- Reject same-name custom readers, public/forged DTOs, proof from another invocation or argument digest, stale registry/policy generation, missing/invalid whitelist, out-of-root roots, unreviewed wrappers, writes, unknown/composite prepared intents, mixed read+write intents, and proof/root/WorkspaceID mismatch. Stale proof must produce zero executor calls.
- No-intent receipt cases use the existing consumer/session validation: malformed or `unknown` `KnownReceipts` with a read intent fail before either executor runs; a canonical known `error` denial for a write call may coexist with the read intent, the reader runs, and the denied write executor count remains zero. These receipts are never passed as dispatch actions or resolution evidence.
- `TestRecoveryAllowsSafeReadWhileWorkspaceQuarantined`: restore an unresolved child action, permit the fresh scoped `ReadTool`/`LSTool`, keep every conflicting mutation blocked, and show that the read resolves only its own marker while the old marker and receipt remain unchanged. Only verified child exit or explicit durable reconciliation plus synced exact resolution releases quarantine.
- Inject session and global index sync failures and assert zero executor calls. A failed global sync must leave admission closed after reopen unless the exact marker and resolution state prove otherwise.
- Run the affected tools/core/session/CLI race suites after the same RED turns green. Separately, R2-REV-01 must run the real builtin CLI subprocess SIGKILL/live-child matrix; a helper-process fixture is not that evidence.

## Historical unknown boundary

A complete historical `unknown` receipt may remain unchanged in the transcript sent to the LLM for a fresh below-budget user request. That is not replay: only newly prepared tool calls reach this admission gate, and untrusted or mutating calls stay blocked by it. Do not add an unconditional historical-unknown provider-request gate here. Compaction's future eligibility to summarize or drop that receipt remains a separate policy decision and review item.
