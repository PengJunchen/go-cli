## Actionable source findings

1. **P2 — ACP HTTP rate limiting releases before dispatch completion.** `rateLimitMiddleware` holds one of 64 slots only while the HTTP handler runs ([`http_server.go`](../../../../internal/acp/http_server.go#L265)). `/send` increments a wait group, starts one goroutine per request, then returns 200 ([`http_server.go`](../../../../internal/acp/http_server.go#L729)). The core semaphore limits active subagent `Run` calls to five, but `factory.Create` and the wait for that semaphore happen before/around the acquire ([`subagent_tool.go`](../../../../internal/core/subagent_tool.go#L126)); sequential requests can therefore accumulate unbounded dispatch goroutines and created agents while those five slots are occupied. This misses the approved admission contract to reserve bounded capacity before acknowledging and reject overload ([handoff](../../2026-09-25-runtime/r6-adapter-lifecycle-handoff.md#L20)). Minimal RED: `TestACPDispatchAdmissionBounded` holds dispatches behind a barrier, sends past the configured admission capacity, and asserts the excess request is rejected without creating another worker/agent; release the barrier and assert admitted work drains.

2. **P2 — MCP hot reload reconnects the old client and cannot replace/remove a complete tool generation.** `DefaultHotReloader` stores one `MCPClient` and `runCycle` calls `Disconnect → Connect → ListTools` on that same object; the changed file is only a detection signal ([`hot_reload.go`](../../../../internal/mcp/hot_reload.go#L190), [`runCycle`](../../../../internal/mcp/hot_reload.go#L562)). CLI assembly captures that client and a void callback; it registers tools one at a time and only warns on registration errors ([`assemble.go`](../../../../internal/cli/assemble.go#L2203), [`registerMCPToolBatch`](../../../../internal/cli/assemble.go#L2285)). There is no removal path. For already materialized tools, `RegisterDeferred` clears only its deferred cache, while `DeferredToolRegistryAdapter.Get` returns the underlying definition first ([`deferred.go`](../../../../internal/tools/deferred.go#L66), [`Get`](../../../../internal/tools/deferred.go#L321)); the old executor remains reachable. Callback errors cannot reach the reloader, which can log success after a partial registration. The lifecycle owner/`Done`/join path itself is present and should not be reopened as an old finding ([`HotReloadLifecycle`](../../../../internal/mcp/hot_reload.go#L36), [`Stop`/`Wait`](../../../../internal/mcp/hot_reload.go#L300)). Minimal RED: `TestMCPReloadUsesChangedConfigAndReplacesGeneration` updates a server endpoint and its tool definitions under a barrier; verify the new peer is used, changed/removed tools do not resolve to old executors, observers never see a partial generation, and registration failure is observable. This must use the R4 registry-generation seam; do not add another registry.

3. **P2 — TUI `remote` is an event-source toggle, not a remote session.** The configured path starts a GET-only SSE adapter, but the REPL's local turn goroutine still executes the user's message through its local `TurnRunner` ([`repl_session.go`](../../../../internal/cli/repl_session.go#L762), [`remote` branch](../../../../internal/cli/repl_session.go#L795)). The adapter sends only `Accept` and an optional replay cursor ([`http_client.go`](../../../../internal/tui/http_client.go#L140)); the ACP server requires bearer auth when configured, the exact private-profile header, and a principal/session-bound `session_id` for `/events` ([`http_server.go`](../../../../internal/acp/http_server.go#L222), [`profileMiddleware`](../../../../internal/acp/http_server.go#L247), [`handleEvents`](../../../../internal/acp/http_server.go#L851)). Minimal RED: `TestTUIRemoteModeDispatchesToAuthenticatedRemoteSession` uses a local private-profile peer to assert the prompt is sent to that peer, events come from its same session, and the local `TurnRunner` is not called. Until that path exists, fail closed or expose the setting as event observation only rather than remote execution.

## Gates and evidence limits

- ACP session/principal routing and replay/live gap handling have later accepted source reviews; their earlier rejected snapshots are historical evidence, not current findings. ACP stdio cancellation/write serialization and MCP local lifecycle completion likewise have bounded accepted slices. None of those reviews accepts all R6 adapters or external interoperability.
- The approved R6 matrix requires serve assembly failure to exit and a bound remote approval round-trip. Current serve instead starts a clearly warned no-dispatch handler; default `ask` uses local stdin (or denies when stdin is not a terminal). Treat these as unsupported/gated behavior and keep them out of the shipped capability claim until the R4 prepared-invocation approval seam exists.
- Web unavailable behavior is intentional and independently accepted; it is not an echo/Agent defect. ACP HTTP is a private JSON profile, the historical `gRPCAdapter` name is not a wire claim, and the MCP `OfficialSDKAdapter` name does not prove use of the official SDK.
- Evidence here is source inspection plus existing review records. No current test command was run; no real ACP/MCP peer, serve subprocess journey, browser, PTY, or external environment was validated. Full integrated verification remains a separate gate.
