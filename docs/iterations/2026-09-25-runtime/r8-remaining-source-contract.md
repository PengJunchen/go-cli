## Findings from the current source

### Transcript rendering and terminal behavior

- The accepted `internal/tui/cells` slice supplies grapheme/cell-width handling and terminal-control sanitization for its covered helpers. The fixed `r8-cells-main-consumer-race.log` is a race run at `d83be9de5fff13755999e592ca178fd1d08dc120`, with `NO_COLOR=1 TERM=dumb`; it passed `./internal/tui` and `./tests/e2e_20260802` on that snapshot. This is focused software-test evidence, not a PTY, viewport, performance, or current-HEAD result.
- No transcript viewport/search model or the five named R8 acceptance tests (`TestTranscriptViewportSearchAndScroll`, `TestTranscriptViewportCJKAndANSI`, `TestStreamRenderBoundedLargeTranscript`, `TestTerminalResizeKeepsViewportStable`, `TestASCIIFallbackHasNoControlGlyphDependency`) were found in source. There is no transcript/render benchmark in `internal/tui`.
- The current `AccordionModel.Render` walks and renders every entry. `RenderView` also walks all entries, materializes all matching lines, and only then keeps the last `height` lines; this is tail clipping, not virtualization, stable scroll anchoring, or search. `Entries` copies only the pointer slice. In single-column mode `renderViewLocked` uses the full accordion render.
- `teaModel.handleIncremental` appends to `streamingBuf` and calls `String()` for the entire accumulated message on every event. `StreamingMarkdownRenderer.RenderIncremental` calls `strings.Split` over the full accumulated input and scans its lines on each invocation. The renderer cache can avoid some Markdown re-rendering, but these input-copy/split/scan operations and whole-view redraw remain proportional to accumulated content. The source comment claiming that incremental rendering avoids O(n²) work overstates that guarantee.
- `tea.WindowSizeMsg` updates the current model dimensions and resets the active approval-detail scroll state. Existing accordion entries retain event-time rendered `Full` strings; the resize path does not re-render stored entries or preserve a durable-entry viewport anchor, search selection, and input caret as one viewport state.
- `WithDiffStyle` stores `diffStyle` on the app/model and `repl_session.go` passes the config value, but no rendering path consumes it. `DiffRenderer` renders unified diffs. `TUIConfig` has no `ascii` option; `NO_COLOR` controls color only. Therefore `diff_style` is currently a silent no-op and a configured ASCII glyph fallback is absent.

### Platform and evidence boundary

- `internal/term` has explicit Darwin and Linux `TIOCGWINSZ` implementations; the other-GOOS implementation reports zero size, and the TUI size provider falls back to 80x24. This describes source behavior only. It neither establishes Windows interactive support nor proves that other platforms cannot run the application.
- The fixed R5 PTY evidence is one Darwin/arm64 run against a loopback fake provider. It exercised approval/detail scrolling and resize, ask_user Unicode input, cooked-mode handoff, and terminal-state restore. Its own report excludes Windows cancellation, non-Darwin terminal behavior, IME correctness, crash/restart recovery, and full R5/R8 closure.
- The Windows cross-compile attempt in the R5 report stopped on existing `syscall.Stat_t` references in `internal/approval`; that is a failed compile attempt, not runtime evidence. Interactive TTY input is explicitly disabled on Windows in the R5 source. No native Windows PTY run or Linux PTY run is present in the reviewed R8 evidence.
- No test or benchmark in the evidence proves bounded render latency/allocations for 1k/5k/10k entries or 1 MiB streaming input. Do not infer those metrics from the cell-helper race suite.

### Default capabilities and user-visible claims

- Goal, Task, and Todo tools are registered by default, but assembly creates fresh `TaskStore` and `TodoStore` instances and calls `NewDefaultGoalStore("")`; these are process-local stores. They are not restart-persistent capabilities.
- Memory uses `~/.go-cli/memories.jsonl` when a home directory is available, and `/memory` exposes manual list/add/delete/search/clear. Assembly currently calls `List` and places every returned record into `MemoryEntries`; the available bounded `Search`/`MemoryRetriever` path is not used for default prompt injection. Thus storage is persistent, but automatic prompt selection is currently unbounded and not query-retrieval-backed.
- Default `web_search` construction uses the mock provider unless configuration selects a real provider; current assembly tests explicitly expect mock metadata in the default case. `web_fetch` is a separate tool. Public status must not imply that default WebSearch reaches the live web.
- `ImageReadTool` has an implementation and tests but is absent from the default extra-tool registration list. A registered `ImageRenderer` is not an image-reading tool.
- Plugin load/init errors are discarded at the assembly call sites. Plugin setup is conditional on configuration and paths; skill tools are also discovered/configured and deferred-registered. Their package-level existence does not establish default availability or successful initialization.
- Slash handlers can advertise commands whose dependencies are absent; several handlers print “not configured” and return normally. The `/tools` handler lists the current registry, which is a better source for callable tools than a static capability list. Session command semantics remain owned by R2/R5 reviews and are not re-audited here.
- Tracing status must consume the single canonical R7 exporter matrix, rather than introduce a second protocol claim in R8. This report makes no new tracing support assertion.

## Minimal implementation and verification sequence

1. **Freeze the public matrix before changing claims.** R8-DES-01 should choose each optional capability and its shipped wording using the reviewed R5/R6/R7 owner contracts. Keep default registry truth authoritative. Either show a selected capability as available through a real default-entrypoint test, or make invocation/help explicitly report `unsupported`; do not register placeholders. Keep `/tools` derived from actual registered tools. Use the R7 tracing matrix as the sole tracing authority.
2. **Build a real viewport before optimizing paint.** Add a durable-entry-ID scroll anchor, follow-tail state, bounded visible-row window with small overscan, and keyboard search with an explicit loaded-history limit until R2 exposes paging. Reflow cached rows on resize from source content, preserving anchor/selection, active interaction, input text, and caret. Keep viewport clipping distinct from executor source-capture truncation. Reject designs that duplicate the complete durable transcript in another TUI-owned unbounded buffer.
3. **Make streaming cost depend on new input and visible work.** Replace whole-message `String`/`Split`/rescan on every event with a line/chunk incremental renderer plus bounded render cache. Re-render only changed tail and visible rows. Benchmark renderer-only synthetic chunks separately from R1/provider candidate limits; measure 1k/5k/10k transcript sizes, 1 MiB over 1k chunks, allocations/retained heap, and key latency. Then run a real PTY growing-transcript journey to validate interactive latency and follow-tail/scroll behavior.
4. **Close configuration behavior.** Make every accepted `diff_style` value change the actual preview, or remove/reject unsupported values with a load-time error. Add an independent `tui.ascii` glyph option, leaving `NO_COLOR` color-only. Verify chrome states remain textual and that plain non-TTY output has no terminal-control sequences.
5. **Resolve capability choices and default-path tests.** For selected Goal/Task/Todo persistence, test subprocess restart; otherwise document process-only lifetime. For memory, retain manual operations and connect the R3-approved bounded selector/budget to default injection or disclose/disable automatic injection; test budget, no-match fallback, restart, and write/reopen failures. Label default mock WebSearch and configured providers distinctly. Select or explicitly leave `image_read` unavailable. Surface plugin/skill load failures and distinguish configured availability from default availability. Do not use a generic success return for dormant slash commands.
6. **Validate only the claimed terminal rows.** Record exact OS/version, architecture, terminal emulator/version, shell, locale, `TERM`, color variables, and geometry for each real PTY. Run at least the selected Linux and Darwin TTY journeys before marking those specific rows supported. Keep Windows and other platforms unavailable/unverified until native PTY evidence exists; a cross-compile is not a PTY test. Verify pipe/plain mode separately.
7. **Apply exact R8 gates.** First assert every planned test name appears in `go test -list` output, then run targeted race tests and the complete affected package race suites. Preserve raw benchmark and PTY output tied to the tested commit. R8-REV-01 should report each support claim and its evidence tier separately; do not let cell-helper unit tests, renderer benchmarks, one Darwin PTY, or a passing package suite stand in for one another.

The acceptance test names and thresholds in `r8-capability-design.md` remain planned requirements, not existing tests or measured results. At this baseline R8-DES-01 remains pending and R8-BLD-01 remains in progress; this source contract does not update task status or assert release readiness.
