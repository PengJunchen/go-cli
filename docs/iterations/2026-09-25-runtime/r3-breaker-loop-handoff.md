## Ownership and terminology

The detector observes a **frozen prepared attempt**: a registered TrustedToolIdentity plus the digest of normalized, schema-validated, frozen JSON arguments. It does not prove approval, dispatch commit, executor entry, a receipt, or a mutation. An approval-denied or never-dispatched frozen attempt still counts; reports and tests must not call it an executed action.

The breaker owns logical model-call admission and provider terminal classification. The stream-producing layer owns its reader and request resources. The Loop owns active-run cancellation. Existing R1 RunOwner and RunCommit code retain sole authority over run terminal sync, quiescence, and acknowledgement. No breaker or detector path writes durable run state.

## BUILD-1: source-close prerequisite

Do this as an independent source-close/join commit before changing breaker accounting. The default wrapper order stays as assembled. Every owning reader must stop forwarding after a local error/cancel, cancel its own source context with a typed local cause, drain **that same input channel** to close, and only then close its output. Do not start a second drain goroutine or add a generic stream supervisor. If the source ignores cancellation, its reader remains pending until the source closes; the run must not claim that callback is quiescent.

## BUILD-2: one breaker ticket per logical model call

The breaker currently wraps the entire model middleware chain: failover/retry are inside it and output guard is outside it (internal/cli/output_guard_adapter.go, newModelWrapperWithChain). Keep this position. One ticket covers one **logical model call** through that chain; it is not a per-provider-dispatch ticket or an operation-wide AttemptID. A failover/retry chain may make several synchronous setup requests before returning a stream, but it settles one ticket: final setup exhaustion is one failure; a handed-out stream settles only on its terminal and joined close. Current overflow-owned continuation is also within this logical call. Midstream error does not replay.

Keep DefaultCircuitBreaker as the only state machine and retain Execute for Generate. Add a narrow optional streaming-ticket interface for the assembled adapter. Admission checks Closed/Open/HalfOpen before calling the chain; open returns typed ErrCircuitOpen without provider dispatch or synthetic assistant content. The one-shot ticket completes the existing state once and protects against duplicate/late completion. HalfOpen reserves a probe slot until source close; actual caller cancellation releases it neutrally, without counting success or failure.

Terminal classification must preserve cancellation ownership:

| Condition at the logical-call boundary | Ticket result |
|---|---|
| One valid Final, then joined source close | Success. |
| Setup retries/failovers exhausted synchronously; malformed terminal; missing Final; data after final; provider error; timeout/cap/local wrapper abort | Failure. |
| Actual caller cancellation wins before terminal | Neutral; release a HalfOpen reservation. |
| Child context is canceled by core budget, timeout middleware, overflow, sanitizer, loop detector, or guard abort while caller context remains live | Failure, not neutral. Carry a typed local abort cause; ctx.Err() alone cannot distinguish this from caller cancellation. |
| Provider channel already closed successfully, then outer OutputGuard rejects the candidate | Keep provider success. Outer policy cannot retroactively change the ticket. |
| Source never closes after cancellation | Ticket and run remain pending; no success, retry, or ACK. |

Do not infer caller cancellation from the breaker wrapper's context alone: OutputGuard is outside the breaker and core creates a child stream context. Default-chain local aborts must preserve a typed cause distinct from inherited caller cancellation. Do not write raw provider error text to logs.

**BUILD-2 acceptance:** assembled httptest provider: first synchronous Stream setup fails, retry/failover setup succeeds, and the ticket records one final success; separately prove a midstream error after handoff is one failure and no replay. Assert HalfOpen stays reserved until final plus source close; open calls make zero requests; cancellation-neutral is distinguishable from timeout/local-abort failure; and guard denial after provider close leaves the breaker successful. Do not describe this as a shared retry budget or one ticket per HTTP request.

**BUILD-2 files:** internal/production/circuit.go and tests; internal/cli/output_guard_adapter.go circuit-wrapper portion and assembled tests. Depends on BUILD-1's close semantics.

## BUILD-3: live detection of frozen prepared attempts

The current Assembly detector runs after successful Run/RunCanonical, skips errors, ignores Disposition, and receives tool_call proposals with only name/call ID (internal/cli/assemble.go:2512-2595, internal/core/loop.go:709-727,819-840). Its configured default kind is "tool", and name-only content cannot distinguish different arguments (internal/production/loop.go:170-220,296-312). Do not treat provider message.ToolCalls as a frozen identity.

Add one immutable tools.FrozenPreparedAttempt value containing captured registered identity and the 32-byte frozen-argument digest. Call the one synchronous optional callback in the existing trusted PreparedToolStages pipeline after registration snapshot, path normalization, schema and mutation validation, and freezeToolCall, but before approval/policy and before PreparedInvocation construction (internal/tools/prepared_registry.go:101-151). Approval denial and never-entered-executor attempts count; invalid/unregistered/unfreezable calls do not. Compare full identity (registration source, tool name, registration generation, executor fingerprint, and scope) plus digest, excluding call ID. Never log or display the digest/raw args.

The callback is installed only by fixed internal Assembly code. It can return nil to continue or a typed rejection; nil does not approve, mint an invocation, set DispatchCommitted, skip a fence, create completion proof, or run an executor. Adapt the identity snapshot and argument digest using domain-separated, unambiguous encoding to a fixed-size detector key; do not fabricate an AgentEvent or put the fact on the user event stream. Use one private detector session per Run/RunCanonical, not mutable state in the process-global loop-detector registry.

Preserve consecutive repeat policy: first identical key is count 1, a different identity/digest resets to 1, and configured threshold triggers at count >= threshold (default 3). Preserve default warn and reminder behavior. Add validated optional production.loop_detector.disposition (warn default, terminate opt-in, steer reminder semantics) so live termination is explicit. When the threshold is reached, first inspect the run context's cause: if caller cancellation/deadline already won, return that cause and keep cancellation; only install and return ErrLoopDetected when the detector cause wins or was already the first cause.

Durable and live outcomes must agree. LoopAgent.RunCanonical owns an inner terminal defer at internal/core/loop.go:417-435; outer CLI middleware cannot normalize the detector cause afterward. Before that defer calls terminalOutcome, normalize a first-cause ErrLoopDetected from the run context to the typed loop error. terminalOutcome must classify that typed error as RunOutcomeError before generic context cancellation handling. The outer loop wrapper returns the same ErrLoopDetected without errors.Join-ing context.Canceled into it. First cause wins: if parent cancellation was first, keep cancellation and do not upgrade it; if detector cause was first, later parent cancellation does not turn it into cancelled status. This keeps durable terminal outcome and live RunStatusSource consistent while R1 remains the only terminal writer.

The ordinary protected proxy and durable consumer both use the prepared registry (internal/tools/middleware_registry.go:164-183, internal/core/run_commit_consumer.go:367-414). Propagate ErrLoopDetected after recording the existing known interrupted/error receipt; do not swallow it as ordinary policy denial. In parallel mode preparation completes before workers launch (run_commit_consumer.go:600-653); when cancellation wins during preparation, no prepared group dispatch may enter its executor, and each assistant ToolCall must have exactly one canonical receipt.

**BUILD-3 acceptance:** through both ordinary proxy and durable runCommitConsumer.prepareInvocation routes, tests use real successful PreparedInvocation values and assert the observer facts equal ToolIdentity() and ArgumentDigest(). A policy-denied attempt is counted before denial and runs no executor; compare its captured facts with an allowed control invocation built from the same registered identity and normalized args. Real Assembly/Harness threshold test asserts trigger attempt is not executed, no subsequent provider request occurs, and R1 persists one terminal. Add parallel-group receipts, different-digest/registration reset, per-run isolation, default-warn, and explicit-terminate cases. Exercise two first-cause races: caller cancellation first yields durable and live RunOutcomeCancelled; detector first yields typed loop error plus durable and live RunOutcomeError. The public returned detector error must not contain context.Canceled.

**BUILD-3 files:** internal/tools/{prepared.go,prepared_registry.go,trusted_registry.go}; internal/production/loop.go; internal/cli/assemble.go and internal/config/{types.go,validator.go}; internal/core/{loop.go,run_commit_consumer.go}; plus targeted tests. Keep the loop observer/cancel state run-local and do not add a global registry or event store.
