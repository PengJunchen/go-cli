# R3 attempt accounting Stage-1 review

**Decision: REJECT against the frozen attempt-accounting contract.** Reviewed isolated commits `a2f59576f310cd1145c60febd13359ab961df8aa` and `33a3cbe7c4bd90217a13836185ab631ff0629a79` on accepted source baseline `42c1de01887bb9018c1e44319d6d90708ea78dc4` in `repair-20260930-attempts`. This is a source review plus targeted package verification; no product source was changed.

The commits establish useful provider-layer primitives: resolver builds are fixed to guarded mode, direct builds are fixed to one-call unbound mode, both HTTP adapters place `BeginDispatch` immediately before `client.Do`, and post-fence transport/provider errors reach `Finish` with explicit unknown usage when no usage was returned. The new cost API also preserves unknown usage and unknown cost separately. These pieces do not yet satisfy the frozen contract as an assembled operation path.

## Blocking findings

1. **The operation permit is not an unforgeable Loop-owned capability.** `DispatchPermit`, `OperationDispatchAuthority`, and `ProviderDispatchAuthority` are public implementable interfaces in `internal/llm/attempt.go:258-300`; the context setters are public as well. The adapter checks only the permit's operation and candidate IDs, then delegates one-shot consumption to the caller-provided authority at `attempt.go:437-494`. `ResolvedModel.CandidateHandle()` exposes the real opaque handle. A package consumer can therefore supply its own authority and permit implementation that accepts that handle and lets the request proceed. The tests use a cooperative in-package test authority, so they verify the happy path and ID mismatch checks, but not that only the Loop can issue and consume authority. There is no production operation-authority implementation in either commit.

2. **Pre-dispatch failures are not classified or routed through the typed preflight contract.** `PreDispatchCandidateError` and its enum are declared, but no production code constructs that error. Resolver, credential, request-serialization, and request-construction failures still return ordinary errors. Without a Loop operation owner, there is no allowlist for `PreDispatchCandidateUnavailable`, no finite candidate-set check, and no protection against a wrapper treating an arbitrary setup error as a reason to select another model.

3. **Attempt `Finish` does not cover the outer stream cleanup chain.** `finishProviderAttemptStream` finishes when the adapter's source channel closes (`attempt.go:607-665`). The adapter response body is closed before that source channel closes, which the new stream test verifies (`attempt_test.go:433-490`). The selected-model cleanup in `cycledModel.Stream`, however, runs only after the outer cycler receives the adapter channel close (`cycler.go:313-341`). Thus the attempt result can be frozen before the enclosing candidate cleanup has completed. The test observes body close, not the returned build cleanup or cycler cleanup, and there is no Loop-owned join handle that could keep a later proposal pending through that work.

4. **The shared dispatch policy and CLI wiring are still absent, leaving a runtime fail-closed regression.** No changed file implements the `RunOperationFactory` or `OperationDispatchAuthority` for `core.Loop`, attaches one to model calls, or converts retry/failover/overflow/cycler decisions into proposals. Existing cycler fallback remains in `cycler.go:248-265` and `272-302`; retry/failover/overflow middleware is unchanged. Meanwhile CLI model construction already goes through `ResolvedModel.Build` (`assemble.go:1986-2005`), which now permanently builds a guarded candidate. Until Loop wiring supplies an authority, the assembled CLI call reaches `providerDispatchBinding.begin` without one and returns `ErrOperationAuthorityRequired` before HTTP dispatch. There is no shared MaxAttempts counter or proof that the breaker still wraps one complete candidate chain.

5. **Attempt costs are not yet connected to accounting output.** `RecordAttempt` has no production caller in this checkout; only its tests call it. `CostHandler` still prints `Total()` and `Calls()` without unknown-attempt counts (`slash_handlers.go:55-58`), and the token usage event still publishes only `Total()` as cost (`interactive.go:226-239`). The record-level API avoids treating unknown usage as zero-cost evidence, but `/cost` and `token_usage` do not yet expose that distinction. This requires the separate accounting and CLI wiring already listed in the design.

## Checks that passed

- `provider.go` and `native.go` prepare and validate the request before calling `providerDispatchBinding.begin`; after it returns, the next operation is the corresponding `client.Do` (`provider.go:516-536`, `native.go:180-201` and `258-284`). A post-fence transport error retains the attempt and is finished with unknown usage when there is no provider usage.
- `ResolvedModel.Build` calls only the guarded resolver constructor (`model_resolver.go:123-135`). Direct Eino/native `Build` calls explicitly construct `UnboundLibraryBuild`; the zero value of `ProviderBuildMode` is rejected rather than treated as unbound (`provider.go:149-157`, `native.go:1213-1221`, `attempt.go:437-443`). The new tests cover direct one-call behavior and zero-value rejection.
- Attempt and usage enums that must distinguish absent values start at one. `FailureNone` is intentionally zero and the cost validator accepts it only for a successful result; failed results with zero failure and unknown usage without an explicit unknown source are rejected.
- `CostTracker.RecordAttempt` deduplicates by AttemptID, retains known subtotals, and counts unknown usage/cost separately (`cost_tracking_attempt.go:63-129`).
- `rtk go test -race ./internal/llm ./internal/production` passed: **1,045 tests in 2 packages**.

## RED/GREEN evidence

GREEN is verified by the race run above. The committed history does not demonstrate a RED phase: `a2f5957` adds `attempt.go` and `attempt_test.go` together, and `33a3cbe` adjusts the cycler test fixtures. No test-only failing commit or builder RED/GREEN report is present in the reviewed path. The new tests exercise adapter permits, unknown-usage finishing, source-body close ordering, direct/resolver build modes, and cost-record behavior; they do not exercise the frozen Loop, retry-budget, fallback, summary-operation, or assembled-CLI RED contracts.

## Required remaining wiring

- **Core Loop:** create main, continuation, and summary operations; own the immutable result store, actual-dispatch budget, finite candidate set, one-shot permit consumption, cancellation/publication/tool/ack/receipt/stream-join facts, historical-versus-current unknown scope, overflow recovery state, and continuation cap. Attach the correct authority to each provider call and make a pending stream attempt unfinishable until all source and candidate cleanup has joined.
- **LLM wrappers:** change retry, failover, overflow, and cycler to submit typed proposals only. Distinguish initial, retry, failover, overflow, selected, and primary candidates; route safe build fallback only from an allowlisted pre-dispatch class; remove hidden automatic second dispatch; preserve one breaker entry per logical chain call.
- **CLI and accounting:** wire guarded primary, small, summary, failover, and cycler models through the operation factory; create independent summary operations; call `RecordAttempt` exactly once per immutable result; show known subtotals and unknown usage/cost counts in `/cost` and usage events. Add assembled CLI coverage for `summary` and `unified`.
- **Acceptance tests:** add actual `httptest` coverage through Loop plus assembled middleware/CLI for shared retry/failover/overflow limits, denied proposals, same-candidate retry, safe pre-dispatch fallback, cycler cleanup ordering, summary accounting, and breaker call count. Preserve evidence of the RED failure before the corresponding builder implementation.
